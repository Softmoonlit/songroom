# 生产部署依赖同步与房间工作台体验缺陷修复规范

## 背景与问题

在阿里云生产环境部署与日常使用中，发现以下关键缺陷与体验问题：
1. **网易云只读刷新异常**：VPS 同步发布方案（方案 A）中由于依赖目录路径错写为 `packages/netease-vendor` 且 rsync 排除 `node_modules`，导致生产环境 `apps/songroom/dist/netease/vendor/node_modules` 软链接缺失，加载网易云 request 模块报 `MODULE_NOT_FOUND`（判定为 `MODULE_ERROR`）；且前端只读刷新提示直接套用了写操作的“请查看操作的确认状态”恐吓文案。
2. **Tab 显隐穿透**：由于 `.room-settings-pane` 的 CSS 类选择器带有 `display: flex`，特异性覆盖了 HTML5 原生 `[hidden]` 属性，导致公共歌单和房间成员页面底部强制漏出整个房间设置面板。
3. **生硬文案**：房间设置内的解散/退出操作被冠以后台极客风格的“危险区域”大标题及冗余警示语，严重偏离点歌台的生活化定位。
4. **审批按钮缺陷**：房间成员右上角“审批申请”按钮样式类名错写为 `secondary-action` 导致裸奔无样式，且展示逻辑倒挂（无待审批时展示、有待审批时消失）。

## 修复目标

- [x] 1. 全局样式重置增加 `[hidden] { display: none !important; }`，彻底根除 Tab 内容显隐穿透；
- [x] 2. 优化房间设置解散/退出区域的语义与文案，移除突兀的“危险区域”标题及常识说教，保留优雅红框隔离与二次确认弹窗；
- [x] 3. 修复房间成员页审批入口的类名为规范的 `.secondary-button`，补充配套样式，并将无申请时的常驻文案调整为“申请记录”；
- [x] 4. 为只读刷新错误定制专属文案，避免向用户展示“请查看操作的确认状态”等写操作特定警示；
- [x] 5. 修正 `docs/operations.md` 中本地构建同步发布的路径与软链接规则；
- [x] 6. 确保全量自动化测试（单元测试与 E2E 测试）通过，并将修复部署至阿里云环境验证通过。
