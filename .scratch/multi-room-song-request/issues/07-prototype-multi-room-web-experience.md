## Question

统一账号登录、开放注册与建房、房间邀请申请与房主审批、主页进入房间及返回主页切换、账号级网易云授权、房间歌单设置、以公共歌单为默认主页面及可选个人歌单独立访问、个人歌单文本导入、直接搜索及从自己个人歌单逐首点歌的手机与桌面交互如何呈现？原型须表达跨房间角色、只读他人歌单、云端快照时间、导入候选与部分失败，以及用户授权失效/退出/更换对全部自建房间的影响，通过真人反馈确定核心体验，不实现正式后端。

## Comments

### 未解决的首次首页问题

用户曾询问部署后首次访问首页是否只显示登录按钮。多房间与统一账号已经取代单房间模型，需在本票据验证登录/注册、邀请上下文、账号授权与房间初始设置分流，不能直接沿用旧首页提议。

### 已确定的账号、邀请与导航约束

以[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#解决评论账号房间与邀请规则已确认)的最终决议为约束，原型须覆盖开放注册与建房、邀请提交申请、房主审批、待审批不可访问歌单、重置邀请取消旧待处理申请，以及退出或被移除后的重新申请。主页只列自己创建或当前加入的房间，切换须返回主页；仅房主可见邀请码和“复制邀请链接”按钮，不展示完整链接文本，不设置建房邀请码或独立房间切换器。成员离开释放昵称并仅清除本人标签，原型不得展示同昵称继承旧成员数据的流程。

### 歌单配置与生命周期交互约束

以[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为约束，原型须验证授权后选择已授权账号建房、初始无歌单、房主主动新建公共歌单和绑定已有或收藏个人歌单、室友主动创建个人歌单，以及无公共歌单时不能点歌的状态。当前账号选择只有网易云，不展示尚未接入平台的可用入口。

须清楚区分可选个人歌单、直接搜索公共点歌与个人选歌、可维护与只读个人歌单、自己与他人的点歌资格、共用绑定与独立歌单、只读旧快照与已确认删除后主动重新配置。离开和删房要表达专用资源删除、已有资源仅解除绑定、二次确认与云端待清理状态，不能显示可恢复的离开成员档案或假报云端删除完成。播放仍在官方客户端，本原型不制作网页播放器。

### 导入与点歌交互约束

以[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)为唯一决议来源，验证默认候选、共用改选弹窗及异常行非阻塞的一次确认体验，重点检查百行预览的操作量和手机布局。改选不跳页、不额外搜索、不提前写云端，不增加智能匹配、候选分页、草稿或导入历史功能。

原型还须表达个人来源已变化、来源读取失败时仅暂停以其为来源的点歌、未配置个人歌单或个人来源待确认时仍可直接搜索点歌，以及结果待确认、标签未完成、部分成功与未提交选择离开提示；成功状态不暗示歌曲可播放，关闭页面不伪装成取消已提交写入。具体恢复机制以[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md#解决评论并发同步与恢复规则已确认)为准，本票不自行增设正式后台任务或后端实现。

### 并发恢复状态的体验承接

须验证短队列繁忙、同目标待确认阻塞、最近成功同步时间、只读旧快照、接口报告成功但同步待确认、标签未完成、部分成功、清空与批量删除二次确认，以及授权暂停和原账号重新授权后自动继续的呈现。正常创建取得 ID 后自动绑定，不要求房主人工认领；ID 未知属于管理员核查异常，不以最新同名歌单自动关联。不新增持续轮询、提交后取消或导入历史入口，命名与具体恢复规则引用并发票最终评论，不在原型中重定。

### 安全与账号体验的已定输入

[确定多房间安全、部署与运维边界](06-decide-security-deployment-and-operations.md#解决评论安全部署与运维边界已确认)已解决。原型自行设计称呼、邮箱与密码注册登录及改密页面，按 Better Auth 原生账号策略表达输入校验、认证错误、限流和会话到期；区分账号称呼与各房间昵称，房间内不公开邮箱。不增加验证码、邮件验证、邮件找回、首次强制改密或网页管理员后台。

容量与执行限制以该最终决议为准，呈现满额拒绝新增和队列繁忙，不伪造已测性能，不把会话到期或退出变成成员资格与歌单数据删除。本票仍只验证手机与桌面体验，不接正式认证或上游，不承担现有 Caddy 与资源的实际部署验收。

### 真人反馈迭代：公共与个人入口须切换实际内容

用户反馈：「B和C都有一个问题，就是点公共歌单和个人歌单都显示一样的界面啊。」

浏览器实际复现：B、C 在两个入口下都同时渲染公共、个人两份歌单，内容完全相同。原因是双栏渲染同时匹配 `public` 与 `mine`，点击导航后仅滚动定位。这是原型导航行为与入口名称不一致，修正依据已经由渲染分支和实际页面对比直接确认。

已在原型分支提交 `a9108ee` 修正：

- “公共歌单”只显示公共快照和成员标签；“我的歌单”只显示自己的来源及允许的维护、点歌操作，选中状态与实际内容一致。
- B、C 增加明确的“点歌工作台”入口，双栏仅在此显示。B 的工作台公共、个人等宽并排；C 的工作台个人为主、公共为辅助。默认进入房间时展示工作台。
- 工作台切换到 A 时展示“我的歌单”，保持有效的导航状态；切换视图返回页面顶部，切换布局保留歌曲、点歌结果和标签。
- 更新原型说明、桌面 B/C 与手机 C 截图。未选定最终布局，票据继续开放。

验证覆盖 B、C 在 1440px 桌面与 390px 手机下的公共、个人、工作台三个入口，共 12 种组合；每个入口的实际歌单数量、标题、选中状态与操作按钮相符，无横向溢出。另验证从工作台点歌后切换单独个人视图、跨布局切回工作台，已点过状态和公共标签仍保留；收藏来源在工作台中仍只读且可点歌。浏览器未捕获异常数为零，构建通过。

### 真人反馈：个人歌单可选与直接搜索公共点歌（已确认修订）

用户反馈三种布局的公共歌单都没有搜索并点歌入口，并询问是否必须先搜索加入个人歌单再点歌，以及这是否符合此前“用户不用非得创建自己的歌单”的决定。

反馈提出时，既有决议为：[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)允许个人歌单按需配置，未配置者可只读查看已有歌单；[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)限制公共点歌只能来自自己的个人歌单，不允许搜索结果直接点歌。原型据此实现，产生了想点新歌必须先配个人歌单并入单的使用门槛。

用户已明确确认调整：允许房间成员直接搜索并逐首加入公共歌单，个人歌单作为可选的存歌、批量导入及点歌来源。权威规则已记入 [03 的确认修订](03-decide-import-and-song-request-semantics.md#确认修订搜索直接公共点歌与个人歌单可选)，并同步权限、并发、安全、架构承接与领域定义。原型票继续开放，等待后续整体体验反馈。

### 原型修订实现：直接搜索公共点歌

原型分支提交 `81ba09d` 已在 A、B、C 的公共歌单标题旁增加“搜索点歌”，共用搜索弹窗按目标显示“点歌”或“加入我的歌单”。公共搜索不会自动创建、绑定或写入个人歌单；未配置个人歌单的页面明确标注可选，并提供前往公共搜索的入口。新建房间先展示公共歌单配置，不要求先配个人歌单。

演示工具新增“未配置个人歌单 · 房主”“未配置个人歌单 · 室友”“个人来源待确认”“搜索点歌 · 排队与处理中”“搜索点歌 · 结果待确认”。两条点歌路径共用公共目标及标签确认，个人来源核对仅在从自己的个人歌单点歌时执行。

保留既有单成员受理限制：本人同房间的已提交导入仍有未确认结果时，暂不能开始第二个点歌操作，可通过“查看导入结果”继续确认。其他个人来源目标的失效或待确认不阻止直接搜索点歌。导入结果、确认及重试对应提交时的原目标；解除或更换绑定后仅确认原目标未知结果，未发步骤停止，不写入新绑定。

已验证三布局在 1440px 桌面及 390px 手机下的公共搜索入口和五候选弹窗，无横向溢出、候选按钮重叠或浏览器未捕获异常；已从主页新建无个人歌单的房间，仅创建公共歌单后直接搜索点歌，确认歌曲和本人标签出现且个人绑定仍为空。另验证未完成导入解除及更换绑定后的原目标确认、停止未发步骤、旧失败项禁用重试，以及确认完成后公共搜索解锁；手机结果页无溢出或重叠。构建通过，更新三布局截图并保存桌面、手机公共搜索截图。

独立浏览器专项复查通过：

- 未配置个人歌单的房主、室友均可搜索点歌，点后本人绑定仍为空；室友自己的网易云授权失效不影响使用房主授权点歌。
- 已配置个人歌单时，公共直接搜索不写入个人歌单；重复点歌不重复歌曲或本人标签，不改变公共顺序。收藏来源仍只读且可点歌，公共搜索也不改变收藏内容。
- 个人来源读取失败、歌曲已移除或待确认时，个人选歌遵守原有拒绝或暂停规则，公共搜索仍可独立点歌；自建房间房主授权暂停、公共目标待确认时公共搜索禁用，未知结果无直接重试入口。
- 搜索点歌的排队、处理中、刷新确认与标签补记均不要求个人来源，不自动建单；标签未完成时先分别反馈，推进后完成标签且不重复加歌。
- 原有个人搜索只加入个人歌单，再点歌才加入公共；混合输入及 100 行导入预览仍可用，公共视图无文本导入入口。本人同房间导入未完成时公共搜索禁用，查看结果并确认完成后解锁。

专项复查未捕获 JavaScript 异常；全部验证均使用固定演示数据，不构成真实上游、持久恢复、账号隔离或上线验收。

### 真人反馈确认：公共歌单为房间主页面

用户明确指出：个人歌单并非必需，点歌台以公共歌单为主，因此 B、C 在点歌台同时展示公共、个人歌单不合理。

已确认界面层级：进入房间默认展示公共歌单，直接搜索点歌为主要操作；个人歌单作为可选来源在独立视图访问，不在主页面与公共歌单并列。此前保留双歌单工作台的方案已由本反馈否定，移除该入口和渲染、样式路径，不将未配置个人歌单呈现为主页面的待办步骤。

三种候选均改为公共歌单主页：A 使用水平标签页，B 保留常驻侧边导航，C 使用聚焦公共歌曲及成员标签的单栏列表，其他歌单和管理功能通过原生展开菜单访问。空房间先展示公共歌单配置，房主与室友从主页进入房间均默认打开公共歌单；个人来源异常等专项场景仍可直接定位到相应独立视图。
