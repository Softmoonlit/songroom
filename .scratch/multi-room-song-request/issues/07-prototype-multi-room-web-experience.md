# 原型验证多房间与双类型歌单体验

Type: prototype
Label: wayfinder:prototype
Status: open
Assignee: Codex
Blocked by: 01, 02, 03, 05, 06

## Question

统一账号登录、开放注册与建房、房间邀请申请与房主审批、主页进入房间及返回主页切换、账号级网易云授权、房间歌单设置、公共/个人歌单查看、文本导入和仅从自己个人歌单逐首点歌的手机与桌面交互如何呈现？原型须表达跨房间角色、只读他人歌单、云端快照时间、导入候选与部分失败，以及用户授权失效/退出/更换对全部自建房间的影响，通过真人反馈确定核心体验，不实现正式后端。

## Comments

### 未解决的首次首页问题

用户曾询问部署后首次访问首页是否只显示登录按钮。多房间与统一账号已经取代单房间模型，需在本票据验证登录/注册、邀请上下文、账号授权与房间初始设置分流，不能直接沿用旧首页提议。

### 已确定的账号、邀请与导航约束

以[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#解决评论账号房间与邀请规则已确认)的最终决议为约束，原型须覆盖开放注册与建房、邀请提交申请、房主审批、待审批不可访问歌单、重置邀请取消旧待处理申请，以及退出或被移除后的重新申请。主页只列自己创建或当前加入的房间，切换须返回主页；仅房主可见邀请码和“复制邀请链接”按钮，不展示完整链接文本，不设置建房邀请码或独立房间切换器。成员离开释放昵称并仅清除本人标签，原型不得展示同昵称继承旧成员数据的流程。

### 歌单配置与生命周期交互约束

以[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为约束，原型须验证授权后选择已授权账号建房、初始无歌单、房主主动新建公共歌单和绑定已有或收藏个人歌单、室友主动创建个人歌单，以及无公共歌单时不能点歌的状态。当前账号选择只有网易云，不展示尚未接入平台的可用入口。

须清楚区分可维护与只读个人歌单、自己与他人的点歌资格、共用绑定与独立歌单、只读旧快照与已确认删除后主动重新配置。离开和删房要表达专用资源删除、已有资源仅解除绑定、二次确认与云端待清理状态，不能显示可恢复的离开成员档案或假报云端删除完成。播放仍在官方客户端，本原型不制作网页播放器。

### 导入与点歌交互约束

以[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)为唯一决议来源，验证默认候选、共用改选弹窗及异常行非阻塞的一次确认体验，重点检查百行预览的操作量和手机布局。改选不跳页、不额外搜索、不提前写云端，不增加智能匹配、候选分页、草稿或导入历史功能。

原型还须表达来源已变化、来源读取失败、结果待确认、标签未完成、部分成功与未提交选择离开提示；成功状态不暗示歌曲可播放，关闭页面不伪装成取消已提交写入。具体恢复机制以[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md#解决评论并发同步与恢复规则已确认)为准，本票不自行增设正式后台任务或后端实现。

### 并发恢复状态的体验承接

须验证短队列繁忙、同目标待确认阻塞、最近成功同步时间、只读旧快照、接口报告成功但同步待确认、标签未完成、部分成功、清空与批量删除二次确认，以及授权暂停和原账号重新授权后自动继续的呈现。正常创建取得 ID 后自动绑定，不要求房主人工认领；ID 未知属于管理员核查异常，不以最新同名歌单自动关联。不新增持续轮询、提交后取消或导入历史入口，命名与具体恢复规则引用并发票最终评论，不在原型中重定。

### 安全与账号体验的已定输入

[确定多房间安全、部署与运维边界](06-decide-security-deployment-and-operations.md#解决评论安全部署与运维边界已确认)已解决。原型自行设计称呼、邮箱与密码注册登录及改密页面，按 Better Auth 原生账号策略表达输入校验、认证错误、限流和会话到期；区分账号称呼与各房间昵称，房间内不公开邮箱。不增加验证码、邮件验证、邮件找回、首次强制改密或网页管理员后台。

容量与执行限制以该最终决议为准，呈现满额拒绝新增和队列繁忙，不伪造已测性能，不把会话到期或退出变成成员资格与歌单数据删除。本票仍只验证手机与桌面体验，不接正式认证或上游，不承担现有 Caddy 与资源的实际部署验收。

### 原型进展：三种布局已制作，等待真人体验反馈

已采用 prototype 的 UI 分支，在独立 `prototype/multi-room-web-experience` 分支制作一次性交互原型。主分支仅记录认领与原型入口，不引入正式前端或后端；本评论不是解决评论，票据保持开放，尚未选定布局或记录真人认可的交互结论。

#### 覆盖范围与限制

- 覆盖首次登录/注册、邀请上下文与待审批主页、多房间与跨房间角色、空房间主动配置、公共/自己的可维护或只读收藏/他人只读歌单、成员审批与邀请重置、昵称与账号称呼、用户级授权及其跨房间影响。
- 导入覆盖混合异常输入、百行预览、默认候选、共用五候选弹窗、跳过、一次提交、未提交离开提示、已提交结果、部分成功、明确失败和结果待确认。异常场景还包括来源移除、来源读取失败、队列繁忙、标签未完成、旧快照、创建 ID 未知、已确认云端删除、容量和会话反馈。
- 退出、移除与删房通过二次确认表达本地立即清理、专用云端资源待清理，以及已有和收藏歌单仅解除绑定。更换账号在核实新账号后再次确认受影响自建房间，原账号恢复与更换账号分开表达。
- 全部状态为内存中的固定示例，不接 Better Auth、网易云或数据库；歌曲 ID、搜索及版本候选均为演示数据。扫码、排队和处理中通过底部“推进演示”手动推进，不使用计时器模拟网络，不保存凭据。
- 刷新重置原型。已提交操作跨刷新持久恢复、上游真实顺序、真实候选、账号组件策略与服务端权限只表达规格，未由本原型实现或验收。真实账号、生产并发和部署验收继续由对应决议与后续架构工作承接。

#### 初步验证与待反馈

已在真实浏览器通过以下演示交互检查，不将检查通过等同于真人体验认可：

- 正常及重复点歌、他人只读、收藏只读但可点歌、待审批不展示歌单、本人授权失效只影响自建房间。
- 101 行输入整批拒绝且不生成预览；100 行预览与提交；共用候选弹窗取消保持原选择、确定只修改本行；未提交离开确认与已提交结果页离开；部分成功中待确认期间禁止失败项重试，刷新确认后解除阻塞。
- 审批昵称重名拦截、正常批准不自动建单、重置邀请取消旧申请且保留现有成员、室友退出与房主删房的二次确认及本地立即清理/云端待清理反馈。
- 三种布局循环切换与 URL 同步，输入框内方向键不切换布局。补查发现非元素键盘事件目标调用 `closest` 的异常，已加入元素检查并通过文档级键盘事件与输入框方向键回归，浏览器未捕获异常数为零。
- 26 个演示场景在 390px 手机宽度无横向溢出；桌面三种布局无歌曲行重叠，本地图片正常加载；手机登录提交按钮在首屏、百行导入预览与长候选弹窗可用。构建通过，封面包含在构建产物中。

待真人反馈：先比较三种结构，再重点体验百行预览、未提交离开提示，以及结果待确认和标签未完成是否清楚。尚不决定辅助成员信息，也不推进或解决[确定多房间 MVP 架构与完整规格](08-decide-mvp-architecture-and-spec.md)。

### 真人反馈迭代：公共与个人入口须切换实际内容

用户反馈：「B和C都有一个问题，就是点公共歌单和个人歌单都显示一样的界面啊。」

浏览器实际复现：B、C 在两个入口下都同时渲染公共、个人两份歌单，内容完全相同。原因是双栏渲染同时匹配 `public` 与 `mine`，点击导航后仅滚动定位。这是原型导航行为与入口名称不一致，修正依据已经由渲染分支和实际页面对比直接确认。

已在原型分支提交 `a9108ee` 修正：

- “公共歌单”只显示公共快照和成员标签；“我的歌单”只显示自己的来源及允许的维护、点歌操作，选中状态与实际内容一致。
- B、C 增加明确的“点歌工作台”入口，双栏仅在此显示。B 的工作台公共、个人等宽并排；C 的工作台个人为主、公共为辅助。默认进入房间时展示工作台。
- 工作台切换到 A 时展示“我的歌单”，保持有效的导航状态；切换视图返回页面顶部，切换布局保留歌曲、点歌结果和标签。
- 更新原型说明、桌面 B/C 与手机 C 截图。未选定最终布局，票据继续开放。

验证覆盖 B、C 在 1440px 桌面与 390px 手机下的公共、个人、工作台三个入口，共 12 种组合；每个入口的实际歌单数量、标题、选中状态与操作按钮相符，无横向溢出。另验证从工作台点歌后切换单独个人视图、跨布局切回工作台，已点过状态和公共标签仍保留；收藏来源在工作台中仍只读且可点歌。浏览器未捕获异常数为零，构建通过。

### 待澄清的真人反馈：个人歌单可选与直接搜索公共点歌

用户反馈三种布局的公共歌单都没有搜索并点歌入口，并询问是否必须先搜索加入个人歌单再点歌，以及这是否符合此前“用户不用非得创建自己的歌单”的决定。

核对当前已解决票据：[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)允许个人歌单按需配置，未配置者可只读查看已有歌单；[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)限制公共点歌只能来自自己的个人歌单，不允许搜索结果直接点歌。原型据此实现，产生了想点新歌必须先配个人歌单并入单的使用门槛。

本轮待澄清：是否允许房间成员直接搜索歌曲并加入公共歌单，把个人歌单作为可选的收藏、批量导入及点歌来源。如果采用此方向，需修订来源限制及相应来源核对语义，再同步原型；尚未把该建议记为已确认规则，票据继续开放。
