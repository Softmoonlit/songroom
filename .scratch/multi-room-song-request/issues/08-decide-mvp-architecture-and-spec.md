# 确定多房间 MVP 架构与完整规格

Type: grilling
Label: wayfinder:grilling
Status: open
Blocked by: 01, 02, 03, 04, 05, 06, 07

## Question

综合账号与房间模型、双类型歌单、导入与点歌语义、授权复用实测、并发失败、安全运维和交互原型，采用什么系统架构、技术栈、数据模型、模块职责、接口与页面更新契约，才能形成无歧义、可直接开发的多房间 MVP 规格？需明确规模目标、非功能约束、验收门槛和延期项，将未证实的上游行为明确标为测试门槛，不实现旧匿名/单房间/主动重排方案的兼容路径。

处理本票据时同时使用 codebase-design 与 domain-modeling，最终规格存放于本 feature 目录的 spec.md。

## Comments

### 已确定的账号实现方向

[确定多房间安全、部署与运维边界](06-decide-security-deployment-and-operations.md#解决评论安全部署与运维边界已确认)为当前账号与运维规则的权威入口，已确认 Better Auth 与 TypeScript/Node.js 主后端，注册、登录、改密页面自行设计，日常认证采用组件默认策略。旧纯用户名注册、自定义密码范围、双重会话期限、失败锁定或首次强制改密不再作为实现规格；默认优先不代表启用全部插件或取消房间业务权限。

本票应选择匹配的具体框架、数据库和 ORM，固定受支持的 Better Auth 稳定版本，复核其原生默认行为，落实公网标准认证入口、生产限流及接入验收，不重写密码、会话或认证限流内核。网易云 Enhanced 仍按已有决议逐调用进程隔离，不能因主后端也使用 Node.js 就复用多账号长期上游进程。

### 已确定的最小运维承接

安全运维最终决议只要求最小执行限制，不增加多层暂停记录配额或独立管理平台；全站执行数与账号短队列须同时落实，未解决任务持久保留，业务数量满额明确拒绝新增。参数待实际部署验收，不能宣称已测性能。

本票应落实简单的服务器管理命令，封装原生账号管理与已确认的异常处置，说明管理员初始化、具权身份接入、设密与撤销分别确认、具体目标和状态核验及最小结果记录。不实现网页管理后台、认证内核或直接改数据库的绕过入口；具体恢复和清理资格仍以并发恢复票为准。

本票同时承接私有密钥、缺失密钥与数据库的启动行为、最小日志轮转和无备份灾难边界，并给出精简上线检查与处置清单。实际 Caddy 版本、可信 HTTPS 入口、证书签发与自动续期、端口及 CPU/内存须在部署前核查和验收；不能把规划票已解决或 IP 证书候选当作既有配置已通过，不以明文 HTTP 或忽略证书告警替代。不新增独立监控告警、备份系统、多级审批或商业级恢复承诺。

### 已确定的歌单权限与生命周期输入

[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为权威决议入口，本票应将已授权账号选择、按需配置、可维护与只读来源、同一云端歌单跨房间共用、创建来源和删除资格、成员彻底清理及最小云端清理任务纳入模型与验收条件，不在此重定产品规则。

新建、清理、收藏读取及多账号隔离的真实证据仍由[验证授权复用、账号隔离与官方客户端共存](04-verify-auth-reuse-and-client-coexistence.md)提供；协调和恢复机制由[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md)决定。当前只形成网易云 MVP，不因未来 QQ 音乐、酷狗音乐接入的方向而预先设计平台适配框架。

### 已确定的并发恢复实现约束

以[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md#解决评论并发同步与恢复规则已确认)为权威决议，落实唯一执行权、意图持久化与未发/可能已发/已确认状态、账号及绑定版本隔离、本地事务、共享快照、公平调度、补查和过期操作标识拒绝，不重开已确认的首版产品取舍。

首版固定 Enhanced 基线并逐调用独立进程隔离，须明确显式凭据与设备/会话状态隔离、移除内部重复写入及其他写重试的具体封装，不能以业务层无重试或旧原型小量通过代替生产保证。最终规格须纳入并发票完整验收矩阵，尤其创建 ID 未知不猜同名最新目标、权限撤销不复活旧数据、原账号恢复先确认再续未发步骤，以及管理员异常终结与专用清理不可混用。

### 点歌来源修订的架构承接

[03 的确认修订](03-decide-import-and-song-request-semantics.md#确认修订搜索直接公共点歌与个人歌单可选)为搜索直接公共点歌及个人歌单可选的权威入口。本票须结合 05、06 已同步条款，在接口、最小恢复记录、标签补记及验收中区分实际涉及的个人来源与公共目标绑定；覆盖无个人绑定、个人来源失效/待确认或撤销时仍可直接搜索点歌，以及两种方式均受成员、房主授权及公共目标约束，不重定产品规则。

### 已确认的房间界面层级

[07 的真人反馈](07-prototype-multi-room-web-experience.md#真人反馈确认公共歌单为房间主页面)已确认：房间默认以公共歌单及直接搜索点歌为主，个人歌单作为可选来源在独立视图访问，不与公共歌单同时占据主页面。本票须将此层级纳入页面及更新契约，不采用以个人歌单为中心或双歌单并列的默认点歌界面；具体导航和视觉方案继续由原型票收敛。

[07 的 C 否决反馈](07-prototype-multi-room-web-experience.md#真人反馈否决-c房间导航入口必须直接可见)另已确认：公共歌单、我的歌单、室友歌单、成员和房间设置需直接展示导航入口，不将其他歌单和管理功能统一收入“更多功能”菜单。当前候选只保留 A 的顶部导航与 B 的桌面侧边导航，最终选择尚未确认；本票不得将已否决的隐藏菜单方案作为默认界面。
