## Question

综合账号与房间模型、双类型歌单、导入与点歌语义、授权复用实测、并发失败、安全运维和交互原型，采用什么系统架构、技术栈、数据模型、模块职责、接口与页面更新契约，才能形成无歧义、可直接开发的多房间 MVP 规格？需明确规模目标、非功能约束、验收门槛和延期项，将未证实的上游行为明确标为测试门槛，不实现旧匿名/单房间/主动重排方案的兼容路径。

处理本票据时同时使用 codebase-design 与 domain-modeling。本票最初把当前 feature 目录的 `spec.md` 作为交付物；用户在最终确认时将规格整理明确移交到下一阶段的新特性目录，最终边界以解决评论为准。

### 第一轮确认：单体技术基线与深模块方向

用户确认本轮八项推荐，并承接固定版本复核结论，作为后续数据模型、接口和验收规格的基础：

- 核心采用 SongRoom 专用的持久操作深模块，以封闭业务意图承接点歌、导入、歌单生命周期和清理，统一隐藏调度、恢复、版本隔离及状态机；另设只读查询模块。不暴露步骤、锁键、重试策略或任意工作流扩展点。
- Web 采用同源单体 `Node.js 24 LTS + Fastify + React/Vite SPA`，不使用 SSR、RSC、Next.js 或 React Router 全栈服务器。Better Auth 固定当前稳定版 `1.7.7`，最终规格固定其余直接依赖的受支持稳定版本并精确锁定。
- 已对 Better Auth `1.7.7` 固定源码复核默认认证行为：会话有效期为 7 天、续期间隔为 1 天，使用中按原生机制滚动续期；用户主动改密须验证当前密码，未显式提交 `revokeOtherSessions: true` 时不撤销其他设备会话。SongRoom 沿用这些默认值，不恢复旧 30 天空闲/90 天绝对期限；管理员重设仍须另调用 `revokeUserSessions`。正式接入测试继续验证这些已确定事实。
- 持久化采用 `SQLite WAL + better-sqlite3 + Drizzle`。数据库事务不得跨上游调用，须配置外键与等待锁超时并使用显式迁移；测试运行真实临时 SQLite。普通启动发现数据库缺失时失败，只有显式初始化命令可创建。
- 首版由 systemd 保证一个长期 Node.js 应用进程；HTTP、持久操作调度和上游执行协调同进程运行。每次 Enhanced 调用仍是独立、隔离的短命子进程，重启恢复只依据持久状态。
- 浏览器接口采用普通同源 JSON 命令和查询，加经鉴权的 SSE 失效通知；事件只提示资源版本变化，客户端重新查询权威状态，重连后完整读取可见状态。SSE 不触发持续上游同步，不引入 WebSocket。
- 首版不增加头像、加入时间、在线状态、最后活跃、点歌历史或统计。房间成员信息仅含昵称、房主或室友角色、个人歌单配置状态及按权限可见的只读歌单；账号称呼和邮箱不进入成员视图。
- 首个服务器管理员通过 Better Auth `adminUserIds` 的服务器受限配置声明。操作员先正常注册并经鉴权 `whoami` 取得本人用户 ID，配置后重启；管理 CLI 隐藏输入管理员邮箱与密码并取得真实具权会话，再调用原生管理接口。SSH 身份不替代应用鉴权，不直改数据库；设密和撤销会话分别核验并记录最小审计。
- 浏览器支持当前及前一主版本的桌面 Chrome、Edge、Firefox、Android Chrome 与 iOS Safari；除 `320px` 起响应式验收外，关键流程须支持键盘、可见焦点、语义标签及 WCAG 2.2 AA 对比度。至少使用一台真实桌面和一台真实手机完成上线验收，不支持旧版浏览器。

本轮只锁定基础方向，尚未决定具体数据表、持久操作状态、接口错误模型、版本令牌和任务调度细节。票据保持开放。

### 第二轮确认：持久状态、版本隔离与单进程调度

用户确认本轮全部推荐，并澄清同一点歌台账号须支持手机与电脑等多端同时登录：

- 同一个真实网易云账号不能同时绑定到两个不同点歌台账号；有效绑定按真实网易云账号 ID 全站唯一。同一点歌台账号可以保留多个 Better Auth 设备会话，多端共享同一成员身份、权限和用户级网易云绑定。
- 多端不能绕过业务受理限制：同一成员在同一房间最多一个未完成写操作，跨全部设备统一计算；一端变更后其他端通过 SSE 失效通知重新读取。日常退出仍只结束当前会话，主动改密沿用组件默认行为。
- 成员退出、被移除、删房或换绑时硬删除相应业务实体，不增加软删除和离开档案。已发写入、创建未知或专用清理仍须处理时，只留下不含昵称、快照和导入原文的最小恢复记录；原成员不可继续查看。
- 云端歌单以真实网易云账号 ID 与云端歌单 ID 规范化标识，不同房间绑定同一目标时共享一份快照但分别鉴权。有效完整读取生成单调快照版本，旧读取不能覆盖新结果；绑定另有单调代次，操作捕获账号、绑定代次及具体目标。
- 持久操作区分用户可见聚合状态与内部上游步骤状态。内部写步骤为 `ready`、`sending`、`confirming`、`succeeded`、`rejected`、`unknown`、`stopped`；外部调用前先提交 `sending`，崩溃恢复后一律视为可能已发，只确认、不重发。用户界面使用排队、处理中、待确认、等待授权、需管理员处理、部分完成、成功、明确失败和已停止等业务状态。
- 只有确认提交的写入、写后确认、补查、创建、标签补记和专用清理进入持久操作。搜索、普通读取和手动刷新共用账号及全站调度与受理上限，但只是可取消的内存工作，重启或客户端放弃后可以丢弃；有效完整读取产生的快照仍持久化。
- 确认提交使用按点歌台账号定域的 UUID 幂等标识与规范请求摘要：同标识同内容返回原操作，不同内容或过期标识以稳定 `409` 业务码拒绝。异步新操作返回 `202`，重复同内容返回 `200`；校验、权限、资源不可见、容量或队列满、授权或风控暂停分别使用稳定 HTTP 状态与机器可读业务码，不能靠文案判断。
- 改绑、解除绑定、移除成员、重置邀请、退出和删房等破坏性二次确认须携带页面读取的本地聚合版本，版本变化则拒绝并重新展示影响范围。普通点歌与导入由服务端受理事务捕获绑定版本，不接受浏览器指定云端目标或绑定版本。
- 不建设数据库租约、心跳或分布式锁。systemd 保证单实例，应用成功监听本机端口后才启动唯一调度器；第二实例因端口冲突失败。全站最多两个不同账号执行、每账号同时一个请求，持久化 `nextRequestAt` 保证重启后至少一秒启动间隔；同目标保持先后顺序，其他操作按最久未获得执行机会者轮转，每次上游请求后让出。

本轮未把多端登录误作多个点歌台账号，也不改变 Better Auth 多会话默认策略。票据继续开放。

### 第三轮确认：关系模型、凭据保护与外部接口形状

用户确认本轮全部推荐：

- 一个真实网易云账号只要仍被某个用户的有效绑定或未解决最小任务占用，就保留该用户的授权归属，其他点歌台账号不能绑定。全部旧任务终结且不存在有效绑定后才释放，任何新用户授权都不得执行旧用户清理。
- 应用实体和操作使用服务端生成的 UUIDv7 文本标识；客户端幂等键也使用 UUIDv7。服务端校验时间，超过 24 小时或明显来自未来的标识直接拒绝，因此防重记录过期删除后仍不会把旧标识当成新提交。网易云账号、歌单和歌曲 ID 作为独立的上游不透明字符串保存。
- 核心业务使用有外键、唯一约束和检查约束的关系表，覆盖房间、成员、邀请、申请、网易云授权、规范化云端歌单、绑定、快照歌曲、点歌人标签、持久操作、逐项结果、最小清理及管理员审计。操作采用公共信封与按类型区分的明细表，不以通用 JSON 任务载荷承载权限、调度或恢复真相。
- Better Auth 表由固定版本生成，业务表只引用其用户 ID，不复制密码或会话。持久操作和查询模块直接使用 Drizzle 与真实 SQLite 事务，不为每张表增加 repository interface；测试运行真实迁移。只有网易云外部调用定义 production 与脚本化 mock adapter。
- 网易云凭据使用 Node.js 原生 AES-256-GCM 独立加密，每条授权使用随机 nonce，并以本地授权 ID、真实网易云账号 ID 和凭据代次作为附加认证数据。数据库保存带格式版本的密文包；32 字节主密钥仅从服务器受限文件读取，不进入环境变量、命令行、仓库或日志。
- 首版不开发在线密钥轮换系统。密钥缺失、丢失或主动替换时暂停相关授权并要求重新授权；不得借新网易云账号处理旧账号清理。
- HTTP 采用资源查询和命名明确的业务命令，不提供通用 `/commands` 或任意上游入口。浏览器只提交用户输入、幂等键及必要的本地聚合预期版本，不能提交凭据、真实账号调度键、任意云端歌单 ID、绑定代次或内部步骤。异步结果统一通过操作资源读取。
- 每个登录浏览器使用一个账号级 SSE 流。事件只含资源类型、本地资源 ID 和新版本，不含歌名、昵称、操作结果等业务数据；客户端收到后按当前权限重新查询。事件不补放历史，重连后完整读取；会话失效关闭，旧事件不能绕过成员撤销后的 `404`。
- 每个成员在房间内最多保留最近一项未完成或尚未看完的操作入口。终结后立即删除导入原文、搜索词、候选和无用恢复字段，仅将歌曲 ID、最终逐项结果与摘要保留至明确关闭或最多 24 小时，不提供历史列表；之后删除结果与防重记录。成员资格撤销时立即失去查看权并收缩剩余恢复数据。

### 第四轮确认：页面 read model、命令结果与短命搜索

### 解决评论：多房间 MVP 架构决策已确认

用户通过六轮 grilling 确认了全部推荐及邀请码修订。本评论与上方六轮确认共同构成本票权威答案，取代正文中仍保留的旧 A/B/C 导航候选、早期版本调查和其他阶段性表述；01–07 各票解决评论继续分别作为产品规则、真实证据和交互决策来源。

#### 系统形状

- 首版是同源、单部署单元的 TypeScript/Node.js 应用：Fastify 提供 HTTP，React/Vite 提供 SPA，Better Auth `1.7.7` 管理邮箱密码认证，Drizzle 与 SQLite WAL 保存认证、业务和持久操作状态。Caddy 负责浏览器可信 HTTPS，systemd 保证单应用实例。
- 核心为 SongRoom 专用持久操作深模块和页面 read model。持久操作接受封闭业务意图，统一隐藏上游调度、步骤状态、崩溃恢复、目标阻塞、账号与绑定代次隔离；查询按房间实际页面提供，不暴露数据库行或内部步骤。数据库事务不跨上游调用。
- 正式应用与受审 Enhanced vendor 包组成一个 pnpm workspace，不拆微服务、独立 worker 服务、通用工作流引擎、每表 repository 或未来音乐平台适配层。

#### 数据与恢复

- 本地业务采用有外键和约束的关系模型，成员与房间生命周期结束时硬删除业务数据；未解决写入、创建未知和专用清理只留下继续判定所必需的最小记录。云端歌单按真实账号与云端歌单 ID 规范化，不同房间绑定共享快照但独立鉴权。
- 操作与实体使用 UUIDv7；客户端 UUIDv7 幂等键按账号定域，终态结果最多保留 24 小时，过期标识根据时间直接拒绝。写步骤发出前持久化为 `sending`，任何崩溃窗口都按可能已发处理，只读确认、不自动重发。
- 调度器与 HTTP 同进程，由唯一成功监听端口的进程拥有执行权；全站最多两个不同账号执行，每真实账号串行且启动至少间隔一秒，同目标保持先后，其他操作按最久未服务者公平轮转。搜索和普通刷新参与相同限制但只作为可取消的内存任务。

#### 网易云与安全

- 每次 Enhanced 调用使用独立短命进程、一次性私有临时目录、最小环境和显式加密凭据。固定源码补丁删除歌曲增删内部重写、隐式环境凭据与敏感原始日志；对 `playlist_create`、`playlist_delete`、`playlist_tracks` 及请求层的静态核查确认白名单中不存在其他原业务写重放，生产 adapter 不暴露其他写方法，离线契约要求每个业务步骤最多一次上游写。worker 只返回受 schema 约束的脱敏结果；固定版本、哈希、补丁与白名单变化后均须重审并在部署后复验。
- 网易云凭据使用 AES-256-GCM 逐条加密，主密钥与数据库分离。真实网易云账号在有效绑定或未解决最小任务期间只归属一个点歌台账号；新用户授权不能处理旧用户清理。
- Better Auth `1.7.7` 使用已复核的原生默认认证策略：会话 7 天有效、1 天更新间隔并在使用中滚动续期；主动改密校验当前密码且默认不撤销其他设备会话。管理员重设密码须另调用 `revokeUserSessions`。服务器管理 CLI 每次经可信 HTTPS 真实登录具权管理员会话，只提供已确认的账号恢复和异常处置命令；SSH 身份不能绕过鉴权。普通日志脱敏并由 journald 限量保存，高风险命令另写最小数据库审计。

#### 浏览器契约

- 页面使用端点级 Zod schema、资源查询和命名业务命令。所有 SongRoom 变更具幂等键；纯本地、云端异步及本地完成但云端待清理分别返回明确结果。错误、操作状态和允许动作均使用稳定机器码，不由浏览器解释文案。
- 页面本地查询不自动访问上游；进入相关页面或手动刷新时显式触发一次短命读取，完成后通过账号级 SSE 只发送资源失效通知，客户端重新读取当前有权 view。事件不承载业务数据，不补历史。
- 房间采用已确认的响应式四入口；服务端状态由 TanStack Query 管理，导航、滚动、弹窗和未提交导入只在当前标签页的房间级内存中存在。辅助成员字段、跨设备草稿和操作历史均不进入首版。
- 邀请码固定为 10 个 base64url 字符、60 位随机熵；链接使用 URL fragment，登录后再通过 POST 提交，避免进入 HTTP 请求和访问日志。
