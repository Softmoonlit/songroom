# 验证授权复用、账号隔离与官方客户端共存

Type: prototype
Label: wayfinder:prototype
Status: resolved
Assignee: Codex

## Question

在低风险真实账号原型中，同一份用户级网易云授权能否用于多个房间的独立歌单，并在同一服务内与其他房主账号正确隔离？首次授权、重新授权、官方电脑客户端重新登录对双方会话有何影响，能否满足点歌台与官方客户端同时可用的上线门槛？需核查依赖的 Cookie/设备参数隔离，记录版本、操作范围、观察结果与未证实条件；若失败，决定可验证的完整授权方式或确认方案被阻塞。

## Comments

### 证据入口与 HITL 边界

用户级复用前提见[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#已确认输入用户级网易云绑定与授权复用)。既有 [扫码授权平台调查](../../dorm-song-request/issues/06-decide-public-room-and-auth-security.md#调查证据扫码授权平台与官方客户端会话影响) 仅证明默认参数，未实测官方客户端并存。

用户已确认同时可用为上线验收条件。本票据为 HITL：开始前与参与房主确认账号、专用测试歌单、操作及观察时机，由人扫描和确认；不自行获取凭据、不压测、不记录原始 Cookie，也不把未合入的 Web 登录修改视为已经可用。

测试不能只观察播放器继续出声或点歌台页面缓存；需验证真实登录请求、歌单读取及约定的低频写入。账号隔离不能仅依靠不同界面按钮，须验证调用实际使用的凭据与目标歌单。

### 歌单生命周期决议补充的验证门槛

以[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为约束，在用户明确批准的专用测试范围内补充验证：按需创建、读取和删除专用歌单；同一房主跨房间共用同一已有个人歌单；收藏来源读取并把所选歌曲写入可维护目标；无权限、授权失效和确认删除的结果判别。不能向原作者的收藏歌单发起写入，不能删除日常已有歌单，也不能将自建歌单的旧实测冒充全部收藏歌单或共享歌单权限证明。

建房选账号只复用当前用户已有的网易云授权，本票不扩展到多网易云账号绑定或其他音乐平台。来源类型、清理目标及多房主凭据都须实际核对，不以界面正确作为隔离通过的证据。

### 导入与点歌决议补充的验证入口

以[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)为产品约束，核对搜索单曲候选的实际字段与数量参数，明确歌名、歌手、专辑和歌曲 ID 的展示及校验依据，不假定首候选准确或依赖未文档化的置信度。补充重复歌曲、混合新旧歌曲批次与写后读回的证据，标明哪些异常仅可由可控测试模拟。

百行输入和五候选是产品取舍，不是上游批次上限或容量实测。超过原批准范围的真实账号调用须重新确认，不自行压测或制造账号风险；本票记录接口事实，失败调度与恢复仍由并发票据决定。

### 解决评论：固定基线的小量实测通过

本票在已批准的低风险样本范围内解决，可继续多房间 MVP 规划。这里的通过是上游能力与共存条件验证，不是正式应用、生产隔离或永久多端稳定性的上线验收。

完整原型作为 primary source 保存在分支 `prototype/verify-auth-reuse-and-coexistence`，最终提交 `dc8bce6`，入口为 `prototypes/verify-auth-reuse-and-coexistence/README.md`，筛选后的接口证据为同目录 `observations.jsonl`。主分支仅保留结论与证据指针，不合入实验应用。

**基线与授权隔离**

- Enhanced `4.40.1`，固定源码 `a8c781fd64faab17fedfd46e0615a2609307f163`，未修改上游；A 官方电脑客户端为 Windows 11、`3.1.41`。二维码使用 PC 基线，不采用未经验证的 Web 登录改动。
- 同一 A 授权创建、读取和维护两份独立房间目标，两个目标操作前读取同一 A.source；不按房间复制凭据。用户已有的普通自建歌单只读两次成功，但为空，不能把该空样本冒充所有已有歌单类型或非空内容的证明。
- A/B 使用独立私有 Cookie、稳定设备参数和每次调用的账号独立进程、TMPDIR，并移除隐式 Cookie 环境变量。交替调用始终匹配各自实际账号，目标内容没有互相覆盖。源码的进程共享状态风险仍存在，不能只传不同 Cookie 就认为生产隔离已落实。
- 首次服务端扫码、A 再次扫码授权、官方客户端退出并重新登录 A 的三个阶段均有用户客户端刷新观察及服务端真实身份、读取、小量写入证据，未观察到相互挤下线。客户端重登后的 A.room2 新增也由用户确认可见。首次再授权二维码失效提示与服务端 `801` 不一致，根因未确定；独立图片文件名的新轮次成功不代表解决全部扫码失效问题。

**收藏来源与绑定能力**

用户收藏后重新读取 `user_playlist`，直接从 A 的账号清单发现「假日出逃｜把期待装进行李，出发吧！」（`18404052595`），创建者不是 A、`subscribed: true`、普通类型 `0`；详情读回 56 首。不需要依赖分享链接列举收藏，也不保存用户分享链接中的附加参数。

正式绑定入口应让用户从已授权账号的自建及收藏清单选择，服务端核验当前身份和选定 ID 的归属或收藏关系，保存绑定与快照；只因一个公开 ID 可读，不代表允许将它绑定为自己的个人来源。收藏只读，点歌仅向自有可维护目标写入。本轮从实时收藏来源取 `3342319503` 写入 A.room1，响应 `200` 且读回三首；来源复读仍为同一 56 个 ID 及顺序，没有向原作者写入或取消收藏。尚无正式房间绑定和点歌标签实现。

**结果判读与清理**

- 无登录凭据的可控只读对照仍返回 `200`，但 `account`、`profile` 为空；它模拟凭据缺失，没有真实撤销授权或观测自然过期。现有 session 不被覆盖，之后 A/B/A/B 复查仍正常。此前已登录账号交叉读取对方隐私歌单的真实 `401` 是目标权限拒绝，不直接判为授权失效。有效授权须核对实际账号，网络或模块错误不能冒充确定失效。
- 搜索、重复 ID、混合新旧批次和写后读回事实见此前评论。一次重复添加返回 `502` 但集合及顺序不变，不能凭响应码重放或推断失败；百行输入不是已验证上游容量，未验证可播放性。
- A 三份、B 一份专用测试歌单均只发起一次删除、响应 `200`，在各自身份匹配的完整 `more === false` 账号清单中确认移除。删除后详情仍可 `200` 返回状态 `10` 和旧歌曲，也观察到一次无快照的 `502`；正常隐私歌单此前状态为 `0`。不能假定删除必然使详情立即 `404`，也不能将任何 `502` 当删除成功。
- 原型在删除前登记意图，已发起后禁止继续写入或重新删除；补查只读。删除确认要求当前身份匹配、完整账号清单无登记 ID；详情若仍有对象，还须与该目标的已删除状态、ID、名称、创建者相符，不能与存活详情矛盾。B 初次旧判据停止后仅补查确认，没有重发删除。清理完成不承诺网易云内部物理擦除或详情永远不可读。
- 最终 A 保留「我喜欢的音乐」、旧空的「点歌台 API 验证（临时）」和本次仍为 56 首的收藏，B 保留其「我喜欢的音乐」。没有清空、删除或修改日常和收藏歌单。四份专用云端目标登记均已标记删除；本地 A/B session、扫码候选及待确认文件、真实调用临时目录也已清除，未调用网易云 logout 或撤销官方客户端会话。
