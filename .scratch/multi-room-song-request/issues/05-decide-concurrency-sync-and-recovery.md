# 确定多歌单并发、同步与失败恢复

Type: grilling
Label: wayfinder:grilling
Status: open
Blocked by: 02, 03, 04

## Question

多房间复用一个房主授权、多房主在同一服务写入各自歌单时，读取、按需创建、个人歌单维护、文本导入、标签提交、授权退出/更换及成员撤销和云端歌单清理如何有序协调？需决定串行化和限流边界、批次部分成功、超时但上游实际成功、同步失败、重复请求、旧结果隔离及外部客户端修改的处理，确保只展示云端实际歌曲与顺序，不重放旧顺序或自动重排争夺状态。

## Comments

### 既有证据的适用边界

旧[外部歌单协调调查](../../dorm-song-request/issues/05-decide-external-playlist-reconciliation.md#调查证据条件写入与读取缓存边界) 涉及完整歌曲 ID、缓存和缺乏原子条件写入的事实，仍是调查入口；新的多房间调度、每账号总量限制和纯快照写入规则须重新决定，不能直接沿用旧单房间完整排序工作流。

授权复用与退出影响全部自建房间的前提见[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#已确认输入用户级网易云绑定与授权复用)。须明确已经发往上游的操作不能凭本地撤销假装取消，旧授权和旧快照结果不得作用于新账号绑定。

### 歌单共用与清理任务的新增边界

以[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为约束，本票还须决定：

- 同一房主已有个人歌单被多个房间共用时，写入协调与各快照更新如何覆盖同一云端目标，不能把不同房间误当成独立歌单。
- 按需创建、超时但云端实际创建、创建成功但本地关联未完成，以及成员退出或删房期间的在途操作如何避免产生僵尸歌单或恢复已清除的业务数据。
- 最小清理任务如何持久化、恢复、确认完成，并处理重复删除、超时但上游已删除、原账号失效或更换；任务不能保存离开成员档案，不能作用于新账号或重新加入后新建的歌单。
- 确认歌单删除与暂时读取失败如何区分，重新配置后旧快照、旧标签及旧请求结果如何隔离；本票不得通过自动复制旧歌曲、重建旧成员关联或本地排序补偿改变最终生命周期规则。

### 导入与点歌决议补充的恢复问题

以[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)为约束，本票进一步决定：

- 百行搜索的每账号限流、调度、失败终结和修改输入后的旧结果隔离，不引入智能匹配或单行自动重试功能。
- 产品输入规模与上游写入批次如何分离，混合新旧歌曲、上游拒绝、容量不足及部分接受的读回证据如何分类，不因接口错误码或超时直接断言失败。
- 不保存未提交草稿、没有导入历史和取消入口的前提下，已提交操作在关页、重启或重复请求后的结果确认与恢复需要保留什么最小信息；不把关页当取消，不重放未知结果或回滚成功部分。
- 点歌前核对当前个人来源后，上游继续修改的并发边界；绑定、授权或成员撤销后如何停止尚未发出的操作并隔离在途结果。
- 云端歌曲确认与本地去重标签记录如何协调，标签未完成和结果待确认如何恢复；已有公共歌曲的标签更新不应重复增歌，同一成员重复点歌不重复计数。
