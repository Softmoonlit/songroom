# 确定多歌单并发、同步与失败恢复

Type: grilling
Label: wayfinder:grilling, resolved
Status: resolved
Assignee: Codex
Blocked by: 02, 03, 04

## Question

多房间复用一个房主授权、多房主在同一服务写入各自歌单时，读取、按需创建、个人歌单维护、文本导入、直接搜索或个人来源的逐首公共点歌、标签提交、授权退出/更换及成员撤销和云端歌单清理如何有序协调？需决定串行化和限流边界、批次部分成功、超时但上游实际成功、同步失败、重复请求、旧结果隔离及外部客户端修改的处理，确保只展示云端实际歌曲与顺序，并使个人来源的核验、失效与待确认仅影响使用该来源的操作，不重放旧顺序或自动重排争夺状态。

## Comments

当前执行规则以[解决评论](#解决评论并发同步与恢复规则已确认)及后续决议、[修订指针](#后续修订指针搜索直接公共点歌与个人歌单可选)为准；下方轮次记录为讨论历史，其中所有公共点歌均须读取个人来源的旧规则不再作为现行要求。

### 既有证据的适用边界

旧[外部歌单协调调查](../../dorm-song-request/issues/05-decide-external-playlist-reconciliation.md#调查证据条件写入与读取缓存边界) 涉及完整歌曲 ID、缓存和缺乏原子条件写入的事实，仍是调查入口；新的多房间调度、每账号总量限制和纯快照写入规则须重新决定，不能直接沿用旧单房间完整排序工作流。

授权复用与退出影响全部自建房间的前提见[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#已确认输入用户级网易云绑定与授权复用)。须明确已经发往上游的操作不能凭本地撤销假装取消，旧授权和旧快照结果不得作用于新账号绑定。

### 歌单共用与清理任务的新增边界

以[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为约束，本票还须决定：

- 同一房主已有个人歌单被多个房间共用时，写入协调与各快照更新如何覆盖同一云端目标，不能把不同房间误当成独立歌单。
- 按需创建、超时但云端实际创建、创建成功但本地关联未完成，以及成员退出或删房期间的在途操作如何避免产生僵尸歌单或恢复已清除的业务数据。
- 最小清理任务如何持久化、恢复、确认完成，并处理重复删除、超时但上游已删除、原账号失效或更换；任务不能保存离开成员档案，不能作用于新账号或重新加入后新建的歌单。
- 确认歌单删除与暂时读取失败如何区分，重新配置后旧快照、旧标签及旧请求结果如何隔离；本票不得通过自动复制旧歌曲、重建旧成员关联或本地排序补偿改变最终生命周期规则。

### 导入与点歌决议补充的恢复问题

以[确定文本导入与公共点歌语义](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)为约束，本票进一步决定：

- 百行搜索的每账号限流、调度、失败终结和修改输入后的旧结果隔离，不引入智能匹配或单行自动重试功能。
- 产品输入规模与上游写入批次如何分离，混合新旧歌曲、上游拒绝、容量不足及部分接受的读回证据如何分类，不因接口错误码或超时直接断言失败。
- 不保存未提交草稿、没有导入历史和取消入口的前提下，已提交操作在关页、重启或重复请求后的结果确认与恢复需要保留什么最小信息；不把关页当取消，不重放未知结果或回滚成功部分。
- 点歌前核对当前个人来源后，上游继续修改的并发边界；绑定、授权或成员撤销后如何停止尚未发出的操作并隔离在途结果。
- 云端歌曲确认与本地去重标签记录如何协调，标签未完成和结果待确认如何恢复；已有公共歌曲的标签更新不应重复增歌，同一成员重复点歌不重复计数。

### 授权复用实测提供的结果分类输入

[授权复用与共存](04-verify-auth-reuse-and-client-coexistence.md#解决评论固定基线的小量实测通过)已在固定 PC 基线的低风险样本范围内解决，原型 primary source 为 `prototype/verify-auth-reuse-and-coexistence` 分支提交 `dc8bce6`。本票须据此决定机制，不把样本事实扩大为永久保证：

- 无登录凭据的可控对照返回 `200` 但账号及个人资料为空；真实登录正常时，跨账号隐私歌单读取返回 `401`。授权核验与目标权限错误必须分开，网络或模块异常不冒充确定失效，未观测到自然到期。
- 收藏可以从当前账号清单直接列举并核验创建者、收藏关系；来源绑定不依赖手填分享链接，也不能因任意公开 ID 可读就允许绑定。公共点歌仍须另读当前有效来源。
- 删除专用目标的响应为 `200`，完整同账号清单已无 ID，但详情可能继续返回 `200`、状态 `10` 和旧歌曲；另有无快照的 `502`。不能把详情必然 `404` 作为完成前提，也不能将任何 `502` 当成功。须定义确认完整清单与当前身份、矛盾详情及结果待确认的机制，不重放已发起的删除。
- 已删除对象仍可读出的旧歌曲不能当有效来源或公共点歌成功依据。结果确认必须识别目标是否仍有效，不能只看 `code: 200`、存在歌单对象或旧歌曲 ID。
- 重复歌曲请求返回 `502`，云端实际集合及顺序不变；混合新旧批次读回两个唯一 ID。产品百行上限不是已测上游容量，错误码不能代替写后读回或成为自动重放依据。

四份专用云端目标及本轮本地凭据已清理，不存在遗留清理任务。本票不直接复用实验凭据；额外真实调用须重新确认范围和授权。

### 第一轮确认：账号级串行、按需同步与服务端恢复

用户明确同意本轮三项推荐。本票仍在讨论中，下述为已确认输入，不是整票解决评论。

- 以真实网易云账号识别调度对象，同一账号每次只执行一个上游请求，不按房间划分；不同账号可以并行。同一云端歌单被多个房间共用时不能视为独立目标。长任务在上游请求之间让出执行机会，尚未确认的操作不一直占住整个账号；公平调度、限流及冲突阻塞范围继续讨论。
- 首版按需同步：进入页面、手动刷新、操作所需核验及写后读回时同步，不做页面持续定期轮询。展示最近成功同步时间；读取失败保留最后成功快照并标明未更新，不因失败清空歌曲或标签。公共歌曲的标签只在有效、完整读取确认歌曲已移除时清除。
- 已接受的操作由服务端持久化最小恢复记录，关页或服务重启后继续确认，不保存未提交草稿或形成导入历史。未知结果先读取核验，不自动重发不确定的写请求；完成后清除恢复所需的歌曲输入等信息，仅短期保留防重复提交所需的最小结果。等待原账号重新授权的任务暂停，不能使用新绑定账号处理。
- 账号级串行不替代账号隔离。[授权复用与共存](04-verify-auth-reuse-and-client-coexistence.md#解决评论固定基线的小量实测通过)只验证了每次调用独立进程的低频隔离方式，正式应用的隔离方式仍须明确并验证。
- 固定版本的增歌模块存在特定错误路径下的内部重复写入，禁止重放须覆盖依赖内部，不能只限制业务层重试。未找到创建歌单接口支持幂等键的证据，创建结果未知时不能直接再次创建；识别与恢复规则继续讨论。

### 第二轮确认：目标阻塞、短队列、逐首导入与提交防重

用户明确同意本轮四项推荐，本票仍保持开放。

- 结果待确认只阻塞涉及对应云端歌单的冲突操作，不阻塞整个网易云账号。允许读取和结果确认，暂停该目标新的增删、清空及以其为来源的公共点歌；同一云端歌单的全部房间绑定采用相同阻塞范围，不能换房间绕过。其他歌单继续处理。
- 每个成员在同一房间最多有一个未完成写操作，重复点击返回原操作状态，不新建任务。不同成员可以排队，采用有上限的短队列；队列满时明确反馈繁忙，本次不接受。容量和限流参数后续明确。
- 长任务每完成一个上游请求就允许其他可执行任务轮流获得机会；同一歌单的冲突操作仍按先后顺序协调。每个导入页面只保留一轮有效搜索；修改输入重新搜索后停止旧轮尚未发出的请求，丢弃旧轮在途结果，不自动重试搜索失败行。
- 首版导入逐首添加、每首写后读回确认。先完整读取目标，已存在歌曲跳过写入，仅写缺少歌曲，不调整顺序。某首结果未知时暂停该歌单后续写入并先确认；明确失败可继续处理下一首，成功部分不回滚。百行上限不是上游批次保证，未验证前不切换为大批写入。
- 每次确认提交使用唯一操作标识；同标识同内容返回原状态，同标识不同内容拒绝，不重新写入。未完成记录保留到确认或按生命周期终止，成员仍有权限时重新进入相关歌单可查看当前状态；完成后删除歌曲输入等恢复数据，只短期保留最小防重记录，不提供历史列表。保留期限后续明确。
- 权限撤销后立即禁止查看操作状态，清除成员业务数据，只留下必要的云端清理信息；不能借恢复记录保留离开成员档案。

### 第三轮输入：清空范围确认，核验与命名方案待简化

- 用户同意清空只针对执行开始时完整读取到的歌曲 ID 集合，不循环删除外部新增歌曲；最终仍有新歌时不假报空歌单。同 ID 外部删除后重加仍可能被选定 ID 的删除请求影响，点歌台不能保证消除该窗口。用户同时询问删除是否还需要确认，结果判定尚待讨论。
- 用户提出公共歌单名采用 `songroom-公共-<房间名>`，尚未确认随机命名标记方案；普通显示名称与创建超时后唯一识别目标须分开决定。
- 用户质疑删除、增歌与来源核验的必要性，尚未确认上一轮这些推荐；不能把第三轮全部视为通过，也不能据此擅自推翻[文本导入与公共点歌规则](03-decide-import-and-song-request-semantics.md#解决评论文本导入与公共点歌规则已确认)中既有的当前来源核对与写后实际同步规则。
- 只读核查固定源码：`module/playlist_create.js` 和 `module/playlist_delete.js` 返回上游请求结果；创建成功样本取得具体歌单 ID，删除成功样本业务码为 `200`。`module/playlist_tracks.js` 在普通错误路径也会包装外层 `status: 200`，业务结果须解析响应体；`512` 路径会内部再次请求。文件位于授权复用原型固定源码目录，未发起新真实调用。
- 删除详情仍返回旧歌曲不能证明删除失败，恰恰是既有成功删除样本的表现；必须区分接口明确成功、正常快照同步和响应丢失或矛盾后的补查，不能把所有成功请求都当未知或无依据扩大为多轮核验。正常响应与异常补查的最终简化规则继续讨论。

### 第四轮确认：正常成功路径简化与可读歌单名

用户同意简化方案，并修正公共歌单命名顺序。以下取代第三轮未获确认的多重核验推荐；本票仍未解决。

- 公共歌单名称采用 `songroom-<房间名>-公共`。用户另提出 `songroom-公共-<房间名>-<成员1>`，其对应歌单类型及是否统一顺序尚待澄清，不能自行视为已确认的室友个人歌单命名。
- 正常创建成功取得具体云端歌单 ID 后按 ID 管理，不依靠名称识别，房间改名不自动修改云端名称。不在可读名称中强制加入随机标记。创建响应丢失而 ID 未知时暂停，由房主核对原账号清单并确认目标，不按名称自动认领或删除，也不自动重复创建；人工确认的安全校验与验收仍须落实。
- 删除整个专用云端歌单收到明确业务成功响应时按成功完成清理，不在正常路径强制做身份、完整清单与详情三重核验。只有超时、响应丢失或结果不明确时补查；删除后详情仍能读旧歌曲不意味着删除失败。服务端执行前的账号、权限、专用创建来源与具体目标 ID 校验不能省略，也不能把 HTTP 状态 `200` 当业务成功。
- 歌曲添加与删除解析业务结果，并使用正常的一次写后读回更新实际歌曲集合与顺序、同时确认相关 ID，不另加多轮核验。业务成功而同步失败时分别反馈接口报告成功与结果尚未同步确认，不重发、不假造快照；异常才进入补查。逐首写后读回规则保持不变。
- 保留公共点歌执行前的一次当前个人来源读取，不反复核验；这源自当前来源产品规则而非添加接口的技术要求。读取失败不能凭旧快照放行，成员资格与绑定权限检查不能省略。
- 清空及批量删除需要用户二次确认，单首删除直接操作。清空仍仅处理执行开始时完整读取到的 ID 集合，不追着外部新增反复删除，最终读回不为空时不假报空歌单。
- 第三轮的标签补记和外部竞态细节尚未整体确认；保留一次来源读取不等于已经解决所有在途、标签与生命周期协调规则。

### 第五轮确认：个人歌单命名、生命周期隔离与恢复参数

用户明确确认本轮规则，个人歌单名称按其修正为准。

- 室友新建专用个人歌单名称采用 `songroom-<房间名>-<成员昵称>`，不加入“个人”或随机标记。房主绑定已有歌单不改名，房间与昵称后续变化不自动修改云端名称；名称不是身份或唯一恢复依据。
- 歌曲已确认在公共歌单而标签保存失败时只补标签，不再次增歌。补记前重新确认公共歌曲有效存在，原成员资格及相关绑定仍有效；同一成员标签去重。外部修改不能被点歌台串行化约束，执行前一次来源核验不承诺上游原子同步，不因后续外部变化回滚公共歌曲。
- 成员撤销、删房或换绑立即停止尚未发出的步骤；已发请求可能继续作用于旧云端目标，其返回不得恢复旧业务数据或写入新绑定。退出授权或确认授权失效则暂停，原账号重新授权后先核验未明结果，再决定是否继续尚未发出的步骤，不使用新账号处理旧任务。
- 同账号请求启动至少间隔 1 秒，每账号最多 20 个执行中或排队操作；一轮百行搜索或一次导入各算一个操作，不按歌曲数量占队列。等待人工处理或重新授权的任务不占执行槽，但不能无限累积，存储配额交由[安全、部署与运维](06-decide-security-deployment-and-operations.md)明确。参数是首版待验收工作点，不是上游安全阈值或永久保证。
- 搜索、读取、写入和补查共用账号限流。明确风控或频繁请求提示后暂停该账号上游请求，不持续试探；普通目标权限错误只暂停受影响目标，不直接判整个账号授权失效。
- 首次同步失败后最多自动补查三轮，分别约在失败后 5 秒、30 秒、2 分钟调度，仍受账号限流；不是保证执行的精确时刻。未确认则保留待确认状态并停止自动请求，手动刷新或原账号重新授权可触发新一轮只读确认，不重发未知写入。异常返回是否有可恢复对象及账号可用性仍须先判定，搜索失败不采用这套自动补查。
- 终结后的最小防重复记录保留 24 小时，不保留歌曲输入或提供历史列表；过期操作标识拒绝，不能当新操作执行。未解决的恢复或清理任务不因满 24 小时而删除，权限撤销仍立即清除成员业务信息。人工终结与解除阻塞的规则尚待明确。

### 第六轮确认：管理员异常处理、共享快照与依赖隔离

- 普通歌曲增删或标签任务在长期无法查明时，可由管理员核对原账号、目标当前状态和请求记录后终结为“结果未能确认”并解除阻塞。不提供成员取消任务按钮，不宣称原写入失败、不撤销云端效果、不自动补写；后续操作须重读当前状态并作为新操作明确提交，不能恢复旧成员或旧绑定。管理员入口与审计交由[安全、部署与运维](06-decide-security-deployment-and-operations.md)决定。此规则不允许直接丢弃创建未知或专用歌单删除未知任务，两者仍保留最小核查或清理信息。
- 服务端按真实网易云账号与云端歌单 ID 维护统一快照，各房间引用并分别检查权限；一次有效完整读取更新所有仍有效引用，已经打开的页面仍按需同步，不增持续轮询。快照、公共歌曲移除后的标签清理及标签提交须保持本地一致，旧读取结果不得覆盖较新快照或新绑定。
- 首版固定 Enhanced `4.40.1` 已验证基线，每次调用独立进程、显式传该账号凭据和独立临时目录，移除隐式全局凭据来源；不得采用未经验证的多账号共享长期进程。移除或禁用歌曲增删模块内部自动重复写入，核查底层其他写请求重试；具体封装由[系统架构与规格](08-decide-mvp-architecture-and-spec.md)承接，改动后与实际部署均须重新测试。
- 创建正常返回具体歌单 ID 时，自动按该 ID 关联有效目标，无需房主再次确认。用户希望自动识别新建歌单，并提出重名时按最新日期选择；这一建议与“创建响应丢失、云端 ID 未知”异常路径尚需澄清。不能把普通创建成功的自动绑定误写为每次都要求人工认领；正常路径不需要按名称或日期猜 ID。
- 原账号重新授权后尚未发步骤的自动继续规则、风控暂停解除，以及明确拒绝删除后的人工清理仍待收口。

### 解决评论：并发同步与恢复规则已确认

用户已明确确认全部剩余取舍。本评论为本票最终决议，取代上述讨论中与之冲突的推荐和阶段性输入；不采用创建后按名称或最新日期猜测目标、正常删除成功后的强制多重核验、未经验证的多账号共享长期进程。本票只形成决策，不开发正式应用，不调用真实账号。

#### 调度、冲突与限流

- 以真实网易云账号识别调度对象，同账号每次只执行一个上游请求，不按点歌台账号或房间拆成独立队列；不同网易云账号可以并行。账号级串行不能替代凭据与依赖进程状态隔离，也不能约束网易云官方客户端。
- 首版同账号请求启动至少间隔 1 秒，每账号最多 20 个执行中或排队操作。一轮百行搜索、一次导入各算一个操作，不按歌曲数量占队列；搜索、读取、写入及补查共用限流。参数是待验收的初始工作点，不是上游安全阈值保证。
- 每个成员在同一房间最多有一个未完成写操作；重复点击返回原操作，不新建任务。不同成员可以排队，满额明确反馈繁忙且本次不接受，不无限排队。等待重新授权或人工处理不占执行槽；暂停记录的配额取舍以[确定多房间安全、部署与运维边界](06-decide-security-deployment-and-operations.md#解决评论安全部署与运维边界已确认)为准，未解决恢复或清理任务不能为腾空间丢弃。
- 长任务在上游请求之间让出执行机会，其他可执行操作轮流获得机会。同一云端歌单的冲突操作保持先后顺序，操作内部的来源核验（仅个人来源点歌）、写入与确认阶段不能因让出账号执行机会而被同目标冲突操作穿插破坏。
- 结果待确认只阻塞对应云端歌单的冲突操作，不占住整个账号。允许读取和确认，暂停该目标新的增删、清空及从该个人歌单发起的公共点歌；阻塞覆盖同一目标全部房间绑定，其他歌单照常处理。直接搜索点歌仍受公共目标的冲突阻塞，个人来源目标的待确认阻塞不会扩散到直接搜索点歌；成员自己在该房间已有未完成写操作时，仍受上述单成员受理限制。
- 明确风控或频繁请求提示后暂停该账号上游请求，不持续试探，须人工明确恢复。普通目标权限错误仅暂停受影响目标，网络、模块异常或单个目标 `401` 不能直接判整个账号授权失效；须以当前账号身份核查区分授权不可用、账号不匹配和目标权限问题。

#### 快照、来源与外部并发

- 云端歌曲集合与顺序是唯一权威，服务端按真实网易云账号与云端歌单 ID 维护统一快照，各房间绑定引用并独立检查权限；共享快照不扩展房间成员权限。
- 首版按需同步：进入页面、手动刷新、操作所需核验及写后读回，不持续轮询。展示最近成功同步时间；有效完整读取更新所有仍有效引用，已打开页面仍按需更新，不承诺实时一致。
- 个人来源中的歌曲存在性与公共目标结果判定依赖完整歌曲 ID 集合及有效目标状态，不能将默认取前 1000 首、部分 `tracks` 或已删除对象的旧歌曲当成完整有效来源或目标。直接调用固定模块绕过依赖 HTTP 路由缓存，但不据此承诺网易云强一致；具体完整读取契约仍须验收。
- 读取失败保留最后确认快照并标明未更新，不清空歌曲或标签。只有有效完整读取确认公共歌曲已移除时，才清除该歌曲全部标签；未观察到的外部删除后重加不结束标签生命周期。
- 从自己的个人歌单点歌时，执行前读取当前归属成员的个人歌单一次，确认绑定有效、歌曲仍在有效来源才放行，可写与只读来源同规则。来源已变化则反馈并刷新；读取失败不能凭旧快照继续，不能因任意公开 ID 可读就认为仍满足当前绑定的归属或收藏关系。直接搜索点歌不读取个人歌单，不要求个人绑定，也不受个人来源失效阻塞。
- 个人来源点歌接受来源核验后的外部竞态窗口，不承诺与官方客户端原子同步，不因随后外部删歌回滚公共歌曲。两种点歌方式的上游均可在操作和读回之间修改公共歌单，成功表示确认时的状态，不表示由本次操作独占造成或以后永远不变。
- 不主动置顶、重排、回放旧顺序、自动复制旧歌曲或与官方客户端争夺状态。确认来源删除或关系失效后的重新配置遵守生命周期票，单次读取失败不是删除证据，详情仍为 `200` 且有旧歌曲也不是有效来源证明。

#### 搜索、逐首写入与清空

- 文本导入搜索沿用百行、每行前五候选的既有规则，每个导入页面只保留一轮有效搜索；修改输入重新搜索后停止旧轮尚未发出的请求，丢弃旧轮在途结果，不自动重试失败行，不持久化未提交草稿。直接搜索点歌共用既有账号调度和限流，不套用文本导入的候选流程。
- 导入先完整读取目标并按歌曲 ID 去重，已存在项跳过写入。首版逐首添加、每首写后读回；仅添加缺少 ID，不调整云端顺序，不把百行产品上限当作已验证上游批次。
- 解析响应体的业务结果，不能把外层 HTTP `200` 当作添加或删除成功。正常的一次写后读回同时更新实际歌曲与顺序、确认相关 ID，不额外叠加多轮核验。
- 逐项区分已加入、已存在、明确失败和结果待确认；明确拒绝可判失败并继续后续项，成功部分不回滚。一般错误码、超时、同步失败或成功响应后歌曲缺失不单独构成可重放的失败证据；结果未知先阻塞该目标后续写入并确认。
- 接口报告成功但同步失败时分别说明接口结果与尚未同步确认，不重发、不用本地选择假造快照。读回确认成功表示当前云端包含该 ID，不保证可播放，也不必证明是本次操作首次加入。
- 单首删除直接操作，批量删除和清空需要用户二次确认。清空只处理执行开始时完整读取到的 ID 集合，逐首删除并确认，不循环追删外部新增；批量删除按选定 ID 操作。最终仍有新歌时不假报空歌单；外部将同一 ID 删除后又加回仍可能被选定 ID 的删除影响，不能保证消除该窗口。

#### 公共点歌与标签补记

- 两种点歌方式均须校验当前成员资格、房主授权、有效公共目标及目标冲突；从个人歌单点歌另须通过当前有效个人来源核验。公共目标若已存在歌曲，只记录本人去重标签，不重复增歌、不移动。歌曲确认在有效公共云端歌单且本人标签记录成功，才显示点歌成功；同一成员重复点歌不累计次数。
- 添加读回失败不提前新增标签。歌曲已确认在公共歌单但标签提交失败时，分别反馈云端歌曲已存在与标签未完成，不假报整项成功。
- 标签失败由服务端尝试补记，只补标签、不再次增歌。补记前重新确认公共歌曲有效存在、原成员资格、房主授权及公共目标绑定仍有效；个人来源点歌另须核对原个人来源归属与绑定仍有效，直接搜索点歌不检查个人绑定。歌曲已移除或相关权限、绑定已撤销时终止补记，不恢复已清除标签、成员或旧绑定。
- 快照更新、公共歌曲移除后的标签清理和标签提交须保持本地一致，旧读取结果不得覆盖较新快照或新绑定；外部调用不能与本地提交伪装成同一事务。

#### 操作持久化、补查与防重

- 接受提交后由服务端保存最小恢复记录，关页或重启不等于取消，不提供成员取消任务或提交后回滚入口，不形成导入历史。未完成记录至少足以识别操作、原账号、目标及目标绑定版本、发出状态、待确认歌曲与逐项进度；公共点歌须能区分直接搜索或个人来源，只有个人来源点歌需要原个人来源归属及绑定信息。不能只留无法区分未发与可能已发的笼统状态。
- 请求发出前持久化意图及原目标版本，执行权须唯一；已发或可能已发且未确认的写请求，重启后先读取判定，不自动重发。结果应用前重新核对账号、操作涉及的绑定及成员资格，直接搜索点歌不以个人绑定为条件，具体事务、版本和锁实现由架构票确定。
- 首次同步失败后最多自动补查三轮，约在失败后 5 秒、30 秒、2 分钟调度，仍受账号限流；不是精确时间承诺，不采用等待绕开竞态。未确认则保留待确认并停止自动请求，手动刷新或原账号重新授权可触发新一轮只读确认。搜索失败不适用这套补查。
- 每次确认提交使用唯一操作标识；同标识同内容返回原状态，同标识不同内容拒绝，不产生新的写入。完成后清除歌曲输入等恢复数据，最小防重复记录保留 24 小时，不提供历史列表；过期标识拒绝，不能作为新操作重放。
- 未解决恢复或清理任务不因满 24 小时删除。权限撤销后立即禁止查看原操作，清除成员业务信息，仅保留必要云端清理信息，不保留离开档案、昵称、快照或歌曲导入历史。
- 普通歌曲增删或标签任务长期未明时，管理员核对原账号、目标当前状态和请求记录后，可终结为“结果未能确认”并解除阻塞。此状态不宣称原写入失败、不撤销云端效果、不自动补写；后续须重读当前状态并作为新操作明确提交。创建未知、专用歌单删除未知不能按此规则直接丢弃。

#### 创建命名与自动绑定

- 新建公共歌单名称为 `songroom-<房间名>-公共`，室友专用个人歌单名称为 `songroom-<房间名>-<成员昵称>`，不加入随机标记。房主绑定已有歌单不改名，房间或昵称后续变化不自动修改云端名称。
- 名称与日期不是身份或删除资格。正常创建成功取得具体云端歌单 ID 后立即自动绑定有效目标，无需房主再次确认，也不再按名称寻找一份歌单替代返回 ID。
- 创建响应丢失、ID 未知时暂停，不按同名中最新日期猜测、不自动再建，交管理员核查，不要求房主在正常流程人工认领。管理员须结合原账号、创建意图、创建前后清单、创建者及具体 ID 核查，证据不足不自动关联或删除，仍保留最小核查信息。
- 创建前记录意图，已获 ID 而本地关联未完成时可恢复关联，但须检查原成员、房间和绑定仍有效；已离开或删房则只处理相应专用资源清理，不恢复业务关联。更换网易云账号遵守保留旧账号云端歌单的既有决议，不能借恢复自动删除。

#### 授权与生命周期隔离

- 成员撤销、删房或操作涉及的歌单换绑立即停止该操作尚未发出的步骤，本地权限、业务数据与标签清理依生命周期规则执行；个人来源绑定撤销仅影响从该来源发起的操作，不停止直接搜索点歌。在途请求可能继续作用于旧云端目标，不能声称已从网易云撤回。
- 返回结果不得写入新网易云账号、新歌单绑定、重新加入后的成员或恢复已清除业务数据。旧授权响应尤其不能覆盖新授权凭据；共享目标的其他仍有效绑定不因某一房间解除绑定而被破坏。
- 退出授权或确认失效时暂停全部受影响自建房间任务。原网易云账号重新授权后核对身份、成员、操作涉及的绑定与目标，先查明已发请求；确认安全后自动继续已提交操作中尚未发步骤，无需成员重新提交。个人来源点歌继续前须核验当前归属、绑定与歌曲仍在，直接搜索点歌不读取个人歌单；未确认的目标仍阻塞，已撤销的资格不恢复。
- 换账号不以新授权核验或执行旧账号任务，不迁移歌曲，不恢复旧配置。风控暂停须人工明确恢复，不靠定时探测继续写入；服务端重启也不能绕过暂停、确认与权限核验。

#### 专用歌单清理

- 本地权限和业务数据立即清除，云端失败不阻止本地生命周期完成。清理记录仅保留完成原账号具体专用歌单删除所需的最小信息，不作用于已有或收藏歌单、其他房间共用目标、新成员新建歌单，也不保存离开成员档案。
- 执行前核对原账号、具体 ID、点歌台专用创建来源与删除资格。收到明确业务成功响应即完成清理，正常路径不强制再做身份、完整清单、详情三重核验；不能只看 HTTP `200`。
- 删除尚未发出时，原账号恢复授权后自动继续。删除已发但结果未知时只读补查，不自动重发；须使用同账号完整清单和有效目标状态区分已删、仍存活与读取失败，不能要求详情必然 `404`，不能将任意 `502` 当成功，不能将删除墓碑的旧歌曲当存活目标。
- 未知删除长期无法查明则交管理员，保留最小清理任务。管理员确认原目标仍存活且仍应清理后，可明确授权一次新的删除尝试，不把旧未知请求伪装成失败，不自动盲目重放。
- 上游明确拒绝删除时提示房主在原账号官方客户端处理，服务端核验完成后终结；未完成前保留最小任务，不因本地成员已清除而丢弃，不使用新绑定账号处理。读取失败、身份不匹配、证据矛盾或暂时无权不能假报清理完成。

#### 依赖隔离与验收门槛

- 首版固定 NeteaseCloudMusicApiEnhanced `4.40.1`、源码基线 `a8c781fd64faab17fedfd46e0615a2609307f163`。每次调用独立进程，显式传入该账号凭据、隔离设备及会话状态并使用独立临时目录，移除隐式全局凭据来源；不采用未经验证的多账号共享长期进程。
- 移除或禁用歌曲增删模块特定错误路径的内部重复写入，并核查底层其他写请求重试。禁止未知写入重放必须覆盖依赖内部，业务层无重试并不足够；具体改动与封装由架构票确定，不保留旧重复写入兼容路径。
- 既有独立进程、小量账号与客户端共存实验不是生产隔离、负载、自然过期或改动后行为验收。后续正式部署须测试账号隔离、完整读取、风控分类、调度公平性、限流及依赖重试边界；真实调用仍先确认本人授权和专用测试范围。
- 验收须覆盖同账号多房间共用目标、不同账号并行不串凭据、短队列满额拒绝、长任务让出执行机会、未明目标不阻塞其他歌单，以及开页不持续轮询、失败不清空快照或标签。
- 验收须覆盖逐首部分成功与未知暂停、HTTP 成功但业务失败、写后同步失败、个人来源已变化或读取失败时停止该来源点歌、直接搜索点歌在无个人绑定或个人来源失效/待确认时仍可进行，以及已有公共歌曲仅补标签。两种点歌方式均须覆盖成员或公共目标撤销；个人来源点歌另覆盖原来源归属及绑定撤销，直接搜索点歌不得因此停止。
- 验收须覆盖请求发出前后与本地提交前后的崩溃、重复标识与内容冲突、24 小时防重过期拒绝、旧结果晚到、两种点歌方式重新授权后按各自涉及的绑定自动继续未发步骤，以及管理员终结未知普通写入不宣称失败、不自动补写。
- 验收须覆盖同名创建不猜最新日期、已获 ID 未关联的恢复、创建未知的管理员核查、清理业务成功直接完成、墓碑详情仍返回旧歌曲、补查错误不假报成功、未知删除需明确人工授权新尝试，以及成员离开后只留最小清理信息。
