# 确定多房间安全、部署与运维边界

Type: grilling
Label: wayfinder:grilling
Status: open
Blocked by: 01, 02, 04, 05

## Question

统一账号、多房间角色及用户级网易云凭据复用下，如何设计服务端鉴权、跨站防护、密码与令牌恢复、邀请码管理、凭据加密、日志脱敏、资源配额和滥用限制？部署、持久化、备份、密钥管理和故障恢复如何保证账号与房间隔离，尤其防止把操作者授权误用于其他房主房间，或允许调用任意歌单与上游接口？需确定与首版规模相称的具体边界，不引入匿名身份兼容层。

## Comments

### 既有安全调查入口

旧[公网房间与网易云授权安全决策](../../dorm-song-request/issues/06-decide-public-room-and-auth-security.md#解决评论最终安全规则已确认) 可提供凭据不进浏览器/URL/日志、泄露威胁模型及上游风险的输入，但单一部署房主密码、匿名成员恢复和房间独立授权不适用于新模型；旧有效期也须在账号登录语义下复核，不能让会话失效删除成员身份。

用户级授权与多房间复用的确认输入见[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#已确认输入用户级网易云绑定与授权复用)。服务端必须先验证当前账号在目标房间的权限，再使用该房间房主的授权，不能由浏览器任意指定凭据来源或歌单。

### 歌单归属、只读来源与清理资格

依据[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)，服务端须区分房间内归属、云端编辑权限与点歌台创建来源，明确绑定校验和删除资格，防止把已有、收藏或其他房间共用的个人歌单当成可删除的专用歌单。只读收藏可作为归属成员的点歌来源，不授予原歌单维护权；共享绑定不扩展房间成员权限。

本票须明确成员彻底清理与最小云端清理任务在日志、备份和恢复中的数据边界，不能用保留离开成员档案代替任务所需的最小信息。建房前有效授权与所选账号的校验仍在服务端执行，不依赖前端禁用按钮。

### 并发恢复决议的运维承接

以[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md#解决评论并发同步与恢复规则已确认)为权威输入，本票须决定全站并行与任务总量、等待授权或人工处理任务的存储配额、告警与数据保留，不把已有账号短队列参数当作完整防滥用边界。

须明确管理员核查创建未知、终结普通未知写入、授权新的专用删除尝试和人工恢复风控暂停的权限、审计与操作手册，以及房主在原账号客户端手工清理后的核验流程。不能把未知当失败重放、丢弃未完成清理任务、依赖同名最新日期猜删除目标，或用新绑定账号处理旧任务；这些产品边界不在本票重开。
