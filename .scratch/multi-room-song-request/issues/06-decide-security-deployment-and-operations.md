# 确定多房间安全、部署与运维边界

Type: grilling
Label: wayfinder:grilling
Status: open
Blocked by: 01, 02, 04, 05

## Question

统一账号、多房间角色及用户级网易云凭据复用下，如何设计服务端鉴权、跨站防护、密码与令牌恢复、邀请码管理、凭据加密、日志脱敏、资源配额和滥用限制？部署、持久化、备份、密钥管理和故障恢复如何保证账号与房间隔离，尤其防止把操作者授权误用于其他房主房间，或允许调用任意歌单与上游接口？需确定与首版规模相称的具体边界，不引入匿名身份兼容层。

## Comments

### 既有安全调查入口

旧[公网房间与网易云授权安全决策](../../dorm-song-request/issues/06-decide-public-room-and-auth-security.md#解决评论最终安全规则已确认) 可提供凭据不进浏览器/URL/日志、泄露威胁模型及上游风险的输入，但单一部署房主密码、匿名成员恢复和房间独立授权不适用于新模型；旧有效期也须在账号登录语义下复核，不能让会话失效删除成员身份。

用户级授权与多房间复用的确认输入见[确定账号、房间与邀请关系](01-decide-account-room-and-invitations.md#已确认输入用户级网易云绑定与授权复用)。服务端必须先验证当前账号在目标房间的权限，再使用该房间房主的授权，不能由浏览器任意指定凭据来源或歌单。
