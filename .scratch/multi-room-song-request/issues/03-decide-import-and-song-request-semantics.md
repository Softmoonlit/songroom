# 确定文本导入与公共点歌语义

Type: grilling
Label: wayfinder:grilling, resolved
Status: resolved
Assignee: Codex
Blocked by: 02

## Question

成员以一行一个歌名批量导入自己可维护的个人歌单时，如何解析、搜索和确认候选，处理同名/不同版本、未找到、重复歌曲、超额输入及部分成功？成员直接从搜索结果，或从自己的可维护、只读个人歌单逐首向公共歌单点歌时，来源校验、已有歌曲、点歌人标签和失败结果如何处理？需选择批次规模和验收语义，不改变云端原生写入后的顺序，不把文本输入行顺序默认当成歌单排序要求。

## Comments

### 已确认顺序模型与接口证据

用户明确要求：操作网易云添加接口后，同步真实歌单及其顺序即可；点歌台不另定首尾落位，不主动置顶或重排已有歌曲。导入个人歌单不自动写入公共歌单，个人歌单到公共歌单是逐首点歌，源歌单不被修改。

[验证点歌歌单写入语义](../../dorm-song-request/issues/03-verify-playlist-write-semantics.md) 是既有实测入口，包含单首新增、批量新增反序、重复添加及规模证据。接口原生行为不等于所有官方客户端界面行为，也不能把旧原型的完整排序步骤当成新模型仍需执行的操作。

### 早期来源与权限边界（已由后续确认修订）

以[确定公共与个人歌单权限及生命周期](02-decide-playlist-permissions-and-lifecycle.md#解决评论歌单权限与生命周期规则已确认)为约束，本票须分别覆盖可维护个人歌单的添加与导入、只读收藏个人歌单的选歌，以及公共歌单未创建时的结果反馈；不能提供对收藏源的写入，也不能开放从别人的个人歌单或搜索结果直接写公共歌单。搜索结果用于维护自己可写的个人歌单，公共点歌来源仍限于自己的个人歌单。

### 第一轮输入：输入格式、歌曲去重与结果语义

- 用户基本同意每个非空行对应一条搜索输入，补充使用 `歌名 - 歌手` 格式。是否兼容仅歌名输入、分隔符处理及无效行处理尚待明确，不把此前完整搜索词建议直接视为最终解析规则。
- 用户指出百首导入若有八十首候选，逐首确认工作量过大。自动匹配、整体预览及需要人工处理的范围尚待决定；不将默认选择首候选或自动导入视为已获同意。
- 用户同意仅按网易云歌曲 ID 去重，不按歌名或歌手合并；不同 ID 可同时保留，多行选中相同 ID 只提交一次，个人歌单已包含的 ID 显示已存在，不重排。
- 用户同意公共歌单已有歌曲仍可点歌并增加当前成员的点歌人标签；同一成员重复点歌不累计次数，仅反馈已点过。云端原本已有而尚无标签的歌曲也允许记录标签，标签不代表最早添加者，不形成票数排名。
- 用户同意导入允许部分成功，不回滚已添加歌曲；逐项区分已加入、已存在、明确失败和结果待确认，仅对确知失败项提供再次尝试，不能将超时直接认定为失败或笼统宣称全部成功。
- 既有写入实测中重复添加已有歌曲曾返回 `502`，读回仍只有一个副本；一次添加二百首成功不证明最大批次、满额或部分失败行为。结果分类须依据读回证据，不能只凭接口状态码；具体恢复机制由[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md)决定。
- 本票仍在讨论中，未记录解决评论或关闭。

### 第二轮输入：格式与百行上限确认，自动匹配方案待简化

- 用户同意支持 `歌名 - 歌手`，也允许仅填歌名；以两侧带空格的 ` - ` 作为分隔符，不拆解普通连字符。格式不完整或无法明确拆分的行标记出来，不猜测。
- 用户同意每次最多一百个非空输入行，重复行也计入输入上限，选歌后再按歌曲 ID 去重。超额时提示拆分，本次不启动搜索，不静默截断；产品输入上限不等于上游单次写入数量。
- 用户要求导入功能尽量简单、稳定，避免复杂匹配规则造成大量缺陷；尚未同意此前提出的歌名与歌手唯一吻合自动选择方案。后续讨论须优先明确简单默认候选方案及用户接受的误选边界，不能继续把严格匹配当成既定要求。
- 接口调查显示 [搜索文档](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/public/docs/home.md)、[搜索模块](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/search.js)与[更全搜索模块](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/cloudsearch.js)提供关键词、单曲类型、返回数量与分页参数；现有文档、模块及[类型声明](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/interface.d.ts)没有定义可直接依赖的匹配置信度或精确匹配标记，也不承诺第一条一定准确。此边界不代表上游私有响应绝无额外字段。
- 搜索结果具体展示字段、批量请求与异常行为仍须通过后续验证核对；本轮未调用真实账号接口，也不把文档调查当作多账号或批量导入实测。

### 第三轮确认：简单默认候选与原地改选

- 用户同意简化导入流程：每行搜索后默认选中第一条候选，不做智能匹配、置信度打分或唯一吻合判断，不承诺默认候选一定是所需歌手或版本。
- 展示原输入及默认歌曲信息，用户无需逐首确认。跳过就是取消该行勾选；未找到的行不自动替换为相似歌曲，不阻止其他已选行导入。
- 用户确认改选在当前导入预览页面的弹窗内完成，不跳转到独立搜索页面。各行共用一个弹窗，显示这行已经取得的其他候选，单选后确认只更新该行，取消保留原选择，不改变其他行及页面位置。
- 首版改选弹窗不增加重新搜索功能；搜索词写错时返回修改输入。候选数量与修改输入后的重新搜索范围尚待确定。
- 预览中的选择、改选或跳过均不写入网易云，最后一次点击导入已选歌曲才提交。弹窗本身不增加搜索或写入请求；批量搜索、写入失败和读回恢复与界面选歌分开处理。
- 用户要求继续 grilling，候选数量、异常输入与搜索失败、预览离开后的保留范围及陈旧点歌来源仍待进一步确认。

### 第四轮确认：五候选、异常行、草稿与点歌来源

- 用户同意每行只取前五个候选，默认选第一条，改选弹窗不提供分页或加载更多。候选都不合适时修改输入后重新搜索或跳过，不承诺所需版本一定在前五个中。
- 格式错误、未找到和搜索失败分别标记，不默认勾选，不阻止其他已选行导入；本轮搜索结束后才提交。不能把搜索请求失败显示为未找到。
- 首版不做单行自动重试；处理剩余项时，用户修改或复制这些输入，再发起一轮搜索。
- 首版不保存尚未提交的导入草稿，不提供跨设备草稿或导入历史。刷新或离开导入流程前提示未提交选择会丢失；重新进入后重新输入与搜索。
- 已提交写入不因关页被视为取消，不回滚已加入歌曲。结果确认与恢复由[确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md)决定，不能把不保存草稿误解为无需协调已提交操作。
- 公共点歌前核对当前归属成员的个人歌单，确认目标歌曲仍在才放行；已不在则反馈来源已变化并刷新个人歌单，不继续添加公共歌曲。来源读取失败时不能凭旧快照放行，可写与只读个人歌单采用相同规则。
- 此核对不承诺阻止网易云客户端在核对后继续修改；并发、成员或绑定撤销及在途结果隔离由后续并发票据决定。
- 剩余待确认项为成功与标签判定、入单与播放能力的区别，以及提交后取消的产品边界。

### 第五轮确认：成功证据、播放边界与提交后不取消

- 用户同意只有确认歌曲在公共云端歌单中且本人的标签记录成功后，才显示点歌成功。公共歌曲原本已存在时不重复添加、不移动，仅记录本人去重标签；仍须遵守当前个人歌单来源核对。
- 添加返回成功但读回失败时，显示结果待确认，不提前显示成功或新增标签。歌曲已确认在公共歌单但标签记录失败时，分别反馈歌曲已在公共歌单与标签未完成，不假报整项成功；具体恢复机制由后续并发票据决定。
- 用户同意导入成功只表示歌曲已确认在云端歌单中，不保证可播放。首版不额外做试听或播放权限筛选；上游明确拒绝添加时反馈失败，VIP、版权及客户端播放能力由网易云账号和官方客户端决定。
- 用户同意不提供提交后的取消任务功能；提交前可以改选、取消勾选或放弃预览，提交后展示处理进度和逐项结果，不通过删歌回滚成功部分，也不把关闭页面当成取消。
- 授权失效、成员权限撤销、目标绑定变化等必须停止或隔离操作的情况，仍遵守生命周期决议，具体调度及在途结果由后续并发票据决定。
- 本票主要决策已收敛，等待用户对整票汇总的共同理解确认；暂不记录解决评论或关闭。

### 解决评论：文本导入与公共点歌规则已确认

用户已明确确认整票汇总。本评论为本票最终决议，取代上述讨论中与之冲突的建议和阶段性输入；尤其不采用此前的严格匹配或唯一吻合方案。公共点歌来源已按下方[确认修订](#确认修订搜索直接公共点歌与个人歌单可选)更新，个人歌单为可选来源。本票只形成决策，不开发正式应用。

#### 输入与适用范围

- 文本导入只写入归属成员自己的可维护个人歌单，不支持收藏歌单导入，不自动写入公共歌单。可维护性、归属与授权仍须服务端校验，不能只依赖界面控件。
- 每个非空行对应一条搜索输入，支持 `歌名 - 歌手`，也允许仅填歌名；去掉首尾空白、忽略空行。以两侧带空格的 ` - ` 作为分隔符，不拆普通连字符，格式不完整或无法明确拆分时标记错误，不猜测。
- 每次最多一百个非空输入行，重复行也计数，选歌后才按歌曲 ID 去重。超额整批提示拆分，不启动搜索，不静默截断；不把产品上限当作上游单次写入上限。

#### 搜索与候选选择

- 每行只取前五个单曲候选，默认选第一条，不做智能匹配、置信度评分或唯一吻合判断，不承诺默认候选一定是用户所需歌手或版本。
- 预览展示原输入与选中歌曲的歌名、歌手、专辑，不要求逐首确认。取消行勾选即跳过，不写入该行歌曲。
- 改选在当前预览页面的共用弹窗中完成，各行共用一个弹窗，不跳转独立页面。显示该行已经获取的候选，单选后确定只更新该行；取消保留原选择，不改变其他行选择和页面滚动位置。
- 弹窗不分页、不加载更多、不重新搜索，也不写入云端。候选不合适或搜索词错误时返回修改输入，重新搜索或跳过。
- 格式错误、未找到和搜索失败分别标记，不默认勾选，不阻止其他已选行导入；本轮搜索结束后才能提交，不能把网络失败显示为未找到。
- 首版不做单行自动重试，处理剩余项时修改或复制对应输入，再发起一轮搜索。具体搜索限流、调度及旧结果隔离由后续并发票据决定。

#### 提交、去重与云端结果

- 预览、改选和取消勾选均不写入网易云，最后一次点击导入已选歌曲才提交。
- 仅按网易云歌曲 ID 去重，不按歌名或歌手合并。不同 ID 可同时保留，选中多行相同 ID 只提交一次，目标个人歌单已包含的歌曲显示已存在，不重排。
- 允许部分成功，不回滚已添加歌曲。逐项反馈已加入、已存在、明确失败和结果待确认，不笼统宣称全部成功；明确失败可再次尝试，超时或读回失败不能直接视为失败并重放。
- 写后读取云端实际歌曲集合与顺序，云端为唯一权威。不以输入行顺序另定歌单排序，不主动置顶或重排已有歌曲，也不以本地待选列表冒充云端成功快照。
- 入单成功只表示歌曲已确认在云端歌单中，不保证可以播放。首版不额外做试听或播放权限筛选，上游明确拒绝添加时反馈失败；VIP、版权与实际播放能力由网易云账号及官方客户端决定。

#### 草稿、离开与取消

- 导入是“我的歌单”下的二级状态。尚未提交的输入、预览选择及页面位置只保留在当前浏览器内存中；在同一房间的四个一级页面之间切换时保留这些状态且不弹确认，返回导入后继续原位置。不把这种房间内暂存做成持久、跨设备或跨房间草稿，也不提供导入历史。
- 刷新、关闭页面、明确放弃、返回房间列表或准备进入另一房间前，均提示尚未提交内容将丢失；确认后丢弃输入、预览选择及位置。切换到同一房间的其他一级页面不属于离开导入流程。
- 提交前可改选、取消勾选或放弃预览；提交时仍须重新校验成员权限、个人歌单归属与有效绑定。提交后可切换页面，服务端操作继续，不提供取消任务；展示处理进度和逐项结果，不通过删歌撤销已成功部分，不将切页或关闭页面当作取消。
- 不保存草稿不等于无需协调已提交操作。授权失效、成员撤销、绑定变化、关页后的结果确认和恢复，仍遵守生命周期决议，并由后续并发票据确定机制；不得恢复已撤销成员的数据或把旧结果写入新绑定。
- 房间一级导航、滚动保留、弹窗遮罩和响应式布局以[07 的响应式四入口反馈](07-prototype-multi-room-web-experience.md#真人反馈确认响应式四入口房间导航)为准；本票只定义导入状态的保留、丢弃与提交边界。

#### 公共点歌来源与标签

- 房间成员可直接搜索并逐首向公共歌单点歌，无需配置个人歌单，不自动创建或写入个人歌单。个人歌单是可选的存歌、文本导入及点歌来源；文本导入仍只写入自己的可维护个人歌单，不提供公共文本导入。
- 也可从自己的个人歌单逐首向公共歌单点歌，可维护与只读收藏来源均允许；不能从别人的个人歌单点歌，不修改源个人歌单。
- 从个人歌单点歌时，操作前核对当前归属、有效绑定及歌曲仍在。已不在时反馈来源已变化并刷新来源，不继续写公共歌单；来源读取失败时不能凭旧快照放行。直接搜索点歌不读取或写入个人歌单，不要求个人绑定，也不被个人来源失效或待确认阻塞。
- 两条路径均校验当前成员资格、目标房间房主授权、公共歌单绑定及可用状态、目标冲突与歌曲 ID，并遵守既有队列及单成员未完成写操作的受理限制；使用目标房间房主的授权，不能凭客户端参数绕过权限或指定任意云端目标。
- 个人来源核对不代表可以阻止官方客户端随后继续修改，不承诺上游原子条件写入；核对后的外部并发边界由后续并发票据明确。
- 没有公共歌单时不能点歌，不影响已有可维护个人歌单的导入。授权失效或受影响歌单不可用时按生命周期决议暂停操作，不用旧快照冒充当前可用来源。
- 公共歌曲已存在时不重复添加、不移动，只记录本人去重标签；包括云端原本已有而尚无人通过点歌台点过的歌曲。同一成员重复点歌反馈已点过，不累计次数或形成票数排名，标签不表示最早添加者。
- 只有歌曲确认在公共云端歌单且本人标签记录成功，才显示点歌成功。添加返回成功但读回失败时显示结果待确认，不提前新增标签或显示成功；已有标签的生命周期仍遵守领域规则，不因一次失败自动清除。
- 歌曲已确认在公共歌单但标签记录失败时，分别反馈歌曲已在公共歌单与标签未完成，不假报整项成功。具体恢复与幂等边界由后续并发票据决定。

#### 验收与后续证据

- 输入一百行时允许搜索，第一百零一个非空行使整批超额提示；重复行不绕过上限，空行不计数。
- 一百行中正常匹配的行默认选第一条，无需逐首点击；异常行保持未选，其他行可一起提交。改选确定、取消与跳过均不会提前写云端。
- 不同 ID 的同名歌曲可以共存，多个选中行指向同一 ID 只提交一次；已存在歌曲不增加副本或主动重排。混合结果按实际证据区分成功、已存在、失败与待确认。
- 未配置个人歌单的房主和室友均可搜索点歌；搜索、候选查看与取消不写云端，只有逐首点击点歌才提交，不自动建单或将歌曲存入个人歌单。
- 从个人歌单点歌时，源已删去歌曲或读取失败不放行；个人来源失效或待确认不阻止独立的搜索点歌。两条路径在公共歌曲已存在时都可记录新成员标签，同一成员不重复计数。读回或标签失败不得假报点歌成功。
- 导入不自动写公共歌单、不保证输入顺序落位或客户端可播放。同一房间切换一级页面时，未提交输入、预览选择和位置仍在当前浏览器内存中且不弹确认；刷新、关页、明确放弃、返回房间列表或进入另一房间前提示，确认后丢弃，不跨设备或跨房间恢复。
- 提交时重新校验权限、归属与绑定；提交后切页或关闭页面不取消服务端操作，也不撤销已成功写入。
- [验证授权复用、账号隔离与官方客户端共存](04-verify-auth-reuse-and-client-coexistence.md)：核对实际搜索候选字段、候选数量参数、收藏来源读取及目标写入、重复添加与混合批次的读回证据；真实账号操作仍须先确认测试范围，不将已有二百首成功当成所有批次与失败场景的保证。
- [确定多歌单并发、同步与失败恢复](05-decide-concurrency-sync-and-recovery.md)：决定搜索限流、写入批次、部分成功证据、超时与待确认恢复、标签幂等、源核对后的外部修改、关页后的已提交操作及权限或绑定变化隔离。
- [原型验证多房间与双类型歌单体验](07-prototype-multi-room-web-experience.md)：验证五候选默认选择、共用改选弹窗、异常行非阻塞、一次提交、草稿离开提示，以及待确认和标签未完成的手机与桌面呈现，不扩展为复杂匹配系统。
- [确定多房间安全、部署与运维边界](06-decide-security-deployment-and-operations.md)：落实输入总大小、字符串长度、请求频率、账号与归属校验等防滥用边界；不把百行上限误当成完整安全限制。
- [确定多房间 MVP 架构与完整规格](08-decide-mvp-architecture-and-spec.md)：以本评论为导入与公共点歌的规格来源，结合后续证据落实验收，不恢复旧排序逻辑。新增边界由现有票据承接，不另建重复决策票。

### 确认修订：搜索直接公共点歌与个人歌单可选

用户在[交互原型反馈](07-prototype-multi-room-web-experience.md)指出，不能直接搜索公共点歌会迫使用户先配置、入单再点歌，并明确确认调整为：公共歌单页面允许直接搜索并逐首点歌，个人歌单作为可选的存歌、批量导入和点歌来源。

本修订取代早期“公共点歌只能来自自己的个人歌单、禁止搜索结果直接点歌”的限制；上方解决评论已同步修正。当前个人来源核对只适用于从个人歌单点歌，两条路径均遵守房间权限、房主授权、公共目标冲突、云端确认与本人去重标签规则。其他已确认的导入、排序、操作受理与队列限制、失败恢复及生命周期规则继续适用；原型调整不代表正式上游接口或部署已通过验收。
