# 随机点歌选择成员

## 状态与范围

需求已逐项确认，用户已确认采用一张无阻塞的完整纵向工单，功能尚未实现。实现与验收见 [01：随机点歌按所选成员生成预览](issues/01-select-random-source-members.md)。

房主发起随机点歌时，在现有弹窗中选择参与抽选的成员，歌曲来源限制在所选成员的个人歌单，不再固定使用全体成员来源。

本规格替代旧规格中“固定读取全部已配置成员来源”及“打开弹窗立即抽选”的行为，其余抽选、预览确认和替换规则以 [随机点歌抽选与批量替换调整](../random-selection-and-order/spec.md) 为现行基础。

## 成员选择

- 成员使用 checkbox 多选，可选成员包含当前房间的房主与室友，以房间昵称显示。
- 每次打开弹窗默认不勾选任何成员，不记住上次选择。
- 未创建个人歌单的成员仍显示，但禁用勾选并注明“未创建歌单”。
- 已创建个人歌单的成员允许勾选，不因已有快照显示为空而禁用；实际读取为空时贡献 0 首，名额只在其他选中成员之间重分配。
- 提供“全选”checkbox，只作用于可选成员。
- 没有选中成员时，“全选”未选中；部分选中时显示半选状态；全部可选成员选中时显示选中状态。
- 未选中或半选状态下点击“全选”会选中全部可选成员；全选状态下再次点击会取消全部勾选。
- 未选任何成员时禁用“生成预览”，提示“请至少选择一位成员”。

## 弹窗流程

1. 打开现有“随机点歌”弹窗，先选择成员及总首数。
2. 首数仍为 5、10、15、20 首，默认 10 首，表示本次合计首数。
3. 点击“生成预览”后才读取所选来源并抽歌；打开弹窗、勾选成员或修改首数均不自动生成预览。
4. 预览继续展示具体歌曲、来源成员、成员贡献数量、实际总数和旧歌替换范围。
5. 预览后可返回调整成员或首数，再重新生成；调整后须使用新预览，不能确认调整前的旧歌曲组合。“重新抽选”继续使用本次选择的成员与首数。
6. 最终确认后才开始替换公共歌单；取消、关闭或返回调整均不写入云端歌曲。

## 来源边界与异常

- 服务端接收明确的所选成员集合，验证非空、属于当前房间并已配置个人歌单；不接受客户端绕过成员及来源限制。
- 仅刷新并抽选所选成员的个人歌单，不读取未选成员来源，不将未选成员用于补足首数。
- 任一所选来源读取失败、目标失效或无法证明读取完整时，整次预览失败并提示来源问题；不自动跳过，不将失败当作空歌单，不凭旧快照放行。未选成员的来源故障不影响本次抽选。
- 所选成员的个人歌单全部为空时，提示“所选成员的歌单暂无歌曲”，不能继续确认或清空公共歌单。
- 所选来源候选不足时沿用现有规则展示实际可抽首数，不自动扩大成员范围。
- 生成期间所选成员离开或个人歌单失效时，拒绝本次预览，要求重新选择或生成，不静默缩减来源范围。
- 预览保存本次所选来源及歌曲归属；确认时只对这些来源沿用现有成员、绑定代次、快照及歌曲有效性校验。所选来源失效则要求重新生成预览；未选成员的变化不影响本次来源校验。
- 公共歌单变化、预览过期、授权及冲突检查继续沿用现有规则；来源选择不允许绕过这些检查。

## 沿用的抽选与执行规则

- 多成员之间尽量均分，余数随机分配，成员内部随机抽选，不区分新旧歌曲。
- 按歌曲 ID 去重并处理交叉候选归属，候选不足仅在所选成员之间重分配；选好后整组洗牌。
- 最终来源成员决定本次点歌人标签，不给未选成员新增来源标签。
- 确认服务端固定预览，客户端不能替换歌曲或来源；执行中不重新抽歌或更换来源。
- 沿用批量清空后批量添加、读回确认、未知写只读确认、部分成功反馈、标签生命周期及恢复机制。
- 本次调整不授予房主编辑他人个人歌单或任意逐首取歌的权限。

## 实现定位

- `apps/songroom/src/client/RandomReplacementDialog.tsx`：当前打开弹窗会立即生成默认预览，需要改为先选择再生成，并接入当前成员及个人歌单配置状态。
- `apps/songroom/src/shared/public-playlist-contracts.ts`：预览命令目前只有首数，需要明确所选成员集合；不保留缺省为全成员的旧请求路径。
- `apps/songroom/src/operations/public-random-preview.ts`：目前刷新全部已配置成员来源，需要在读取前校验并限制为所选成员，确认依据也仅保存所选来源。
- `apps/songroom/src/operations/public-playlist-replacement.ts`：复用现有固定预览确认、持久操作及执行来源校验，不增加平行的换歌机制。

## 讨论记录

- 第一轮：用户确认采用 checkbox 多选，并通过同一个“全选”checkbox 完成全选与取消全选。
- 第二轮：用户确认每次默认都不选；同意在同一弹窗先选择再生成预览、预览后可返回调整；同意未建歌单成员禁用、已建空歌单成员贡献 0 首并将名额分给其他选中成员。
- 第三轮：用户确认半选状态下点击补齐为全选、无选择时禁用生成；确认所选来源任一读取失败整次失败、全部为空不可换歌；确认沿用所选来源有效性校验，未选成员变化不影响本次抽选。需求已收敛，尚未修改功能代码。
