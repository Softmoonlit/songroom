# 成员自主绑定个人歌单与多账号去中心化点歌规范

Status: ready-for-agent

## Problem Statement

在此前的“房主统一分配已有歌单”（ADR-0005）设计中，系统要求房间内所有成员（包含室友）的点歌来源必须全部来自房主本人的网易云音乐账号（由房主分配其收藏、自建或我喜欢歌单），室友无法使用自己网易云账号里的歌单。这种中心化模式带来了显著的体验痛点与权责倒挂：
1. **室友自身音乐资产无法利用**：室友在自己的网易云客户端中积累了大量红心歌曲（「我喜欢的音乐」）与自建歌单，但在点歌台内却只能从房主挑选的歌单中选歌，无法表达个性化音乐偏好；
2. **房主承担不必要的管理负担**：房主需要逐一了解每位室友的听歌口味，在成员列表中为每位室友逐个打开弹窗分配和更换歌单，操作繁琐且权责过载；
3. **隐私边界模糊与界面层级冗余**：原系统在成员列表中提供“查看歌单”功能，导致室友被分配的歌单曲目可被全房间无差别翻看；且角色标签与昵称割裂分散在卡片两侧，视觉流混乱；
4. **单账号集中风险与扩展受阻**：所有歌单读取和点歌来源全部压在房主一个网易云账号上，无法体现宿舍内“每个人带自己的歌来共同建歌单”的去中心化协作本质。

## Solution

彻底废除由房主代为统一分配歌单的中心化模型，建立**各成员在全局账号设置中独立绑定网易云账号、并在房间内自主绑定本人歌单作为只读点歌来源**的去中心化架构（ADR-0006）：
1. **多账号去中心化自选**：每位成员（房主与室友）可在全局「账号设置」中独立授权绑定自己的网易云账号；进入房间后，在「我的歌单」中自主挑选本人账号下的「我喜欢的音乐」、自建歌单（含私密）或收藏歌单作为点歌来源；
2. **全员一致的极简交互**：所有成员在「我的歌单」使用相同的操作流：未绑定网易云时引导前往全局账号设置页扫码；未绑定歌单时点击「绑定歌单」挑选；已绑定后仅提供「手动刷新」与「更换歌单」，不设冗余的独立解绑按钮，换歌直接通过「更换歌单」覆盖；
3. **公共歌单权威与写入权收敛**：公共歌单依然由房主主动新建并由房主网易云账号托管；无论成员逐首点歌还是房主发起随机点歌，公共歌单的最终云端增删写入均严格由房主授权执行；各成员自身授权仅用于拉取本人个人歌单快照与候选；
4. **严格一致性双账号校验**：逐首点歌时，严格核验点歌人自身网易云授权有效（active）且房主授权有效；若点歌人授权失效，拒绝点歌并提示先重新授权，不凭旧快照放行；
5. **随机选歌公平抽选与异常置灰**：房主发起随机点歌时，弹窗中未绑定歌单或授权失效的成员自动置灰禁用并标注具体原因；抽选时使用各自成员凭证并发拉取最新曲目，任一选定来源不可读则整次抽选报错，不凭旧快照掩盖异常；
6. **房间成员列表隐私保护与布局重排**：彻底移除“分配歌单”、“更换歌单”、“解除分配”以及“查看歌单”按钮，他人曲目不对房间全量公开以保护室友私密曲库；角色胶囊（`房主` / `室友`）左移至头像和昵称旁边紧凑聚合，右侧仅对房主保留针对其他室友的“移除成员”管理操作；
7. **无害化生命周期**：成员更换歌单、退出房间或被移出房间时，仅清除本地关联与该成员在公共歌单上的点歌人标签；成员用户级的网易云授权和云端歌单完全保留，不生成任何云端清理任务。

## User Stories

1. 作为普通室友，当我尚未在全局账号设置中绑定网易云账号时，在房间内打开「我的歌单」页面，我希望看到清晰的引导文案提示我先完成网易云授权，并提供「前往账号设置」的按钮，以便我一键跳转到设置页进行扫码。
2. 作为普通室友，在全局「账号设置」中完成网易云扫码授权后返回房间，在「我的歌单」页面，我希望看到“尚未绑定个人歌单”的提示和「绑定歌单」按钮，以便我开始挑选本房间的点歌来源。
3. 作为普通室友，在「我的歌单」点击「绑定歌单」按钮时，我希望唤起歌单选择弹窗，浏览我本人网易云账号下的候选歌单，包括「我喜欢的音乐」、自建歌单（含私密）以及收藏的歌单，以便挑选我心仪的歌单。
4. 作为普通室友，在歌单选择弹窗中，我希望清晰看到每个候选歌单的封面、名称、歌曲数量以及来源分类标签（如我喜欢、自建、收藏），以便精准区分不同歌单。
5. 作为普通室友，在歌单选择弹窗中选中某个歌单并点击确认后，我希望系统迅速建立绑定并拉取曲目快照，「我的歌单」页面立即展示出该歌单的歌曲列表，以便我能够即刻浏览。
6. 作为普通室友，当我的个人歌单绑定成功后，在「我的歌单」顶部，我希望看到歌单名称、曲目总数以及最新同步时间，以便掌握当前来源的状态。
7. 作为普通室友，在「我的歌单」歌曲列表中，我希望可以通过搜索输入框输入歌名或歌手名快速过滤曲目，以便在较长歌单中迅速找到想听的歌。
8. 作为普通室友，在「我的歌单」中找到想听的歌曲后，我希望可以点击单曲旁的「点歌」按钮将歌曲添加到公共歌单，并在点歌台该歌曲旁边正确打上我本人的昵称标签，以便大家知道是我点的歌。
9. 作为普通室友，当我点击「点歌」按钮时，如果我的网易云授权凭据失效（如 Cookie 过期变为 waitingAuthorization），我希望系统拦截本次点歌并给出明确提示“网易云授权已失效，请重新授权”，以便我及时恢复授权而不产生无效操作。
10. 作为普通室友，当我点击「点歌」按钮时，如果房主的网易云授权失效或公共歌单写入遇到冲突，我希望系统据实返回错误提示，以便我知晓当前公共歌单暂时不可写。
11. 作为普通室友，当我在手机网易云客户端中向自己的歌单添加或删除了歌曲后，在点歌台「我的歌单」页面点击「手动刷新」按钮，我希望系统使用我的网易云授权重新同步最新的云端歌曲列表，以便把新歌同步到点歌台。
12. 作为普通室友，当我想把点歌来源换成另一份歌单时，在「我的歌单」顶部点击「更换歌单」按钮唤起选择弹窗，选定新歌单后直接覆盖原绑定，无需先进行繁琐的解绑操作，以便流畅地切换歌单。
13. 作为普通室友，在「我的歌单」页面中，我希望页面只有「手动刷新」和「更换歌单」两个动作，不出现冗余的“解除绑定”按钮，保持操作链路的极简。
14. 作为普通室友，在打开「房间成员」列表时，我希望只看到成员的基础信息，其他室友无法通过“查看歌单”功能窥探我绑定的私密歌单曲目，以便充分保护我的个人听歌隐私。
15. 作为普通室友，在「房间成员」列表中，我希望我的头像、昵称、“（我）”标记以及“室友”角色胶囊整齐紧凑地排列在左侧，以便一眼看清成员的身份信息。
16. 作为普通室友，当我主动退出房间或被房主移出房间时，我希望系统只清理我在该房间的绑定关系与点歌人标签，我的网易云账号授权及云端歌单毫发无损，以便保障我的个人平台资产安全。
17. 作为房主，在创建房间并进入房间后，在「我的歌单」页面，我希望享有与室友完全一致的自选体验，自主挑选并绑定我本人网易云账号下的「我喜欢」、自建或收藏歌单。
18. 作为房主，在「我的歌单」页面中，我同样可以通过「手动刷新」拉取最新歌曲快照，或通过「更换歌单」随时调整本人的点歌来源。
19. 作为房主，在打开「房间成员」列表时，我希望列表中不再出现任何针对室友的“分配歌单”、“更换歌单”、“解除分配”或“查看歌单”按钮，由室友全权管理自己的歌单，以便大幅减轻我的管理负担。
20. 作为房主，在「房间成员」列表中，我希望左侧紧凑展示成员昵称与角色标签，右侧仅对除我之外的室友展示“移除成员”按钮，以便保持房间治理能力的简洁专注。
21. 作为房主，在点歌台公共歌单页面点击「随机点歌」按钮时，我希望弹窗中列出房间内的全体成员，以便我选择参与本轮抽选的成员名单。
22. 作为房主，在「随机点歌」弹窗中，对于已经绑定歌单且网易云授权处于 active 状态的成员，复选框默认勾选或允许自主勾选，以便将其歌单纳入抽选候选池。
23. 作为房主，在「随机点歌」弹窗中，对于尚未绑定个人歌单的成员，复选框自动置灰禁用并标注“未绑定歌单”状态标签，以便我直观得知该成员不能参与抽选的原因。
24. 作为房主，在「随机点歌」弹窗中，对于虽然绑定了歌单但其自身网易云授权失效（如 waitingAuthorization）的成员，复选框自动置灰禁用并标注“授权失效”状态标签，以便提醒我该成员需要重新扫码。
25. 作为房主，在「随机点歌」弹窗中勾选好有效成员并确认首数后点击生成预览，我希望系统使用各个成员自身的网易云凭据并发读取最新歌单，尽量均分抽选、去重并整组洗牌，以便形成公平且多样化的推荐歌单。
26. 作为房主，在生成随机选歌预览的过程中，如果任一被勾选成员的歌单临时读取失败（如上游网络错误或受到频控），我希望系统严格中断并提示“成员 XX 个人歌单读取失败”，绝不使用过期的旧快照伪造结果，以便保证公共歌单的准确性。
27. 作为房主，在确认随机点歌替换后，系统使用我（房主）的网易云授权在云端对公共歌单执行批量清空并批量添加新歌曲，并按各歌曲最终归属的来源成员正确写入点歌人标签，以便公共歌单展示最新曲目。
28. 作为房主，当我主动删除房间时，我希望系统只在网易云清理点歌台公共专用歌单，所有成员（包括我和室友）绑定的个人歌单仅在本地数据库解除关联，绝不触碰任何人在网易云的自建或收藏资产。
29. 作为系统与运维人员，在上游调度器（UpstreamScheduler）处理各成员个人歌单只读刷新任务时，我希望任务按各成员各自的真实网易云 accountId 分离队列，避免多个成员同时选歌时互相阻塞。

## Implementation Decisions

### 1. 领域模型与权限边界（彻底去中心化）
- **个人歌单定义与归属**：
  - 废除“房主统一分配来源歌单”规则，全面执行 ADR-0006；
  - 个人歌单彻底归属于各成员自己的网易云音乐平台账号；
  - 个人歌单在点歌台内严格只读，不提供网页加歌、删歌、排序或全网搜索功能；
  - 允许多名成员绑定同一个公开歌单 ID，但各自记录在各成员本人的 binding 记录中。
- **公共歌单权威与写操作归属**：
  - 公共歌单依然在房主已绑定的网易云账号下新建与托管，生命周期随房间绑定；
  - 逐首点歌（`requestPublicSong`）与随机批量替换（`replacePublicPlaylist`）的公共云端写操作严格使用**房主的网易云授权**；
  - 成员自身的网易云授权仅用于拉取本人歌单候选及曲目快照。
- **权限与管理权解耦**：
  - 彻底移除房主为室友分配、更换或解绑歌单的权限；
  - 成员（包括房主与室友）仅能操作自己当前房间的个人歌单绑定；
  - 移除所有成员查看他人歌单详情的入口及后端接口。

### 2. 数据表结构与实体映射
- **`personal_playlist_binding` 字段语义**：
  - `roomId`: 所属房间 ID；
  - `memberId`: 绑定的房间成员 ID；
  - `accountId`: **绑定该歌单的成员本人的真实网易云账号 ID**（不再固定等于房主的 accountId）；
  - `playlistId`: 网易云歌单 ID；
  - `name`: 歌单名称；
  - `generation`: 绑定代际；
  - 保持 `uniqueIndex("personal_playlist_binding_room_member_unique").on(table.roomId, table.memberId)` 约束不变（每名成员在每个房间至多绑定一份歌单）。
- **快照读模型 `playlistSnapshot` 与 `playlistTrack`**：
  - 主键仍为 `(accountId, playlistId)`；
  - 快照存储的 `accountId` 为拥有/绑定该歌单的成员的真实账号 ID；
  - 多名成员若绑定了相同 accountId 下的相同歌单，共享快照数据；若不同成员绑定了不同账号下的歌单，按各自 `accountId` 隔离快照。

### 3. API 契约与 HTTP 路由变更
- **重构候选列表接口**：
  - `GET /api/rooms/:roomId/personal-playlist/candidates`：
    - 开放给房间内任意成员（房主与室友）；
    - 服务端从请求上下文获取当前登录用户 `userId`，查找其自身的 `neteaseAuthorization`；
    - 若调用者未授权网易云或授权状态不是 `active`，抛出 `409 NETEASE_AUTH_REQUIRED`；
    - 使用调用者自身凭证分页拉取其网易云歌单，返回 `favoritePlaylistCandidatesView`（分类为 `liked`、`created`、`favorite`），排除已被用作点歌台公共歌单的目标。
- **新增自主绑定接口，替代原房主代分配接口**：
  - `POST /api/rooms/:roomId/personal-playlist/bind`（替代原 `POST /api/rooms/:roomId/members/:memberId/personal-playlist/assign`）：
    - 开放给房间内任意成员；
    - 请求体：`{ playlistId: string }`；
    - 业务逻辑：校验调用者自身具有 active 状态的网易云授权；校验候选合法性；在当前房间将 `memberId` 绑定到该歌单，并把 `binding.accountId` 记录为调用者本人的网易云 `accountId`；拉取快照并返回最新的 `PersonalPlaylistView`。
- **废除无用接口**：
  - 废除 `POST /api/rooms/:roomId/members/:memberId/personal-playlist/unassign`（不再支持解绑，换歌直接通过 `/bind` 覆盖）；
  - 废除 `GET /api/rooms/:roomId/members/:memberId/personal-playlist` 与 `POST .../refresh`（他人无权查看成员个人歌单）。
- **逐首点歌接口双授权校验（`POST /api/rooms/:roomId/public-song-requests`）**：
  - 校验点歌成员在当前房间已绑定个人歌单；
  - 校验点歌成员自身的网易云授权处于 `active` 状态（且未发生未授权换号）；
  - 校验房主的网易云授权处于 `active` 状态且未暂停；
  - 校验歌曲存在于点歌人绑定的个人歌单快照中；
  - 成功入队后，调度器使用**房主凭据**向公共歌单添加歌曲，并在点歌台记录点歌人标签（点歌成员当前昵称）。
- **随机点歌成员状态与抽选接口（`GET .../random-preview` & `POST .../random-replacement`）**：
  - 随机点歌可选成员列表中，为每个成员附带字段：
    - `hasPersonalPlaylist: boolean`
    - `authStatus: "active" | "waitingAuthorization" | "unbound"`
    - `canSelect: boolean`（当且仅当 `hasPersonalPlaylist === true && authStatus === "active"` 时为 true）
    - `disabledReason: "NO_PLAYLIST" | "AUTH_INVALID" | null`
  - 抽选执行时：
    - 拒绝包含 `canSelect === false` 的成员；
    - 并发拉取各勾选成员的歌单快照，每个成员使用其自身的网易云凭据；
    - 任一成员歌单读取返回错误，整次预览抛出 502 并明确指出失败成员与错误原因，绝不凭旧快照放行；
    - 替换公共歌单时，由房主网易云凭据执行批量清空与添加。

### 4. 前端界面交互与组件调整
- **「我的歌单」页面（`PersonalPlaylistPane`）**：
  - **状态 A（未绑定网易云）**：显示卡片提示“你尚未绑定网易云账号，无法配置点歌来源”，附带按钮「前往账号设置」（链接至 `/account`）；
  - **状态 B（已绑定网易云，但本房间未绑定歌单）**：显示居中空状态提示“尚未绑定个人歌单”，附带主要按钮「绑定歌单」；
  - **状态 C（已绑定歌单）**：顶部展示歌单名称、曲目数量、最后同步时间，右上角展示操作按钮：「手动刷新」与「更换歌单」；主体区域展示搜索框与歌曲快照列表，单曲右侧展示「点歌」按钮；
  - 彻底移除任何“解除分配/解除绑定”按钮。
- **歌单选择抽屉（`BindPersonalPlaylistDialog`，重构自 `AssignFavoritePlaylistDialog`）**：
  - 供当前成员绑定或更换歌单时使用；
  - 调用 `GET /api/rooms/:roomId/personal-playlist/candidates` 获取本人的网易云歌单并分组展示（我喜欢 / 自建 / 收藏）；
  - 选中后调用 `POST /api/rooms/:roomId/personal-playlist/bind` 完成绑定并关闭弹窗。
- **「房间成员」列表（`RoomWorkspace` 成员标签页）**：
  - **左侧信息区**：头像 + 昵称 + （我）标记 + 角色胶囊（`房主` / `室友`），横向聚合在一起；
  - **右侧操作区**：
    - 彻底删除“分配歌单”、“更换歌单”、“解除分配”以及“查看歌单”按钮；
    - 普通室友行右侧为空；
    - 房主查看其他室友行时，仅保留原有“移除成员”红色次要按钮；
  - 彻底删除 `MemberPersonalPlaylistSection` 下钻歌单详情视图。
- **「随机点歌」弹窗（`RandomReplacementDialog`）**：
  - 渲染房间成员勾选列表；
  - 若成员 `canSelect === false`，复选框处于 `disabled` 状态，成员名字右侧展示标签：
    - 未绑定歌单：展示浅灰色标签 `未绑定歌单`；
    - 授权失效：展示琥珀色警示标签 `授权失效`；
  - 仅允许勾选 `canSelect === true` 的成员。

## Testing Decisions

### 1. 测试标准与质量要求
- **外部行为优先**：测试必须通过外部 HTTP 接口或最终状态进行断言，严禁断言内部临时私有状态；
- **全链路真实协同**：在测试中使用真实的 SQLite 数据库（内存模式）、真实的 `createApp` Fastify 实例以及受控的 `ScriptedNeteaseAdapter`，验证网易云 Cookie 隔离、代际校验、调度锁与鉴权拦截；
- **零向后兼容包袱**：删除已废弃的旧代分配与查看他人歌单测试，不保留任何旧逻辑兼容测试。

### 2. 核心测试模块与切面（Seams）
本特性的核心验证切面为 **HTTP 集成层（HTTP Seam: `apps/songroom/src/http/*.test.ts`）** 与 **核心操作领域层（Operations Seam: `apps/songroom/src/operations/*.test.ts`）**：
- **切面 1：成员自选与候选隔离测试（`personal-playlists.test.ts`）**：
  - 室友未绑定网易云调用候选与绑定接口，断言返回 `409 NETEASE_AUTH_REQUIRED`；
  - 室友已绑定网易云，调用 `candidates` 接口，断言只能读取到室友自身账号下的歌单，不泄露房主账号的歌单；
  - 室友绑定自建私密歌单与我喜欢，断言成功创建 `personal_playlist_binding`，且 `accountId` 为室友自身账号 ID；
  - 室友调用 `refresh`，断言使用室友的 Cookie 向网易云发起 `playlistDetail` 调用；
  - 室友调用 `bind` 传入新歌单 ID，断言平滑覆盖原绑定；
  - 验证废弃的 `unassign` 与查看他人歌单路由返回 404。
- **切面 2：逐首点歌双授权与标签测试（`public-song-requests-http.test.ts`）**：
  - 室友从自身歌单点歌到公共歌单，断言网易云写请求由**房主凭据**发出，公共歌单歌曲读回后点歌人标签为**室友昵称**；
  - 当室友自身网易云授权转为 `waitingAuthorization` 时，发起点歌，断言被拦截报错并要求先恢复授权；
  - 当房主网易云授权失效时，发起点歌，断言返回房主未授权错误。
- **切面 3：随机点歌多账号并发抽选测试（`public-random-preview.test.ts` 与 `public-playlist-replacement.test.ts`）**：
  - 房间包含 3 名成员（各自绑定独立网易云账号），房主发起随机点歌抽选，断言系统并发以各成员自身 Cookie 读取各自歌单；
  - 模拟其中一名成员的网易云歌单读取失败（如上游网络错误），断言整次抽选严格失败报错，不降级为旧快照；
  - 模拟某成员未绑定歌单或授权为 `waitingAuthorization`，断言随机抽选候选列表中该成员标记为 `canSelect: false` 并附带正确原因；
  - 抽选成功后确认替换，断言以房主账号批量清空并批量写入公共歌单，各歌曲标签分别对应其来源成员。
- **切面 4：生命周期清理测试（`member-leave-removal.test.ts` & `room-deletion.test.ts`）**：
  - 成员退出或被移出房间，断言删除本地 `personal_playlist_binding`，该成员用户级 `netease_authorization` 完全保留，网易云端零网络写调用；
  - 房主删除房间，断言清理公共歌单专用云端资源，全员个人歌单仅本地解绑，网易云端零个人歌单写调用。

## Out of Scope

- 在点歌台网页内向个人歌单添加、删除、排序歌曲或搜索全网歌曲；
- 成员直接向公共歌单全网搜索歌曲点歌（必须来自已绑定的个人歌单）；
- 跨音乐平台混合点歌（当前基线固定为网易云音乐）；
- 第三方客户端播放器远程控制或实时播放队列同步；
- 在成员列表中跨成员直接浏览他人个人歌单的完整曲目。
