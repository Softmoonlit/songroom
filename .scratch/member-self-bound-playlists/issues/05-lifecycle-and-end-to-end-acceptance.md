# 05: 成员退出/删房生命周期与多账号端到端全链路验收

**What to build:** 验证无害化生命周期与端到端稳定性：成员退出或被移出房间时级联删除该成员在房间内的个人歌单绑定与公共歌单标签，该成员用户级网易云授权保留，云端歌单零写调用；房主删除房间时清理公共专用歌单，全员个人歌单仅本地解除绑定，绝不删除云端歌单或取消收藏；成员在账号设置更换网易云账号时各房间旧绑定自动失效；运行全量单元测试、HTTP 集成测试与端到端浏览器测试，完成全功能回归闭环。

**Blocked by:** 02: 房间成员列表布局重排与他人歌单隐私收敛, 04: 随机点歌多成员独立账号抽选与异常置灰

**Status:** resolved

## Acceptance criteria

- [x] 成员主动退出房间或被房主移出房间：级联删除该成员在当前房间的 `personal_playlist_binding` 行及对应的点歌人标签；成员在点歌台用户级的网易云授权保留，云端个人歌单零网络写调用
- [x] 房主删除房间：清理点歌台公共专用网易云歌单，房间内所有成员（房主与室友）的个人歌单仅在本地数据库解除绑定，绝不删除任何人的云端歌单或取消收藏
- [x] 成员在全局账号设置中主动更换网易云账号：该成员在所加入房间的个人歌单绑定自动失效，进入房间恢复为“未绑定歌单”状态
- [x] 废弃接口与废弃数据表逻辑完全清理，无残留死代码或兼容垫片
- [x] 运行全量单元测试与 HTTP 集成测试全部通过，无回归失败
- [x] 端到端回归验证：多成员登录、各自绑定网易云账号、进入同一房间自选绑定不同歌单、逐首点歌与随机点歌完整闭环跑通

## Comments

### 实现与验收说明
1. **生命周期与云端只读保护**：
   - 成员主动退出（`Rooms.leaveRoom`）或被房主移出（`Rooms.removeMember`）时，事务中触发 `terminatePersonalPlaylistsInTx`，仅在本地清理该成员在该房间的 `personal_playlist_binding`、其本人点歌人标签以及无其他引用的快照与曲目行；该成员的全局网易云授权保留，网易云端个人歌单零网络写调用（不删歌单、不取消收藏）；
   - 房主解散房间（`Rooms.deleteRoom`）时，清理公共专用歌单清理任务，房间内全员的个人歌单仅在本地事务中解绑，绝不删除任何成员的云端个人歌单或取消收藏；
   - 成员在全局账号设置中更换账号（`Binding.switchAccount`）时，原授权账号 ID 变更，各房间个人歌单读模型与列表权限判定识别到账号不匹配，自动将原绑定视为失效，房间「我的歌单」恢复为空白待绑定状态。
2. **端到端测试更新与收敛**：
   - 彻底清理已过时的 ADR 0005 房主分配歌单 E2E 测试文件（`owner-assigned-favorite-playlists.spec.ts`、`owner-personal-playlist.spec.ts`）；
   - 新增 `apps/songroom/tests/e2e/member-self-bound-playlists.spec.ts`，覆盖 ADR 0006 完整用户路径：
     - 未授权网易云引导前往账号设置授权；
     - 未绑定歌单引导与弹窗拉取个人候选（自建、我喜欢、已收藏）；
     - 勾选自选歌单并成功绑定；
     - 绑定后展示曲目、手动刷新快照与更换歌单；
     - 逐首点播歌曲到公共歌单；
     - 房间成员列表紧凑展示且无隐私泄露；
     - Axe 无障碍审查全量合规。
   - 同步修正既有 E2E 测试中的 mock 契约（`rooms.spec.ts`、`member-identity.spec.ts`、`member-leave-removal.spec.ts`、`destructive-dialogs.spec.ts`、`random-replacement.spec.ts`），淘汰旧下钻查看他人歌单遗留断言，全部断言对齐 ADR 0006。
3. **验证结果**：
   - 单元与集成测试：全库 51 个测试套件，574 个测试全部通过；
   - 端到端测试：Playwright 18 个测试套件，192 个测试用例全部通过（包含桌面、平板与移动端各视口无横向溢出及 Axe 无障碍审查）；
   - 生产环境构建：Vite、TypeScript 编译完全通过，零错误零警告。
