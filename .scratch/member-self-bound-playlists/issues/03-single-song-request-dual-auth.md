# 03: 逐首点歌双授权核验与点歌人标签贯通

**What to build:** 成员在「我的歌单」中点击单曲「点歌」到公共歌单：服务端执行双授权强核验，校验点歌成员自身网易云授权 active 且匹配绑定账号，校验房主授权 active；若点歌成员自身授权失效，明确拦截并提示先重新授权，不凭旧快照放行；校验通过后，上游调度器使用房主凭据向公共歌单添加歌曲，并在点歌台公共歌单中打上点歌成员当前昵称的点歌人标签；覆盖完整 HTTP 链路与异常回滚测试。

**Blocked by:** 01: 成员端自选候选与自主绑定点歌来源

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 成员在「我的歌单」点击单曲「点歌」，调用 `POST /api/rooms/:roomId/public-song-requests`
- [ ] 来源校验：要求点歌成员在当前房间已绑定个人歌单，且歌曲存在于该个人歌单快照中
- [ ] 点歌人授权校验：校验点歌成员自身的网易云授权状态为 `active` 且 `accountId` 与 `personal_playlist_binding.accountId` 严格一致；若点歌成员授权为 `waitingAuthorization` 或凭据失效，返回明确的授权失效错误，拦截点歌
- [ ] 房主授权校验：校验房主网易云授权状态为 `active`；若房主授权失效，返回房主未授权错误
- [ ] 调度写入执行：上游调度器使用**房主网易云凭据**调用网易云 `playlist_tracks` 接口将歌曲添加到公共歌单
- [ ] 点歌人标签：公共歌单读回核验成功后，在点歌台将该歌曲打上点歌成员当前昵称的去重标签（`requesterTag`）
- [ ] 若歌曲已在公共歌单中，不重复添加云端条目，正确追加或保留点歌成员的点歌人标签
- [ ] 编写并通过 HTTP 路由与操作层集成测试，覆盖双授权通过、点歌人授权失效、房主授权失效与异常回滚分支
