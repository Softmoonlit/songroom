# 03：搜索歌曲显式操作驱动与已添加防重标记

**What to build:** 
1. 贯彻操作显式驱动原则：用户切换到搜索页在未点击搜索前保持完全静默，不自动读取个人歌单或提前展示提示横幅，仅在点击搜索发起查询时按需读取；
2. 搜索结果候选歌曲添加状态完善：已在个人歌单中的歌曲显示为 `[✓] 已添加` 并禁用（阻止重复添加）；点击添加中显示 `[🔄] 添加中…`；再次搜索相同歌曲持续显示 `[✓] 已添加`。

**Blocked by:** 无，规格与核心原则已确认。

Status: ready-for-agent

规格：[随机点歌弹窗 Checkbox 居左与全站深色模式规格](../spec.md) 第四节。

## 验收清单

- [ ] 切换至“搜索歌曲”Tab 时保持完全静默：不自动触发个人歌单网络查询，未搜索前不展示“未配置个人歌单”提示横幅，页面保持纯净输入状态。
- [ ] 仅在用户输入关键词并点击“搜索”按钮（或回车）发起搜索时，才作为显式操作触发个人歌单数据读取。
- [ ] 搜索结果列表中，候选歌曲状态明确：
  - 未在个人歌单：按钮展示 `[+] 添加到我的歌单`（可点击）；
  - 点击添加在途：按钮展示 `[🔄] 添加中…`（禁用）；
  - 已在个人歌单：按钮展示 `[✓] 已添加`（柔和次级弱色样式，彻底禁用 `disabled`，阻止重复添加，无障碍 `aria-label` 声明已在歌单中）。
- [ ] 再次搜索该歌曲或搜索包含该歌曲的新关键词时，结果中持续正确展示 `[✓] 已添加` 并保持禁用。
- [ ] 若用户尚未配置个人歌单，在搜索发起并得出结果后，添加按钮提示尚未配置个人歌单或引导创建。
- [ ] 移动端窄屏（320px/390px）与桌面端（1440px）适配良好，按钮文字切换不引发布局跳动，Axe-core 无障碍合规。
- [ ] 单元测试与 Playwright E2E 回归测试全部通过。

## Comments

- 需求访谈：用户提出“搜索歌曲并点击添加到我的歌单后，该按钮就该显示为已添加了，再搜索该歌曲，也应继续显示已添加，让用户不用重复添加”；同时用户强调“不希望切换到搜索页不点击搜索按钮就去自动读内存，用户不做操作就自动执行读内存或其他流程是不太合适的”。该指导思想已正式沉淀至 `AGENTS.md` 核心原则第 5 条。
