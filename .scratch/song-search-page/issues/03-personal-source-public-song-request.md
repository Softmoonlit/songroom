# 03：实现个人来源公共点歌并退役直接点歌

Status: ready-for-agent

## 目标

依据[规格](../spec.md)，使公共逐首点歌必须从当前成员自己的个人歌单发起，复用已有公共写入与点歌人标签机制。

## 依赖

- [01：统一成员专用个人歌单与生命周期](01-unify-dedicated-personal-playlists.md)。

## 验收清单

- [ ] 提供自己的个人歌单逐首公共点歌命令；成员详情中他人个人歌单维持只读，房主不能绕过归属限制。
- [ ] 受理与执行重新校验成员、授权、原个人绑定及代次、归属、公共目标、冲突与单未完成写操作。
- [ ] 操作中实时完整读取来源并确认歌曲 ID 仍在，来源变化/读取失败停止，不凭旧快照放行。
- [ ] 公共已有歌曲只记本人去重标签、不重复写入或重排；缺少歌曲时复用单次加歌、完整读回及未知恢复机制。
- [ ] 歌曲与标签分别反馈，标签补记重新校验必要来源条件且不重发加歌；来源、公共写入及标签错误不能混淆。
- [ ] 退役不需要个人来源的直接公共点歌命令/契约，不保留兼容或回退路径；处理已受理旧操作的原目标确认而不把它们重新执行。
- [ ] 公共歌单未创建或冲突时说明原因，不能影响独立个人搜索存歌；房主随机换歌仍使用自身业务意图。
- [ ] 自动化覆盖来源归属越权、来源移除/读取失败/换代、公共去重、多成员标签、未知写入、标签补记与撤权竞态。

## 关联旧工单

承接旧 MVP 28 的个人来源核验与点歌；取消其中保留直接搜索公共点歌及收藏来源的要求。

## Comments

- 规划：用户确认公共点歌改从个人歌单发起；接口端必须同步落实，不能只移除页面入口。
- 当前仅建立工单，无实现提交、测试或部署结果。
