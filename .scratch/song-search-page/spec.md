# 搜索歌曲独立页面与个人歌单点歌

Status: need-review

## 目标与决议范围

房间以“搜索歌曲”为默认页面，成员先搜索并存入自己的个人歌单，再从“我的歌单”逐首点歌到公共歌单。房主与室友统一使用本房间专用、可写的个人歌单。

本规格记录用户逐轮确认的产品规则，用户已确认按工单实施；工单 01 已完成实现、自动化验证与审查，其他工单尚未实施。领域边界见 [ADR-0002](../../docs/adr/0002-dedicated-personal-playlists-and-song-request-flow.md)。

本规格覆盖旧规格中以下规则：房间默认显示公共歌单、直接搜索公共点歌、房主绑定已有自建或收藏歌单、房主个人歌单跨房间共用。旧工单中的实现与验证记录保留为历史事实，不代表新规则已实现。

## 页面与导航

- 房间一级导航顺序为：搜索歌曲、公共歌单、我的歌单、房间成员、房间设置。
- 每次进入房间默认显示“搜索歌曲”，不记忆上次选择的标签页。
- 将公共歌单页原全网搜索点歌入口迁到搜索页，移除原入口与抽屉；公共歌单内针对现有歌曲的搜索筛选保留。
- 搜索页提供关键词输入、候选歌曲列表及加载更多，候选歌曲可逐首“添加”到自己的个人歌单。
- 搜索页没有公共歌单目标选项。点击添加直接提交，不弹出目标选择或添加确认弹窗。
- 同一房间内切换一级标签页时，保留搜索关键词、结果列表与浏览位置。刷新、离开房间或进入另一房间后清空，不保存长期搜索记录。
- 未配置个人歌单时仍允许搜索及浏览结果，但禁用添加，说明尚未配置，并提供“前往我的歌单”入口；不自动创建。
- 搜索使用当前房间房主的有效音乐平台授权，不要求已创建公共歌单或个人歌单；授权不可用时说明原因，沿用既有房主授权恢复流程。
- 添加成功后留在搜索页，保留搜索现场，轻提示“已加入个人歌单”。歌曲已存在时提示“已在个人歌单”，不重复添加或改变顺序。
- 操作明确展示排队、处理中、结果待确认、明确失败与成功，只有云端存在已确认才提示添加完成；切页或关闭页面不取消已受理操作。

## 统一专用个人歌单

- 所有成员，包括房主，都只能在“我的歌单”按需主动创建个人歌单，不在建房、获批加入或搜索时自动创建。
- 创建始终使用本房间房主当前有效音乐平台授权；室友不需要绑定自己的音乐平台账号。
- 每个成员在每个房间最多一份专用个人歌单。房主在不同房间分别创建，不跨房间或成员共用；不与公共歌单共用目标。
- 云端名称统一采用 `songroom-<房间名>-<成员昵称>`，包含房主；后续改房间名或昵称不自动改云端名。
- 不再提供绑定已有自建、收藏或任意公开歌单的入口和业务命令，不保留旧绑定方式的兼容路径。
- 个人歌单只有归属成员可维护、逐首点歌；其他成员仅可从成员详情查看。房主随机换歌仍可读取本房间全体成员来源，但不能编辑他人歌单或任意逐首取歌。
- 不因本功能新增个人歌单任意更换、主动删除重建、批量删歌或文本导入能力；云端目标失效后的恢复沿用并调整既有专用创建机制。

## 个人存歌与公共点歌

- 个人添加按音乐平台歌曲 ID 去重；同名不同 ID 可共存，歌曲集合与顺序以云端完整读回为准。
- 搜索结果添加只写自己的个人歌单，不同时向公共歌单写入，也不新增公共点歌人标签。
- “我的歌单”中的歌曲提供逐首“点歌”操作，目标为当前房间公共歌单；未创建公共歌单时说明不可点歌的原因，个人搜索存歌仍可用。
- 公共点歌在受理及执行时核验当前成员、个人歌单归属、有效绑定及代次，并实时读取来源，证明选中歌曲仍在；来源读取失败不能凭旧快照放行。
- 公共歌单已有该歌曲时不重复写云端、不改变顺序，只记录本人去重点歌人标签；没有时逐首写入并完整读回。
- 歌曲存在与本人标签均确认后才报告点歌成功；云端已确认而标签未确认须分别反馈，标签补记不得重发加歌。
- 服务端公共逐首点歌必须携带并校验本人个人来源，移除不依赖个人来源的直接点歌业务路径，不能只隐藏客户端入口。
- 房主随机换歌继续使用既有独立业务意图，不借普通逐首点歌绕过个人来源归属检查。

## 生命周期与旧关联

- 室友退出或被移除时，立即撤销权限、删除该房间成员业务数据及个人快照引用，并为专用云端个人歌单留下最小清理任务；不影响公共歌曲和其他成员标签。
- 房主删除房间时，经既有二次确认，删除本地房间业务数据，并清理公共歌单及全部成员专用个人歌单，包含房主个人歌单；不影响其他房间。
- 删除确认分别展示已绑定及已获 ID 未关联的个人目标数量，以及尚未获得 ID 的在途创建数量；已知目标按真实账号和歌单 ID 去重。在途创建可能产生云端资源，晚到结果确认后继续清理，即使当前没有公共或已知个人目标，也须提示这项影响。
- 本地删除不等待云端完成。云端删除失败只保留原账号、具体目标及必要证据和恢复状态；不保留成员档案或歌曲快照。确认删除完成后移除清理任务，只保留必要的既有防重与管理审计事实。
- 清理使用创建资源的原房主真实音乐账号；不得混淆发起创建的成员账号与持有云端资源的房主账号，不得使用新账号清理旧目标。
- 原房主已有自建或收藏歌单只解除点歌台关联，保留网易云原歌单与收藏，不删除、不自动搬歌，也不继续作为本房间来源；房主主动新建专用个人歌单后使用新流程。
- 旧关联退役不得重置房间、成员、公共歌单或其他不相关数据。一次性退役方案和对在途操作的处置须在实现时可审查，不加入兼容层或歌曲迁移垫片；未经明确要求不修改实际部署数据。
- 歌单创建未知、已获 ID 尚未关联、成员撤权、房间删除及晚到响应沿用持久操作恢复规则，不按名称猜测目标或自动重建。

## 并发与恢复约束

- 复用现有持久操作、账号有界调度、每真实账号串行与全站并行限制，不新增独立调度器。
- 沿用每成员同房间最多一个未完成写操作、目标冲突检查、幂等键同内容返回原状态、不同内容拒绝。
- 添加及点歌受理、执行和确认阶段重新校验身份、授权、绑定代次及目标；旧操作不能写入新绑定。
- 可能已发送的写入只查询确认，不自动重发或回滚；终结后清除歌曲输入等恢复数据，保留既有最小防重记录。
- 退出、被移除或删房后，晚到结果只用于原目标必要确认或清理，不恢复成员、歌单绑定或业务快照。

## 规划时的代码核对与实现缺口

以下为规划时核对结果，各项当前完成状态见对应实现工单。

- 当前房间默认公共歌单，全网搜索位于公共页点歌抽屉，搜索后端要求公共绑定存在。
- 当前个人歌单只有配置与同步能力，尚无个人逐首添加和个人来源公共点歌；旧工单 26、28 不能作为已完成能力。
- 当前专用个人歌单创建仅允许室友，正常成员退出及删房未完整接入个人云端资源清理；本次统一专用模型必须补齐，不能只修改房主创建权限。
- 当前仓库不能证明生产已有何种绑定，本规格没有宣称旧关联已解除或云端资源已变更。

## 决议记录

- 第一轮：用户确认搜索只添加个人歌单，公共点歌从个人歌单发起；同意同房间切页保留搜索现场。
- 第二轮：用户确认直接添加而不弹窗、未配置时允许搜索并引导配置、成功后停留并轻提示；取消房主绑定已有自建或收藏歌单，统一主动创建。
- 第三轮：用户确认房主个人歌单逐房间独立并随删房清理；原有自建或收藏关联解除，保留云端歌单和收藏，不自动搬歌。
- 工单 01–04 全部实现、自动化验证与双轴审查已完成，各工单状态均已标记为 resolved。自动化测试全面覆盖端到端场景，真实云端写入和生产部署尚未执行。
