# 22: 交付第一期单机生产运行包

**What to build:** 让平台运营者可以在单台公网 VPS 上以受限系统身份初始化、迁移、自检、启动、停止和升级第一期 SongRoom，并由 Caddy 提供唯一可信公网入口。

**Blocked by:** 21/完成第一期安全负面矩阵

**Status:** ready-for-agent

- [ ] 生产使用 systemd 运行一个长期 Node.js 应用进程，不使用 Docker、多实例、独立 worker 服务、数据库租约或自动故障切换。
- [ ] 应用仅监听本机回环地址，Caddy 是唯一公网入口并提供浏览器默认信任的 HTTPS、精确 Origin、正确代理信任和自动证书续期。
- [ ] 持久数据、私有配置和运行临时数据位于彼此分离且权限受限的系统位置；数据库与密钥不在静态资源目录，应用系统用户只拥有必要写权限。
- [ ] 凭据主密钥和 Better Auth 签名密钥从稳定受限文件读取，不进入环境变量、命令行、仓库、数据库或日志；缺失、权限错误或解密失败时停止相关功能。
- [ ] 启动前自检数据库、schema、密钥权限、固定 vendor 哈希、生产补丁、唯一 HTTPS base URL 和必要配置；任何失败都阻止就绪而不自动建库或迁移。
- [ ] 显式初始化、离线迁移和只读检查命令依赖服务器权限但不能修改普通业务状态；升级流程保证应用与前后端原子发布。
- [ ] 应用监听成功后才启动唯一调度器，并在就绪后 5 秒工作点内推进可恢复任务；第二实例因端口冲突失败。
- [ ] 停机先拒绝新业务命令和上游派发，最多等待当前 25 秒子进程，总停机上限 35 秒；中断的发送步骤重启后只确认不重发。
- [ ] systemd 安全限制包含无新权限、只读系统区域和最小必要可写范围；结构化日志由 journald 限量保留且不另建敏感日志平台。
- [ ] 精简运维清单覆盖初始化、启停、升级检查、管理员初始化、账号恢复、异常处置、原账号手工清理、风控恢复、密钥缺失和数据库丢失。
