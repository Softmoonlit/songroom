# 09: 读取并刷新权威公共歌单快照

**What to build:** 让房间成员查看最近确认的公共歌单，并按需从网易云完整刷新真实歌曲集合与顺序，而不会把临时错误、截断列表或旧响应当作当前事实。

**Blocked by:** 07/安全创建公共歌单、08/有界且公平地执行上游操作

**Status:** resolved

- [x] 公共歌单页面先显示最近确认快照、真实顺序、最近成功同步时间和当前刷新状态；没有快照时显示首次同步状态而不伪装为空歌单。
- [x] 进入页面触发一次独立显式刷新，成员也可手动刷新；页面查询和后续 SSE 失效查询不再次触发上游读取，不形成持续轮询。
- [x] 同一真实账号与云端歌单 ID 使用唯一规范化歌单及共享快照；同目标并发刷新合并为一次调度工作，但房间权限仍独立。
- [x] 只有完整有效歌曲 ID 集合可生成单调快照版本并替换集合与顺序；默认截断列表、部分 tracks、旧绑定代次和旧读取均不能覆盖较新快照。
- [x] 读取失败保留最后快照和同步时间并明确标记未更新；读超时、502、解析错误或矛盾结果不能清空歌曲、解绑目标或报告刷新成功。
- [x] 有效完整读取按网易云实际集合在一个事务中替换歌曲与位置，不再存在的快照歌曲被移除；读取失败或不完整结果不改变任何歌曲或顺序。
- [x] 外部删除、重加或排序只按系统实际观察到的连续有效快照呈现，不推断两次同步之间未观察到的中间事件。
- [x] 歌曲列表使用固定的 TanStack Virtual 处理最多 10,000 首快照，保留稳定行高、键盘可达性和滚动位置，不因状态变化跳动布局。
- [x] 房间外用户、待审批者和已移除成员无法通过快照 ID、目标 ID 或刷新命令读取公共歌单；浏览器不能指定任意云端目标。
- [x] 完整应用与模块测试覆盖共享快照、并发合并、乱序响应、读取失败、部分列表、无轮询和 10,000 首替换性能工作点；点歌标签在同步中的生命周期由 ticket 10、确认目标失效与重新创建由 ticket 13 承接。

## Comments

### 实现提交
- 提交 `25a14cf`: `feat: 实现权威公共歌单快照同步与虚拟滚动`
- 数据库演进：新增 `0009_playlist_snapshot.sql`，定义规范化快照表 `playlist_snapshot`、有序快照曲目表 `playlist_track` 以及点歌人标签关联基础表 `requester_tag`，模式版本推进至 10。
- 上游协调与内存任务：`UpstreamScheduler` 新增 `executeMemoryTask`，使读歌单等内存刷新任务严格遵守全站最多 2 个上游并发、单网易云账号串行启动至少间隔 1 秒、风控暂停即时打断以及与持久操作按时间戳公平轮转机制。
- 权威快照服务：`PublicPlaylists` 接入 `playlistDetail` 操作，校验歌单未被删除 (`status === 0`) 以及歌曲详情与 ID 集合完整对应；单事务原子替换歌曲曲目，旧读取与失效代次无法覆盖新快照；同目标并发刷新自动合并为单个调度任务；读取失败保留最后成功快照与同步时间并标注 `lastRefreshError`。
- HTTP 端点：注册 `POST /api/rooms/:roomId/public-playlist/refresh`，只对房间成员开放，校验 Origin 同源，不接受客户端任意目标参数。
- 前端虚拟滚动界面：`PublicPlaylistPane` 集成 `@tanstack/react-virtual` 虚拟化渲染曲目列表（行高 64px 保证稳定无抖动，支持键盘导航与滚动位置恢复）；区分未完成首次同步 (`syncedAt === null`) 与已同步空歌单；进入页面触发一次显式刷新，普通页面查询或状态更新不产生轮询风暴。
