# 09: 读取并刷新权威公共歌单快照

**What to build:** 让房间成员查看最近确认的公共歌单，并按需从网易云完整刷新真实歌曲集合与顺序，而不会把临时错误、截断列表或旧响应当作当前事实。

**Blocked by:** 07/安全创建公共歌单、08/有界且公平地执行上游操作

**Status:** ready-for-agent

- [ ] 公共歌单页面先显示最近确认快照、真实顺序、最近成功同步时间和当前刷新状态；没有快照时显示首次同步状态而不伪装为空歌单。
- [ ] 进入页面触发一次独立显式刷新，成员也可手动刷新；页面查询和后续 SSE 失效查询不再次触发上游读取，不形成持续轮询。
- [ ] 同一真实账号与云端歌单 ID 使用唯一规范化歌单及共享快照；同目标并发刷新合并为一次调度工作，但房间权限仍独立。
- [ ] 只有完整有效歌曲 ID 集合可生成单调快照版本并替换集合与顺序；默认截断列表、部分 tracks、旧绑定代次和旧读取均不能覆盖较新快照。
- [ ] 读取失败保留最后快照和同步时间并明确标记未更新；读超时、502、解析错误或矛盾结果不能清空歌曲、解绑目标或报告刷新成功。
- [ ] 有效完整读取按网易云实际集合在一个事务中替换歌曲与位置，不再存在的快照歌曲被移除；读取失败或不完整结果不改变任何歌曲或顺序。
- [ ] 外部删除、重加或排序只按系统实际观察到的连续有效快照呈现，不推断两次同步之间未观察到的中间事件。
- [ ] 歌曲列表使用固定的 TanStack Virtual 处理最多 10,000 首快照，保留稳定行高、键盘可达性和滚动位置，不因状态变化跳动布局。
- [ ] 房间外用户、待审批者和已移除成员无法通过快照 ID、目标 ID 或刷新命令读取公共歌单；浏览器不能指定任意云端目标。
- [ ] 完整应用与模块测试覆盖共享快照、并发合并、乱序响应、读取失败、部分列表、无轮询和 10,000 首替换性能工作点；点歌标签在同步中的生命周期由 ticket 10、确认目标失效与重新创建由 ticket 13 承接。
