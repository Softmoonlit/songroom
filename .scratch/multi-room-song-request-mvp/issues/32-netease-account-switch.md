# 32: 破坏性更换网易云账号

**What to build:** 让用户在查看全部自建房间影响并二次确认后更换唯一的用户级网易云账号，保留房间关系但彻底隔离旧音乐配置、响应和未解决任务。

**Blocked by:** 12/处理公共歌单创建结果未知、15/退出授权并以同账号重新授权、24/绑定并查看房主个人歌单、25/创建并查看室友个人歌单、31/处理个人歌单失效与重配置

**Status:** ready-for-agent

- [ ] 新扫码流程仍绑定发起用户与会话，由服务端核实真实网易云账号并检查全站归属唯一性；浏览器不能声明账号身份。
- [ ] 扫码得到原真实账号时走同账号重新授权而非破坏性更换；确为新账号时展示全部自建房间、公共及个人绑定、共享引用、标签和未解决任务影响。
- [ ] 最终提交要求明确二次确认和当前聚合版本，影响范围变化时拒绝旧确认并要求重新查看。
- [ ] 更换后保留房间、成员、昵称、邀请和仍有效申请，清除全部自建房间的旧歌单绑定引用、只由其持有的快照引用及公共点歌人标签。
- [ ] 所有自建房间回到按需配置状态，不迁移歌曲、不自动创建歌单、不删除旧账号云端对象、不取消收藏，也不按名称认领目标。
- [ ] 用户作为室友加入的其他房间继续使用各自房主授权，其成员资格、页面与操作不受本次更换影响。
- [ ] 旧绑定尚未发的普通业务步骤停止；可能已发、创建未知和既存清理任务只保留原账号、原目标与原代次所需的最小恢复信息。
- [ ] 新账号凭据永远不能执行、确认或完成旧账号任务，旧响应也不能写入新配置、恢复旧快照、标签或绑定。
- [ ] 原真实账号只要仍有未解决最小任务就保留原点歌台用户归属，不能被另一个点歌台账号绑定或用于新用户清理。
- [ ] 多设备通过账号级 SSE 和重新查询一致看到切换结果，界面清楚区分当前新账号配置与原账号待处理事项。
- [ ] 自动化覆盖多自建房间、共享房主个人歌单、室友房间、在途写入、创建未知、清理未知、账号冲突、版本竞态和晚到响应。
- [ ] 扫码、确认、任务收缩和日志均不暴露二维码、Cookie、凭据、快照或完整上游响应。
