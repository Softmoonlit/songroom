# 12: 处理公共歌单创建结果未知

**What to build:** 让公共歌单创建在响应丢失或本地关联中断后安全恢复：能证明具体 ID 时完成原绑定，无法知道 ID 时暂停等待核查而不再次创建或猜测目标。

**Blocked by:** 07/安全创建公共歌单、11/恢复未知歌曲写入而不重发

**Status:** resolved

- [x] 创建步骤同样遵守发送前持久化和 `sending` 后只确认不重发，超时、异常退出或响应解析失败不会自动再次调用创建接口。
- [x] 正常响应取得具体云端歌单 ID 后，即使绑定事务前进程终止，重启也可在重新核验原房间、房主、授权代次和未被替代的公共绑定后完成关联。
- [x] 已取得 ID 时只可关联该具体目标，且必须重新核验原房间、房主、授权和未被替代的公共绑定；不能把具体 ID 改认到另一个房间、账号或绑定代次。
- [x] 创建可能已发但具体 ID 未知时进入“需管理员处理”，保持创建意图、原真实账号、创建前后完整清单证据和必要时间信息，且阻止该房间再次创建公共歌单。
- [x] 系统不得按歌单名称、创建日期、最新一项或相似候选自动猜测创建结果，也不得以新的创建请求试探原操作是否成功。
- [x] 同账号的其他目标可继续执行；未知创建不占执行槽，但不得因时间、容量或重启而丢弃。
- [x] 本票只在当前授权和业务关系仍有效时自动关联具体 ID；授权退出后的核查由 ticket 15、房间或公共配置结束后的清理转换与晚到结果隔离由 ticket 17 通过公开生命周期动作验收。
- [x] 页面显示已获 ID 待关联、具体 ID 已恢复和创建结果未知等彼此不同状态，不把未知包装成失败。
- [x] 持久证据只包含未来具权核查所需的脱敏事实，不保存凭据、原始响应或开放任意目标操作；具体管理命令由 ticket 20 实现。
- [x] 真实 SQLite 崩溃矩阵覆盖创建调用前后、ID 返回前后和绑定事务前后，证明当前业务关系有效时无重复创建、无错误 ID 关联；删房和授权退出竞态分别由 tickets 17、15 追加公开流程验证。
