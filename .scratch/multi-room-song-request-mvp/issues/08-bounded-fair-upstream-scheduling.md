# 08: 有界且公平地执行上游操作

**What to build:** 让多个房主同时创建公共歌单时，各自看到创建操作在全站约束内公平推进，既不并发使用同一真实网易云账号，也不让一个多步骤操作饿死其他目标；后续上游行为复用同一调度契约。

**Blocked by:** 07/安全创建公共歌单

**Status:** resolved

- [x] 调度键来自服务端核实的真实网易云账号，不使用点歌台用户、房间或浏览器输入替代。
- [x] 同一真实账号每次只执行一个上游请求，两个请求启动至少间隔 1 秒；不同账号可并行，但全站最多同时执行 2 个请求。
- [x] 每个真实账号最多容纳 20 个执行中或排队业务操作，队满明确拒绝新受理且不删除、覆盖或提前终结已有操作；一个业务操作即使包含多个上游请求也只占一项，不按步骤数重复计数。
- [x] 风控或频繁请求类别暂停整个真实网易云账号及其所有目标，只有管理员可明确恢复；普通目标权限错误只暂停该目标。账号为空、核实账号不匹配、授权不可用、网络错误和普通模块错误均保持不同稳定状态，不得互相升级或误清除绑定。
- [x] 当前公共歌单创建及其核查步骤共同遵守账号调度与全站并发；等待授权、目标权限处理、风控或管理员处理的持久任务不占执行槽但仍持久保留。
- [x] 真实账号的下次可启动时间持久化，应用重启后仍保持至少 1 秒间隔，不因内存队列重建产生突发调用。
- [x] 不同成员和不同目标按最长时间未获得执行机会者轮转，每次上游请求后让出；长任务不能连续占住账号。
- [x] 同一规范化云端歌单的冲突步骤保持顺序且不能交错，不同目标在一个目标待确认时仍可推进允许的工作。
- [x] 每个持久步骤由唯一执行权认领，发送意图提交后才调用 adapter，结果使用新的短事务应用；未引入 Redis、内存队列真相或通用工作流引擎。
- [x] 两个账号、多个房间和多项公共创建同时受理时，页面立即看到各自排队或处理中状态；队满、授权暂停、目标阻塞和风控暂停有不同稳定业务码，实际人工处置由 ticket 20 实现。
- [x] 受控时钟、真实 SQLite 与脚本化 adapter 通过公开公共歌单创建和操作查询证明账号串行、间隔、全站并发、20 项边界、多请求仍计一项、重启保持、公平让出、目标冲突及无饥饿。

架构演进与实现细节：
- 数据库新增显式迁移 `0008_bounded_upstream_scheduling.sql`，将 schema 版本升级至 9；新增 `upstream_account` 表持久化真实网易云账号下次可启动时间 `nextStartAt`、当前执行中的操作 ID `runningOperationId` 及风控暂停标记 `paused`；`operation` 表增加 `last_granted` 字段记录上次获得调度机会的时间戳。
- 提取单进程统一上游调度器 `UpstreamScheduler`（`src/operations/upstream-scheduling.ts`），接管全站并发控制（最多 2 个上游调用并行）、真实账号级严格串行（启动间隔 $\ge$ 1 秒）、单账号最大 20 项排队/执行容量、账号级风控暂停，以及按 `(lastGranted, createdAt, id)` 最久未获执行机会者轮转的公平派发。各业务模块通过 `register(kind, handler)` 注册业务处理器，认领与启动预算更新均在 SQLite 短事务内完成，派发后调用 adapter，执行完成自动释放执行槽并唤醒等待的同/异账号任务。
- 公共歌单创建模块 `PublicPlaylists` 拆解为核验身份与实际创建两个独立阶段，在每次上游请求后均让出执行权，多步骤操作整体仅占用 1 项账号容量；停机与重启恢复由应用根通过 `UpstreamScheduler` 统一生命周期管理驱动，无兼容回退与内存队列真相。
- 前端 read model 和 UI 扩展展示 `UPSTREAM_QUEUE_FULL`、`ACCOUNT_PAUSED`、`TARGET_BLOCKED`、`RATE_LIMITED` 等各类稳定业务状态码与禁用原因中文说明。
