# 05: 通过邀请提交加入申请

**What to build:** 让房主查看并复制当前房间的邀请码或邀请链接，也可重置泄露的邀请。受邀者通过链接或手工邀请码进入申请流程，未登录时先登录或注册并保留邀请上下文，登录后填写拟用昵称提交申请；邀请只授予申请资格，申请人获批前不能查看房间内容，并可自行撤回待处理申请。

**Blocked by:** 02/完成点歌台账号闭环、04/创建、列出并进入房间

**Status:** ready-for-agent

- [ ] 每个房间始终只有一份当前有效邀请；邀请码具有 60 位随机熵并固定为 10 个 base64url 字符，房间创建时生成，房间名不参与生成或校验。
- [ ] 邀请链接使用 `/join#<code>` 形式把完整邀请码放在 URL fragment；浏览器只在登录后把经格式校验的码放入 POST body，邀请码不进入 HTTP 请求 URL、Referer、Caddy 访问日志或普通应用日志。
- [ ] 房主可查看完整邀请码并通过明确按钮复制邀请链接；界面不直接展示完整邀请链接文本，复制成功与失败均有可访问反馈。
- [ ] 只有当前房主可读取完整邀请码、复制链接或重置邀请；室友、待申请用户和非成员的界面与接口都不能获得这些能力。
- [ ] 邀请可由多人重复使用且不自动过期，直到房主主动重置、房间删除或邀请被其他明确生命周期动作失效；使用一次不会消耗邀请。
- [ ] 未登录访问邀请链接时先进入登录或注册流程，并在当前标签页内保留 fragment 中的邀请上下文；认证成功后回到申请流程，不把邀请码写入 localStorage、sessionStorage 或查询参数。
- [ ] 已登录受邀者提交拟用房间昵称；昵称去除首尾空白、NFC 规范化、拒绝控制字符且为 1 至 12 个 Unicode 码点。
- [ ] 有效邀请只允许创建待处理申请，不直接建立成员关系，也不允许申请人读取房间名之外不必要的信息、公共歌单、成员或设置。
- [ ] 同一账号在同一房间最多一份待处理申请；重复提交同一幂等键和内容返回原申请，不同内容或另一个未完成申请得到稳定冲突反馈。
- [ ] 申请昵称在待审批期间不占用成员昵称；多人可提交相同拟用昵称，唯一性在后续批准事务重新判断。
- [ ] 当前成员、房主本人和已有待处理申请的账号不能借另一个邀请码重复申请；曾退出或被移除的账号可用当前有效邀请重新申请，但不自动恢复旧成员资格。
- [ ] 申请人可查看自己的待处理状态并主动撤回；撤回后立即不再计入容量，不创建成员、离开档案或云端操作，并可使用仍有效的当前邀请重新提交新申请。
- [ ] 每账号最多有 3 份待处理申请，每房间最多有 10 份待处理申请；达到上限明确拒绝新增且不取消、覆盖或挤出既有申请。
- [ ] 并发申请、重复点击和多设备提交不能突破账号、房间或同账号同房间上限；容量释放后新申请可正常提交。
- [ ] 房主重置邀请时以一个事务递增邀请代次、使旧码与旧链接立即失效，并取消由旧邀请代次产生的全部待处理申请；当前成员关系不受影响。
- [ ] 重置邀请使用固定 Radix Alert Dialog 做带当前聚合版本的破坏性确认；若房间、邀请或申请影响范围在确认后变化，旧确认被拒绝并展示最新影响数量。
- [ ] 旧邀请产生的已撤回、已拒绝或已取消记录不能被恢复为待处理；旧码在任意设备和旧页面中都不能再次提交申请。
- [ ] 邀请读取、申请、撤回和重置均在服务端重新校验当前账号、房间、邀请代次、权限与容量，不能依赖前端隐藏控件或缓存状态。
- [ ] 申请页面清楚区分无效码、已重置、容量已满、已有申请、已是成员、待处理和已撤回，不把申请资格描述成房间访问权。
- [ ] 邀请、登录/注册回跳和申请表单可完全使用键盘完成；从 320px 起邀请码、复制按钮、昵称字段和状态文案不溢出或重叠，焦点在认证回跳后落到合理位置。
- [ ] HTTP 集成测试覆盖 fragment 不上送、手工码、未登录回跳、多次使用、权限隔离、重复申请、撤回再申请、所有容量边界、并发竞争和旧码失效。
- [ ] 集成测试覆盖重置邀请取消旧代次待处理申请但保留当前成员、聚合版本冲突和普通成员无法读取/重置邀请，并检查请求与访问日志不含完整邀请码。
- [ ] 浏览器测试覆盖复制成功/失败、登录与注册后继续申请、昵称校验、待处理状态、撤回、房主重置确认以及窄屏、键盘和焦点行为。
- [ ] 本 ticket 不自动批准申请，不提供全站房间目录、按房间名加入、单人邀请、邀请自动过期、注册邀请码或个人歌单入口。
