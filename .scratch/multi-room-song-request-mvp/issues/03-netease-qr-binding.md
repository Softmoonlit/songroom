# 03: 安全扫码绑定网易云账号

**What to build:** 让已登录用户在自己的有效会话中扫码授权网易云，核实并确认真实账号身份后建立一份可供其全部自建房间复用的服务端授权。

**Blocked by:** 02/完成点歌台账号闭环

**Status:** resolved

- [x] 仓库纳入规格固定版本与源码哈希的 NeteaseCloudMusicApiEnhanced vendor、许可证、来源说明和锁文件，生产不会联网下载替代版本。
- [x] vendor 生产补丁移除歌曲增删特定路径的二次写、隐式 `NETEASE_COOKIE` 来源和敏感原始错误输出，并修复二维码检查遮蔽原错误的问题；完整性检查可检测任何偏离。
- [x] 生产 adapter 只暴露批准的白名单业务能力；每次调用使用独立短命子进程、0700 一次性目录、严格 umask、最小环境和显式凭据，退出后清理目录且不接入原始 stdout/stderr。
- [x] IPC 输入输出均由 schema 校验，worker 只返回脱敏结构；账号为空、核实账号不匹配、授权不可用、目标权限错误、风控或频繁请求、网络错误、普通模块错误、截止、异常退出和解析失败保持可区分的稳定类别，候选凭据只有在身份与授权代次仍匹配时才可提交。
- [x] 每个扫码流程有有效期、单次使用并绑定发起点歌台账号、发起 Better Auth 会话和流程代次；替代流程、过期流程、会话失效及跨账号读取或完成均被拒绝。
- [x] 浏览器只能查看自己当前流程的临时二维码和状态，不能声明或覆盖真实网易云账号 ID；服务端以扫码后的身份接口核实结果并在最终确认前展示真实身份。
- [x] 一个点歌台账号同时最多绑定一个网易云账号，同一真实网易云账号不能同时归属两个点歌台账号；并发完成时由数据库约束保证唯一结果。
- [x] 网易云凭据使用 Node.js AES-256-GCM 逐条加密，随机 nonce，并以授权 ID、真实账号 ID 和凭据代次作为附加认证数据；主密钥来自受限私有文件。
- [x] 首次绑定后再次扫到另一个真实账号必须拒绝并保留原绑定；主动退出、同账号重授权和破坏性换号分别由后续 ticket 实现，本票不提前暴露这些动作。
- [x] 离线 adapter 契约证明私有目录、最小环境、显式 Cookie、硬截止、脱敏及每个白名单写步骤最多一次出站写请求；完整应用测试覆盖扫码成功、替代、过期、跨会话、伪造 ID、重复归属和并发完成。

## Comments

### 2026-10-06：实现与验证完成

账号设置已接入首次扫码绑定：用户显式检查扫码结果，服务端核实真实账号身份后展示昵称和 ID，最终确认再次核实身份、原 Better Auth 会话及流程代次，数据库保证用户授权及真实账号归属唯一。短命二维码与未确认候选凭据仅存在服务端内存，五分钟失效、替代或退出会话后的晚到结果不会生效；已绑定用户不能启动新流程，同账号重授权及换号仍由后续工单实现。

加入独立 32 字节受限主密钥文件与逐条 AES-256-GCM 加密存储，授权 ID、真实账号 ID 和凭据代次参与认证。SQLite schema 升至 4；扫码命令的内容摘要与防重记录在同一受理事务中保存，按 UUIDv7 签发时间保留 24 小时，重启或短命资源失效后不能重新执行旧操作标识。

受审 vendor 采用固定 4.40.1/源码提交，保留批准能力所需源码、许可证、原始来源锁、生产补丁及完整性清单。构建复制受审源码，运行时从受审副本启动一次性隔离子进程；每个白名单写步骤在成功、512、断连及重定向下最多一次出站请求，网络与异常退出等可能已发写入保留 `unknown`，不自动重发。

验证使用 Node.js 24.21.0：`pnpm typecheck`、`pnpm build`、`pnpm install --frozen-lockfile --offline`、`pnpm test`（12 个文件、96 项）与 `pnpm test:e2e`（12 项）全部通过。离线 adapter/vendor 契约共 36 项，完整 HTTP 扫码测试 23 项；浏览器扫码测试使用 HTTP mock 验证界面状态，完整服务端授权链路由真实 Better Auth 与 SQLite 的 HTTP 测试覆盖。没有调用真实网易云账号，目标 VPS 与真实上游验收由后续部署工单承接。
