# 06: 审批成员并管理房间身份

**What to build:** 让房主审批加入申请并管理邀请，让当前成员查看房间身份和修改自己的昵称，同时严格限制房主与室友各自可见的管理动作。

**Blocked by:** 05/通过邀请提交加入申请

**Status:** ready-for-agent

- [ ] 房主可查看当前房间待处理申请并批准或拒绝；室友及其他房间房主不能读取申请、完整邀请或执行审批。
- [ ] 批准事务重新核验申请、邀请代次、拟用昵称、申请人归属上限、房间成员上限和全站约束，昵称已被当前成员使用时拒绝并要求申请人重新提交。
- [ ] 每房间最多 10 名当前成员且包含房主；并发审批只能产生满足全部容量与唯一约束的成员关系。
- [ ] 获批账号立即在自己的房间列表看到该房间，并以室友角色访问第一期三个入口；其自身不需要绑定网易云账号。
- [ ] 房主可重置邀请；旧码、旧链接和由旧邀请产生的待处理申请在同一事务失效，当前成员资格不受影响。
- [ ] 房主待审批角标在 1 至 9 时显示实际数量，超过 9 时显示“9+”；室友不显示角标、邀请码或审批操作。
- [ ] 房主可修改房间名称；所有成员只能修改自己的房间昵称，旧昵称立即释放且后来使用者不继承原成员数据。
- [ ] 成员列表和房间壳显示当前昵称与角色，不返回邮箱、账号称呼、邀请或其他房间身份。
- [ ] 所有 read model 返回当前 allowedActions 和禁用原因，命令受理时再次鉴权；隐藏按钮不作为权限控制。
- [ ] HTTP 集成和 Playwright 测试覆盖审批竞态、昵称竞态、容量竞态、邀请重置、角色差异、角标、改名和跨房间越权；多端 SSE 失效由 ticket 14、成员退出或移除由 ticket 16 实现。
