# 11: 恢复未知歌曲写入而不重发

**What to build:** 让公共点歌在超时、进程中断或读回矛盾时保留“结果待确认”，重启后只读取网易云事实来收敛结果，绝不重复发送可能已经发出的歌曲写入。

**Blocked by:** 10/搜索并直接公共点歌

**Status:** resolved

- [x] 每个上游写步骤在调用前持久化原账号、凭据代次、目标、绑定代次、歌曲和发送意图；进入 `sending` 后的任何中断都恢复为只能确认的步骤。
- [x] HTTP 成功但业务失败、明确业务拒绝、普通错误、超时、子进程被杀、无消息退出、解析失败、同步失败和读回矛盾被按规格区分，只有明确拒绝可直接终结为失败。
- [x] 可能已发的歌曲写入最多在约 5 秒、30 秒和 2 分钟安排三轮只读补查，补查仍遵守账号调度；三轮后停止自动请求并保持待确认。
- [x] 手动刷新和服务重启只能触发新的只读确认，不能把原步骤重新排为上游写入；退出后同账号重新授权的相同行为由 ticket 15 通过公开授权流程验收。
- [x] 待确认只阻塞同一规范化公共歌单的冲突写入，其他目标继续推进；浏览器清页、重复点击或新幂等键均不能绕过阻塞。
- [x] 每个外部调用前后、发送意图提交前后、adapter 返回前后和结果提交前后的确定性终止测试证明每个业务步骤最多产生一次上游写请求。
- [x] 同幂等键同内容始终返回原操作，同键不同内容拒绝；终态最小防重信息保留 24 小时，过期或来自未来的 UUIDv7 即使原记录已清理也不能重放。
- [x] 读回确认歌曲存在后可继续提交标签；标签未知只进入只补标签步骤，不能重发歌曲写入，且补记前重新核验全部当前条件。
- [x] 操作终结后清除搜索文本和无用恢复材料，只按规格短期保留歌曲 ID、摘要和用户尚未看完的结果；成员撤权后不再允许其读取操作。
- [x] 用户界面与机器码始终区分排队、处理中、待确认、明确失败、成功、标签未完成和需管理员处理，不提供误导性的“重试写入”动作；长期未知的具权终结由 ticket 20 实现。

## Comments

### 实现提交
- 数据库 schema 与迁移：
  - 新增迁移 `0011_unknown_song_write_recovery.sql`，在 `public_song_request` 中引入 `playlist_id`、`binding_generation`、`check_round` 与 `next_check_at` 字段及索引；不添加兼容层与数据迁移垫片，直接更新表定义。
- 未知写入恢复与三轮只读补查：
  - 在 `PublicPlaylists` 中实现写前持久化、写入步骤跟踪（`ready` -> `verified` -> `sending` -> `confirming` -> `tagging` -> `succeeded`）。
  - 进入 `sending` 及后续步骤遭遇未知错误（超时、崩溃、网络异常）或写后读回矛盾时，操作转为 `awaitingConfirmation`（step 为 `unknown`），绝不重发写入。
  - 安排三轮只读补查（约 5 秒、30 秒、2 分钟），超限后保持 `awaitingConfirmation` 并不再自动请求。
  - 服务重启与手动刷新只读校验：重启只执行只读补查，手动刷新歌单若证实歌曲存在则自动收敛点歌操作并补记点歌人标签。
  - 目标冲突隔离：`awaitingConfirmation` 仅针对同一公共歌单目标拒绝写入（抛出 `TARGET_BLOCKED` 409），允许只读与手动刷新，不同歌单不受影响；原提交者与室友均被 `TARGET_BLOCKED` 拦截。
  - 标签两阶段持久化与核验：读回证实歌曲存在后，经当前房间与成员权限重新核验才写入 `requester_tag`，若权限已不满足置为 `stopped`。
  - 前端界面与状态展示：在 `PublicPlaylistPane` 中区分排队中、处理中、结果待确认、成功、失败与已停止，待确认状态显示明确说明并禁止写入重试。
