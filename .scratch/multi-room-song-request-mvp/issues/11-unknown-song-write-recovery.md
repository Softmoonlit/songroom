# 11: 恢复未知歌曲写入而不重发

**What to build:** 让公共点歌在超时、进程中断或读回矛盾时保留“结果待确认”，重启后只读取网易云事实来收敛结果，绝不重复发送可能已经发出的歌曲写入。

**Blocked by:** 10/搜索并直接公共点歌

**Status:** ready-for-agent

- [ ] 每个上游写步骤在调用前持久化原账号、凭据代次、目标、绑定代次、歌曲和发送意图；进入 `sending` 后的任何中断都恢复为只能确认的步骤。
- [ ] HTTP 成功但业务失败、明确业务拒绝、普通错误、超时、子进程被杀、无消息退出、解析失败、同步失败和读回矛盾被按规格区分，只有明确拒绝可直接终结为失败。
- [ ] 可能已发的歌曲写入最多在约 5 秒、30 秒和 2 分钟安排三轮只读补查，补查仍遵守账号调度；三轮后停止自动请求并保持待确认。
- [ ] 手动刷新和服务重启只能触发新的只读确认，不能把原步骤重新排为上游写入；退出后同账号重新授权的相同行为由 ticket 15 通过公开授权流程验收。
- [ ] 待确认只阻塞同一规范化公共歌单的冲突写入，其他目标继续推进；浏览器清页、重复点击或新幂等键均不能绕过阻塞。
- [ ] 每个外部调用前后、发送意图提交前后、adapter 返回前后和结果提交前后的确定性终止测试证明每个业务步骤最多产生一次上游写请求。
- [ ] 同幂等键同内容始终返回原操作，同键不同内容拒绝；终态最小防重信息保留 24 小时，过期或来自未来的 UUIDv7 即使原记录已清理也不能重放。
- [ ] 读回确认歌曲存在后可继续提交标签；标签未知只进入只补标签步骤，不能重发歌曲写入，且补记前重新核验全部当前条件。
- [ ] 操作终结后清除搜索文本和无用恢复材料，只按规格短期保留歌曲 ID、摘要和用户尚未看完的结果；成员撤权后不再允许其读取操作。
- [ ] 用户界面与机器码始终区分排队、处理中、待确认、明确失败、成功、标签未完成和需管理员处理，不提供误导性的“重试写入”动作；长期未知的具权终结由 ticket 20 实现。
