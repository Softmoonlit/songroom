# 14: 通过 SSE 同步多端状态

**What to build:** 扩展 ticket 10 已建立的账号级 SSE 失效流，使一端造成的房间、公共歌单、操作和权限变化能让其他端重新查询当前权威 read model，同时保持事件最小、可丢弃且不把 SSE 变成第二套状态来源。

**Blocked by:** 06/审批成员并管理房间身份，09/读取并刷新权威公共歌单快照，11/恢复未知歌曲写入而不重发，12/处理公共歌单创建结果未知，13/识别失效公共歌单并重新创建

**Status:** resolved

- [x] 复用 ticket 10 以规格固定 `@fastify/sse` 建立的账号级连接；每个登录浏览器仍只有这一条经 Better Auth 会话鉴权的流，并把房间、快照、操作和权限资源的最小失效类型加入既有协议。事件只含资源类型、本地资源标识和单调版本，不含昵称、歌名、候选、邀请、上游 ID 或结果正文。
- [x] 当前账号只能收到其可见资源的失效提示，事件本身不扩大房间权限；会话失效或当前设备退出时连接关闭，未认证连接、其他账号和跨源请求不能建立或复用该流。
- [x] 客户端收到事件后只使对应 TanStack Query read model 失效并通过普通 JSON 重新读取；SSE 数据不直接改写页面业务实体，查询也不隐式触发上游刷新，连续事件不得形成持续轮询链。
- [x] 同账号另一设备提交点歌、标签完成、公共快照更新、创建状态变化、公共目标失效或房间成员状态变化后，相关已打开页面最终显示最新服务端状态和允许动作；未打开页面不必预取正文。
- [x] SSE 不补放历史事件；断线、服务重启或浏览器休眠后重连必须完整查询当前可见状态，连接中遗漏事件不能造成永久陈旧，服务端也不持久保存事件正文或依赖 Last-Event-ID 重放业务历史。
- [x] 重复、乱序和晚到事件按资源版本去重或忽略，不能让较旧操作、快照、绑定或权限状态覆盖较新 read model；事件与 JSON 查询竞态时以服务端当前版本为准。
- [x] 页面对连接中断采用非阻塞状态并保持普通查询与命令可用，重连不重复提交命令；操作进度、创建待核查和公共目标失效都继续由查询结果呈现，不从事件载荷猜测成功或失败。
- [x] 房间宽屏侧栏和窄屏底栏中的待审批角标、当前操作入口及公共歌单状态在失效后稳定更新；动态文案和角标不挤压导航，320px 起无重叠，键盘焦点不因后台刷新被抢走。
- [x] JSON 与 SSE 响应使用不缓存策略，SSE 经过精确同源入口且不泄露 Cookie；日志只保留必要关联信息，不记录事件正文、可见资源清单或敏感字段。
- [x] HTTP/SSE 集成测试使用真实认证会话、完整同源应用和真实临时 SQLite 打开多个客户端，覆盖多端失效、账号隔离、乱序版本、断线重连、服务重启和会话到期；Playwright 覆盖可见页面更新，测试不得直接写库、调用私有发布函数或把事件流当作权威状态断言。

## Comments

### 实现总结
1. **服务端架构与数据库迁移**：
   - 增加迁移 `0014_operation_version.sql`，给持久化 `operation` 表增加正整数 `version` 字段；同步更新 `schema.ts`、`database.ts` 以及 schema 测试。
   - `EventStreamService` 扩展支持强类型的账号级与房间级广播，事件格式固定为 `{ type: SseInvalidationType, resourceId: string, version: number }`，绝不携带任何业务实体字段或敏感数据。
   - 在 `upstream-scheduling.ts`、`public-playlists.ts`、`rooms.ts`、`invites.ts`、`song-search.ts` 等所有发生状态变更的业务点接入失效通知发布与单调版本递增；统一 `snapshot`、`permission` 与 `room` 资源以 `room.version` 作为聚合权威版本。
   - 认证与会话退出：在 sign-out、Better Auth 会话撤销及过期定时器触发时主动关闭设备对应 SSE 连接；跨源或 `sec-fetch-site: cross-site` 严格拦截返回 403。
2. **客户端 TanStack Query 失效机制**：
   - `useEventStream` 使用 `InvalidationTracker` 管理已拉取 read model 版本，严格防止旧事件或乱序事件覆盖较新视图；
   - 订阅 TanStack Query 缓存更新事件与错误事件，错误时执行 `reset()` 避免网络抖动或临时失败导致同一版本永久不能失效；
   - 仅调用 `invalidateQueries` 使对应 query key 失效并通过普通 JSON 重新读取，SSE 事件不直接修改页面数据。
   - CSS 优化保证窄屏 320px 下待审批角标自适应绝对定位，不挤压底栏按钮文字且无横向溢出。
3. **验证结果**：
   - 类型检查：`pnpm typecheck` 全部通过。
   - 单元与集成测试：`pnpm test`（28 个测试文件、260 个测试用例）全部通过，包含 `events.test.ts` 与 `useEventStream.test.ts`。
   - 端到端测试：`pnpm test:e2e`（108 个端到端测试用例）全部通过，包含专门验证多端联动与焦点保护的 `sse-invalidation.spec.ts`。
4. **剩余事项**：无，满足所有验收条件。
