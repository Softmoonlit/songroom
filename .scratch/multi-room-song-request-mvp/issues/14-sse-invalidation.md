# 14: 通过 SSE 同步多端状态

**What to build:** 扩展 ticket 10 已建立的账号级 SSE 失效流，使一端造成的房间、公共歌单、操作和权限变化能让其他端重新查询当前权威 read model，同时保持事件最小、可丢弃且不把 SSE 变成第二套状态来源。

**Blocked by:** 06/审批成员并管理房间身份，09/读取并刷新权威公共歌单快照，11/恢复未知歌曲写入而不重发，12/处理公共歌单创建结果未知，13/识别失效公共歌单并重新创建

**Status:** ready-for-agent

- [ ] 复用 ticket 10 以规格固定 `@fastify/sse` 建立的账号级连接；每个登录浏览器仍只有这一条经 Better Auth 会话鉴权的流，并把房间、快照、操作和权限资源的最小失效类型加入既有协议。事件只含资源类型、本地资源标识和单调版本，不含昵称、歌名、候选、邀请、上游 ID 或结果正文。
- [ ] 当前账号只能收到其可见资源的失效提示，事件本身不扩大房间权限；会话失效或当前设备退出时连接关闭，未认证连接、其他账号和跨源请求不能建立或复用该流。
- [ ] 客户端收到事件后只使对应 TanStack Query read model 失效并通过普通 JSON 重新读取；SSE 数据不直接改写页面业务实体，查询也不隐式触发上游刷新，连续事件不得形成持续轮询链。
- [ ] 同账号另一设备提交点歌、标签完成、公共快照更新、创建状态变化、公共目标失效或房间成员状态变化后，相关已打开页面最终显示最新服务端状态和允许动作；未打开页面不必预取正文。
- [ ] SSE 不补放历史事件；断线、服务重启或浏览器休眠后重连必须完整查询当前可见状态，连接中遗漏事件不能造成永久陈旧，服务端也不持久保存事件正文或依赖 Last-Event-ID 重放业务历史。
- [ ] 重复、乱序和晚到事件按资源版本去重或忽略，不能让较旧操作、快照、绑定或权限状态覆盖较新 read model；事件与 JSON 查询竞态时以服务端当前版本为准。
- [ ] 页面对连接中断采用非阻塞状态并保持普通查询与命令可用，重连不重复提交命令；操作进度、创建待核查和公共目标失效都继续由查询结果呈现，不从事件载荷猜测成功或失败。
- [ ] 房间宽屏侧栏和窄屏底栏中的待审批角标、当前操作入口及公共歌单状态在失效后稳定更新；动态文案和角标不挤压导航，320px 起无重叠，键盘焦点不因后台刷新被抢走。
- [ ] JSON 与 SSE 响应使用不缓存策略，SSE 经过精确同源入口且不泄露 Cookie；日志只保留必要关联信息，不记录事件正文、可见资源清单或敏感字段。
- [ ] HTTP/SSE 集成测试使用真实认证会话、完整同源应用和真实临时 SQLite 打开多个客户端，覆盖多端失效、账号隔离、乱序版本、断线重连、服务重启和会话到期；Playwright 覆盖可见页面更新，测试不得直接写库、调用私有发布函数或把事件流当作权威状态断言。
