# 28: 从自己的个人歌单点歌

**What to build:** 让成员从自己当前有效的可维护或只读个人歌单选择歌曲加入公共歌单，并在提交时重新证明来源仍属于自己且歌曲仍然存在。

**Blocked by:** 10/搜索并直接公共点歌、11/恢复未知歌曲写入而不重发、24/绑定并查看房主个人歌单、25/创建并查看室友个人歌单

**Status:** ready-for-agent

- [ ] 只有个人绑定的当前归属成员可从该来源点歌；其他成员即使能只读查看，也没有来源点歌动作且命令端拒绝。
- [ ] 房主自建、房主收藏只读和室友专用个人歌单都可供各自归属成员逐首点歌；来源是否可维护不影响点歌资格。
- [ ] 受理时重新校验当前成员、房主授权、原个人绑定和代次、来源归属、公共绑定、目标可写性、冲突及成员单未完成操作限制。
- [ ] 操作阶段执行一次当前来源完整读取，确认歌曲 ID 仍在；来源读取失败、歌曲移除、绑定撤销或收藏关系失效均停止该路径，不能凭旧快照放行。
- [ ] 来源核验、公共写入和确认组成有序阶段，同目标冲突操作不能在账号公平让出时穿插破坏前提。
- [ ] 公共目标已有歌曲时不写不移动，只提交本人去重标签；缺少时复用单次写入、完整读回、未知确认和标签补记规则。
- [ ] 标签补记前除公共条件外还必须重新核验原个人绑定、归属成员和来源歌曲；来源失效后不补回标签。
- [ ] 页面分别反馈来源变化、来源读取失败、公共歌曲结果和标签结果，不把来源问题包装成公共写入失败。
- [ ] 直接搜索公共点歌仍不读取或依赖任何个人来源，个人目标待确认、删除或失效不能阻塞该路径。
- [ ] 自动化覆盖可写来源、收藏只读来源、他人来源越权、来源歌曲移除、读取失败、绑定换代、公共已有歌曲和标签补记竞态。
