# 04: 创建、列出并进入房间

**What to build:** 让已绑定网易云的用户创建多个房间，在主页只看到自己创建或已加入的房间，并进入适合宽屏和手机使用的第一期房间工作区。

**Blocked by:** 03/安全扫码绑定网易云账号

**Status:** resolved

- [x] 建房要求当前有效网易云授权，并让用户确认当前核实后的网易云身份；浏览器不能借此提交任意真实账号 ID。
- [x] 用户填写房间名称和自己的房间昵称后创建房间，成为不可转让且不能主动退出的房主；建房只建立房间、房主成员和邀请，不创建云端歌单。
- [x] 房间名称可以重复；成员昵称按去除首尾空白并 NFC 规范化后的大小写敏感文本在当前房间唯一。
- [x] 主页只列出当前账号创建或仍是成员的房间，并显示足够的房间名、角色和进入动作；不提供全站目录、搜索或按名称加入。
- [x] 一个账号最多自建 3 个房间、当前归属 10 个房间，全站最多 20 个房间；并发越界只有合法数量成功，已有数据不被删除或挤占。
- [x] 进入房间默认显示“公共歌单”，第一期只渲染“公共歌单”“房间成员”“房间设置”三个一级入口，不显示空置、禁用或预告性质的“我的歌单”。
- [x] 宽屏使用稳定侧栏，窄屏使用固定底部三栏；页面显示房间名称和当前角色，支持返回房间列表，320px 起无横向溢出或文字重叠，搜索或表单输入唤起虚拟键盘时底栏暂时隐藏且内容不被遮挡。
- [x] 每个一级入口独立保留二级页面与滚动位置，重按当前入口回顶；离开或切换房间后清除原房间导航状态。
- [x] 页面、查询和命令始终从当前会话及服务端成员关系推导房间可见性，伪造房间 ID、角色或房主账号均不能越权。
- [x] 完整应用和 Playwright 测试覆盖未授权建房、并发容量、重复名称、昵称冲突、房间列表隔离、三入口导航及 320px、900px、1440px 布局；房间改名与成员身份管理由后续 ticket 承接。

## Comments

### 实现与自动化验证

房间命令只接受当前用户绑定的本地授权标识，提交时解密凭据并重新核实真实网易云身份；返回后再次检查会话、授权版本、幂等键和容量。房间、房主成员、十字符随机邀请与最小防重记录在同一 SQLite 事务内建立，建房不调用歌单创建。角色从持久房主归属与当前成员关系推导，房间查询不返回邮箱、上游账号、凭据或完整邀请。

主页按当前成员关系列房间，房间默认公共歌单，只有公共歌单、房间成员、房间设置三个一级入口。宽屏固定侧栏，窄屏底部三栏；成员列表可查看昵称和角色详情，各入口独立保留当前房间的二级状态与滚动，重按回顶，离房清除。离开建房页后晚到响应不会触发跳转。虚拟键盘使用聚焦与可视高度变化检测，无延时竞态规避。

使用 Node.js 24.21.0 完成 `pnpm build`、`pnpm typecheck`、完整 `pnpm test`（15 个文件、115 项）和完整 `pnpm test:e2e`（24 项），全部通过。房间新增 13 项完整 HTTP 测试与 12 项 Playwright；自建 3 和全站 20 的并发边界通过公开 HTTP 验证，归属 10 的判定由公开纯规则验证；同房间 NFC 昵称冲突、大小写敏感和跨房间同名由真实迁移后的 SQLite 约束测试验证。审批加入与昵称管理的完整 HTTP 场景由 ticket 06 承接，本票不提前增加这些端点。

浏览器测试启动器注入离线脚本化网易云 adapter，真实注册、扫码确认、建房与查询仍走完整应用；虚拟键盘在桌面 Chromium 中模拟公开 viewport 事件（含 innerHeight 与 visualViewport 同时收缩）。未调用真实网易云，未做手机真机或目标 VPS 验收；这些由部署验收票承接。已有数据库须停机显式迁移到 schema 5。

### 两轴审查完成

Standards 与 Spec 分别并行审查并完成复审，最终均无残留发现。扫码与建房统一使用最小 `command_receipt` 账本，禁止业务模块交叉反查各自命令表；显式迁移保留既有扫码防重记录并删除旧表，真实旧库测试验证迁移后的重放与跨命令冲突。建房禁用原因使用封闭错误码，会话主体归认证模块，前端按页面与浏览器行为划分模块，成员详情返回上下文已吸顶并通过三个宽度的滚动验证。本票所需网易云身份核验在 ticket 08 接入统一调度，生产上线仍受 ticket 23 完整验收约束。
