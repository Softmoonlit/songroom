# 20: 通过管理命令处置异常操作

**What to build:** 让具权服务器管理员查看并处置具体的未知写入、未知创建、公共清理和风控暂停，同时把每种高风险动作限制在已确认的业务规则内。

**Blocked by:** 11/恢复未知歌曲写入而不重发、12/处理公共歌单创建结果未知、18/恢复结果未知的公共歌单清理、19/通过管理命令恢复点歌台账号

**Status:** resolved

- [x] 管理命令复用具权 HTTPS 登录、隐藏 TTY 输入、Cookie jar、精确 Origin、证书校验和退出清理，不提供网页管理后台、任意 SQL 或任意 Enhanced 调用入口。
- [x] 管理员只能按具体内部操作 ID 查看脱敏异常事实；列表、详情和命令不返回凭据、请求体、原始上游响应或不相关用户数据。
- [x] 普通歌曲写入长期未知只能终结为“结果未能确认”并解除目标阻塞，不宣称失败、不回滚、不补写；后续业务必须先刷新并使用新幂等键。
- [x] 创建未知只能记录核查结论：具体 ID 证据唯一且原业务仍有效时恢复绑定，业务已结束时转公共清理，证据歧义时继续暂停；不得按名称猜测或再次创建。
- [x] 公共删除未知只有在核实原具体目标仍存活且仍应清理后，才允许明确授权一次新的删除尝试；授权是单次、持久且不能被重复消费。
- [x] 上游明确拒绝后，管理员可记录房主已在原账号官方客户端手工处理并触发服务端只读核验；证据不足时保持清理任务。
- [x] 风控暂停只有管理员可明确恢复；执行时重新核实当前真实账号、授权、暂停原因和状态，不能用重新授权或重启隐式恢复。
- [x] 每个高风险动作显示原账号、具体目标、当前状态和影响，要求原因及明确确认；原因去除首尾空白、规范为 Unicode NFC、拒绝控制字符且为 1 至 500 个码点，执行前重新读取，任何状态变化均拒绝旧确认。
- [x] 高风险审计记录管理员、目标、动作、原因、前后状态和结果，日志仍不含昵称、歌曲、凭据、Cookie 或完整错误响应。
- [x] 集成测试覆盖无权拒绝、普通未知终结、创建证据唯一/歧义、单次删除授权、防重复消费、手工清理核验、风控恢复和确认竞态。

## Comments

### 解决评论

- **实现提交**:
  - `feat(admin): 实现管理命令处置异常操作与安全恢复 (ticket 20)`
- **核心机制与长效设计**:
  1. **具权 CLI 与安全管理会话**:
     - 统一通过 `withAdminSession` 在交互式 TTY 下安全提示输入管理员凭据，使用配置的 HTTPS baseUrl、精确 Origin 与受信 CookieJar 登录并验证管理员身份（`adminUserIds` 鉴权）；操作完毕后立即执行 `signOut`、`dispose` 与凭据内存擦除。
     - 命令包含 `admin abnormal list`、`admin abnormal show <id>` 以及五个特定处置动作：`resolve-write`、`resolve-create`、`authorize-cleanup`、`verify-cleanup`、`resume-risk`。不提供任意 SQL、无网页后台，不绕过安全鉴权。
  2. **严格脱敏与高风险审计日志**:
     - 管理端点与 CLI 输出脱敏事实，不返回凭据、请求体、原始敏感响应或不相关用户数据。
     - 迁移 `0019_abnormal_operation_admin.sql` 将原账户恢复审计日志平滑扩展为通用的管理员高风险审计表 `admin_audit_log`（保留历史记录），持久化记录管理员 ID、目标类型、目标 ID、动作名称、处置原因（Unicode NFC / 1-500字符 / 拒绝控制字符）、前后状态、最终结果与脱敏 details；审计日志严格排除歌曲信息（如 `songId`）、昵称、凭据与 Cookie。
  3. **细粒度业务规则与乐观锁并发控制**:
     - **普通写入未知终结**: 严格核验自动补查三轮已结束（`checkRound >= 3` 且 `nextCheckAt === null`），管理员方可终结为结果未能确认并清除上游占用，解除公共歌单阻塞；补查中禁止提前干预。
     - **创建未知处置**: 比对快照判定证据。新增歌单数量不等于 1 时保持歧义暂停；数量为 1 且房间与房主仍有效时恢复绑定（下沉至 `PublicPlaylists` 维护领域内聚），房间已删除时转为公共歌单清理任务，绝不按名称猜测或重新创建。
     - **公共删除单次重试授权**: 严格核验 `checkFact === "target_still_active"`；授权标记 `retryAuthorized` 在任务认领进入 `sending` 状态瞬间原子持久消费，杜绝重复重试。
     - **手工清理核验**: 仅在上游明确拒绝（`needsAdministrator` 且 `TARGET_PERMISSION`/`upstream_rejected`）后，记录房主手工删除并触发服务端只读核验；未明确拒绝时直接拒绝。
     - **风控暂停安全恢复**: 在调度器保留全站并发上限与真实账号串行间隔约束下，执行只读 `identity` 校验，核实当前真实账号与有效授权无误后解除暂停；重启或重新绑定均无法隐式恢复。
     - **确认竞态保护**: 操作执行前重新读取状态，客户端携带服务端版本号通过 `expectedVersion` 进行原子乐观锁核验，任何版本或状态漂移均拒绝旧确认。
