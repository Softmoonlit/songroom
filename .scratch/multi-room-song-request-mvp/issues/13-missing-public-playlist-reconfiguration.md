# 13: 识别失效公共歌单并重新创建

**What to build:** 让系统在有效完整核查确认房间的专用公共歌单已经从网易云消失后，停止使用旧目标、清除旧公共标签，并允许房主主动创建一份全新的空公共歌单，而不会根据旧快照自动补歌。

**Blocked by:** 09/读取并刷新权威公共歌单快照，12/处理公共歌单创建结果未知

**Status:** ready-for-agent

- [ ] 只有在当前真实账号身份正确且完整账号歌单清单与目标有效状态按契约确认目标已删除时，才把公共绑定标记为失效；一次读取失败、不完整列表、授权暂时不可用、详情旧歌曲、删除墓碑或任意 502 均不能单独解除绑定或清空状态。
- [ ] 确认失效在本地事务中停止旧目标点歌、解除旧公共绑定并清除该绑定代次的全部点歌人标签；不删除房间、成员、邀请或网易云授权，也不改动其他房间及其他云端歌单。
- [ ] 所有成员在公共歌单页看到公共目标不可用及最后一次核查状态，不能继续向旧目标提交点歌；只有房主看到主动重新创建入口，室友、待审批者、非成员和其他房间房主不能触发重建。
- [ ] 新目标必须走专用公共歌单创建及其未知结果处理流程，不能绑定已有歌单、复用旧云端 ID、按旧名称认领目标或跨房间共用；创建完成前房间保持无公共歌单的合法状态。
- [ ] 新公共歌单以真实云端空状态建立新的绑定代次和快照，不从旧快照补歌、不恢复旧标签，也不因同一成员再次点同一歌曲而继承旧标签生命周期。
- [ ] 失效确认、手动刷新、在途点歌和房主重建并发时，以绑定代次和单调快照版本拒绝旧确认；旧读取、旧创建结果、旧歌曲操作及晚到页面查询都不能恢复旧绑定、旧标签或覆盖新目标。
- [ ] 如果检查仍不确定，界面保留最后确认快照并标为未更新或待核查，不自动显示为空、不提供重建；服务重启后继续保留绑定、证据和相应目标阻塞。
- [ ] 重新创建的重复点击和多设备竞态仍受幂等键、单房间唯一公共绑定及创建未知阻塞约束，最终至多绑定一个具体新目标。
- [ ] 浏览器流程在 320px 与宽屏均清楚展示“暂时读取失败”“已确认失效”“等待房主重新创建”和“创建结果待核查”的差异；确认失效后当前操作及页面动作随权限实时更新且不出现个人歌单、导入或换号入口。
- [ ] 自动化从运行中的同源应用经公开刷新、公共歌单查询、重建命令、操作查询和浏览器页面，使用脚本化 adapter 覆盖完整清单缺失、墓碑旧详情、502、读取失败、旧响应晚到及重建竞态；测试断言公开状态和上游调用契约，不直接修改数据库或依赖私有函数。
