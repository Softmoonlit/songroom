# 18: 恢复结果未知的公共歌单清理

**What to build:** 让删房或失效生命周期留下的公共专用歌单删除在超时、服务中断、授权退出或上游证据矛盾后安全暂停并保留最小证据：可能已发的删除只核查不重发，明确结果可自动收敛，其余状态等待后续具权处置。

**Blocked by:** 12/处理公共歌单创建结果未知，13/识别失效公共歌单并重新创建，15/退出授权并以同账号重新授权，17/删除房间及公共歌单

**Status:** resolved

- [x] 最小清理任务只保留原真实网易云账号、具体云端歌单 ID、授权归属、公共专用创建证据、发送状态和必要确认事实；不保存已删房间成员、昵称、邀请、标签、歌曲快照、搜索内容或个人资源资料。
- [x] 删除请求发出前持久记录发送意图；进入发送中后发生超时、子进程终止、无响应、解析失败或服务崩溃时均视为可能已发，恢复后只能读取核查，不得自动再次调用删除接口。
- [x] 删除接口返回明确业务成功时可直接完成清理，不强制等待详情接口变为 404；结果未知时结合当前原账号身份、完整账号歌单清单和目标有效状态区分已删除、仍存活与读取失败。
- [x] 详情仍返回删除墓碑状态及旧歌曲不能证明目标存活，任意 502、读取失败、不完整清单或矛盾证据也不能证明删除成功；证据不足时任务保持待确认并停止自动试探。
- [x] 未发送的删除在原账号授权可用时继续；原账号退出或失效时等待同账号重新授权，重新授权先核查可能已发步骤。第一期不允许绑定新账号，新账号、其他用户授权或其他房间授权永远不能处理旧清理。
- [x] 上游明确拒绝删除时，房主看到应在原账号网易云官方客户端手工处理的说明，但普通用户不能触发服务端清理核验；任务保持需管理员处理，具体只读核验与完成由 ticket 20 的具权命令执行。
- [x] 本票不暴露普通用户或内部私有入口来再次删除；任务持久保存未来具权处置所需的当前证据和稳定状态，具体的一次性删除授权、执行时重验及防重复消费由 ticket 20 实现。
- [x] 清理任务不因 24 小时、队列容量、授权暂停、风控暂停或服务重启被丢弃；它不占等待期间的执行槽，但执行与核查继续服从原账号串行、至少一秒间隔和全站并发限制，风控只能由管理员明确恢复。
- [x] 旧删除响应、旧凭据代次和晚到核查不能删除新创建的公共歌单、其他房间目标或同名歌单；所有判断以清理记录中的原账号与具体云端 ID 为边界，完成后仅移除对应最小任务。
- [x] 原房主在房间列表或账号授权上下文看到不恢复已删房间的待清理摘要，能区分等待授权、待确认、需管理员处理、需官方客户端处理和已完成；无关成员和其他用户不能查看任务，界面不暴露云端凭据或内部证据正文。
- [x] 自动化从运行中的同源应用经公开清理查询、同账号重新授权和浏览器页面，配合脚本化 adapter 覆盖明确成功、超时、进程崩溃、墓碑旧详情、502、完整清单缺失及明确拒绝，证明未知删除没有自动重发、普通用户没有清理核验或重试入口且只触及原公共专用目标；具权手工清理核验和一次性重试由 ticket 20 验收。

2. **只读核查与自动收敛逻辑**：
   - 在 `public-playlists.ts` 中实现生命周期状态机：删除前标记 `hasSent = 1`；遇到网络超时、未知错误或服务中断一律判定为可能已发，状态收敛为 `awaitingConfirmation`。
   - 自动只读核查结合当前原账号身份核验、`userPlaylists` 完整清单比对以及 `playlistDetail` 详情状态，精准处理 status=10 墓碑歌单与旧歌曲场景。两项证据确认歌单已不存在时收敛为 `succeeded`；清单仍存活或为正常有效歌单时记录事实并不自动重发；证据矛盾或读取失败（如 502）保持 `awaitingConfirmation` 并停止自动试探。
   - 明确拒绝（如 TARGET_PERMISSION）时收敛为 `needsAdministrator`。
   - 账号退出或失效时保持 `waitingAuthorization`，重新授权原账号后自动恢复可能已发步骤的只读核查。不同账号授权绝不处理旧清理任务。
3. **前端 UI 与账号上下文**：
