# 多房间网易云点歌台 MVP

Status: ready-for-agent

## 后续体验修订

[房间体验修订规格](../room-experience-refinement/spec.md)汇总用户后续确认的全站降噪、统一整页滚动、云端名称同步、下一首播放与播放指示规则，并记录直接搜索结果扩展的待确认建议。最新修订取消通用公共排序，允许成员将所选公共歌曲移动到播放指示歌曲的紧后方，取代本文完全禁止公共排序的相应条款；个人歌单权限及不读取、修改官方客户端播放队列的边界继续适用。播放记录以近似指示展示，不代表真实设备播放状态或本轮已完成实现与验收。

## Problem Statement

点歌台需要从旧的单房间、匿名成员和浏览器凭据模型，转为可供多个宿舍长期使用的统一账号与多房间协作产品。房主需要复用一份用户级网易云授权管理自己创建的多个房间，室友需要用可恢复的点歌台账号加入房间，而不能因为更换浏览器、登录会话过期或邀请重置丢失仍然有效的成员身份。

公共歌单、个人歌单、房间成员和点歌人标签具有不同的权限及生命周期。网易云才是歌曲集合与顺序的唯一权威，点歌台只能展示经过确认的歌单快照；同时，网易云接口可能超时、返回与实际结果不一致、留下删除墓碑，官方客户端也会并发修改歌单。系统如果把接口错误直接当失败重试、把旧快照当当前事实，或把旧账号结果写入新绑定，就可能重复写入、误删歌单、恢复已经清除的成员数据，或者向用户假报成功。

首版还需要在小规模单机部署下，把认证、房间权限、上游凭据、持久任务、失败恢复、响应式交互和人工异常处置连成一套可执行边界。已有决策和原型已经确定产品语义，但正式应用、生产隔离、目标服务器 HTTPS 与资源条件仍未实现或验收，需要一份无歧义的 MVP 规格指导后续开发与上线检查。

## Solution

实现“一起点歌”多房间网易云 MVP：用户通过 Better Auth 原生邮箱密码流程使用可恢复的点歌台账号，在完成用户级网易云授权后创建多个房间，通过房间邀请和房主审批管理室友。每个房间以公共歌单为默认主页，所有成员都可直接搜索并逐首点歌；个人歌单是独立、可选的存歌、文本导入及点歌来源。

房主为房间按需新建公共歌单，室友按需新建专用个人歌单，房主则可绑定自己已有的自建歌单或收藏歌单。点歌台不维护独立歌曲顺序，所有写入均读取网易云实际结果后更新统一歌单快照。可写个人歌单支持搜索添加、文本导入、单首删除、批量删除和清空；收藏来源只读但可供归属房主逐首点歌。公共歌单在点歌台内只提供点歌，不提供删歌、清空或排序。

应用采用同源 TypeScript/Node.js 单体、Fastify、React/Vite SPA、SQLite WAL、Drizzle 和 Better Auth。服务端通过持久操作状态机、真实网易云账号级串行、公平调度、目标冲突阻塞、幂等提交和写后读回处理上游不确定性；每次 Enhanced 调用都进入独立短命隔离子进程。浏览器通过普通 JSON 查询和业务命令读取状态，通过经鉴权的 SSE 接收资源失效通知，再重新查询权威 read model。

首版部署在单台公网 VPS，由 systemd 保证单实例，Caddy 提供浏览器可信 HTTPS。正常重启须恢复已提交任务，未知写入只确认而不自动重发。服务器管理员仅通过具权管理命令完成人工账号恢复和已明确授权的异常处置；不提供网页管理后台、备份系统或通用上游操作入口。

## Delivery Phases

本规格按两个可独立验收的交付阶段实施，但共享同一套领域模型、持久操作边界和生产架构，不建立临时兼容层、平行数据模型或以后必须迁移的权宜路径。

第一期是可上线日常使用的“公共点歌版”。它包含点歌台账号、用户级网易云扫码授权、房间与邀请审批、专用公共歌单、权威快照、直接搜索点歌、持久恢复、公平调度、SSE、同账号重新授权、成员退出或移除、删房与公共资源清理、服务器管理命令、安全验收和生产部署。第一期不显示空置的“我的歌单”入口，也不提供任何个人歌单、文本导入或更换网易云账号能力；房间一级入口只有“公共歌单”“房间成员”“房间设置”。第一期只有在目标 VPS、可信 HTTPS、真实网易云批准子集、管理命令、恢复矩阵、负载和浏览器验收全部通过后才可上线。

第二期在第一期已上线架构上直接增加个人歌单与完整生命周期：房主已有或收藏歌单绑定、室友专用个人歌单、个人歌单维护、个人来源点歌、文本导入、更换网易云账号，以及成员、房间和未知清理对个人资源的扩展。第二期将“我的歌单”加入房间一级导航，形成最终固定四入口；完成迁移、权限、安全、真实上游和生产回归后发布。第二期不阻塞第一期上线，且第一期缺少这些入口是明确阶段范围，不以禁用按钮、占位页面或隐藏兼容逻辑模拟已实现能力。

## User Stories

1. 作为首次访问者，我希望使用账号称呼、邮箱和密码开放注册，从而无需注册邀请码即可建立可恢复的点歌台账号。
2. 作为新注册用户，我希望注册成功后按认证组件原生流程自动登录，从而立即进入自己的房间列表。
3. 作为用户，我希望邮箱只作为登录标识而不在房间中公开，从而把登录身份与房间社交身份分开。
4. 作为用户，我希望账号称呼可以重复并可在账号页修改，从而不必把它当作唯一用户名或房间昵称。
5. 作为用户，我希望在不同房间使用不同昵称，从而按各宿舍的习惯展示身份。
6. 作为用户，我希望同一账号可同时在手机和电脑登录，从而在多个设备继续同一成员身份和网易云绑定。
7. 作为用户，我希望退出只结束当前设备会话，从而不影响其他设备会话、成员资格或网易云授权。
8. 作为用户，我希望会话过期后重新登录原账号，从而恢复仍然有效的房间成员身份，而不是新建成员。
9. 作为用户，我希望主动改密时验证当前密码，从而避免持有短暂会话的人无验证改密。
10. 作为用户，我希望主动改密遵循组件默认行为而不自动撤销其他设备会话，从而获得稳定且可预期的原生账号体验。
11. 作为忘记密码的用户，我希望通过线下联系服务器管理员恢复账号，从而在没有邮件找回功能时仍能保留原账号和成员关系。
12. 作为忘记密码的用户，我希望人工恢复后旧会话被显式撤销，从而避免只改密码却留下原有登录会话。
13. 作为用户，我希望系统不要求邮箱验证、验证码或首次强制改密，从而保持首版自用流程简洁。
14. 作为用户，我希望认证失败和限流以组件原生错误反馈呈现，从而知道请求未被接受且不会误以为业务数据丢失。
15. 作为用户，我希望会话结束不触发成员退出或歌单清理，从而将认证会话生命周期与房间成员生命周期分开。
16. 作为用户，我希望账号页不提供改邮箱入口，从而符合首版固定登录标识的边界。
17. 作为用户，我希望账号密码由成熟认证组件安全处理，从而不依赖点歌台自制的密码、会话或失败锁定机制。
18. 作为房主候选人，我希望先完成有效网易云授权再创建房间，从而确保房间后续有可用的音乐账号归属。
19. 作为授权用户，我希望扫码流程只绑定到发起授权的当前点歌台账号与有效会话，从而避免二维码被其他账号或过期流程接管。
20. 作为授权用户，我希望系统根据扫码结果核实真实网易云账号，从而不依赖浏览器声明的账号 ID。
21. 作为授权用户，我希望一个点歌台账号同一时间只绑定一个网易云账号，从而让全部自建房间共享明确的授权来源。
22. 作为平台用户，我希望同一真实网易云账号不能同时绑定给两个点歌台账号，从而避免凭据归属和未完成任务互相混淆。
23. 作为房主，我希望我的全部自建房间复用同一份网易云授权，从而无需逐房间扫码或复制凭据。
24. 作为室友，我希望操作别人创建的房间时使用该房间房主的授权，从而无需授权自己的网易云账号。
25. 作为用户，我希望自己的网易云授权失效只影响自己创建的房间，从而不影响我作为室友加入的其他房间。
26. 作为房主，我希望同一网易云账号重新授权后恢复原房间配置和安全的未发步骤，从而无需重新创建房间或重新提交已接受操作。
27. 作为房主，我希望重新授权时系统先核实真实账号身份，从而不会把另一个账号误当成原授权继续旧任务。
28. 作为房主，我希望主动退出网易云授权后全部自建房间的受影响操作暂停，从而不在无授权状态下继续调用上游。
29. 作为房主，我希望更换网易云账号前看到所有受影响的自建房间并二次确认，从而理解这是跨房间的破坏性变更。
30. 作为房主，我希望更换账号后保留房间、成员、昵称、邀请和未被撤销的申请，从而只重置与旧音乐账号相关的配置。
31. 作为房主，我希望更换账号后清除旧歌单绑定、快照和公共点歌人标签，从而不会把旧账号数据冒充为新账号状态。
32. 作为房主，我希望更换账号不迁移歌曲、不自动创建歌单，也不删除旧账号云端歌单，从而避免未经确认的跨账号修改。
33. 作为待处理旧任务的所有者，我希望系统仍只使用原网易云账号处理旧任务，从而不让新绑定账号误删或改写旧资源。
34. 作为用户，我希望登录和网易云授权是两套清楚分离的状态，从而知道退出点歌台、网易云授权失效和更换账号分别会造成什么影响。
35. 作为用户，我希望二维码仅在自己的授权页面临时展示且不进入日志，从而降低授权材料泄露风险。

36. 作为已授权用户，我希望创建房间时填写房间名称和自己在该房间的昵称，并选择当前已授权的网易云账号，从而建立清楚的房主身份。
37. 作为用户，我希望一个账号可以创建或加入多个房间，从而参与多个宿舍的点歌协作。
38. 作为用户，我希望房间名称可以重复且不作为加入凭据，从而可以使用自然名称而不承担唯一标识作用。
39. 作为房主，我希望修改房间名称，从而让房间上下文跟随实际宿舍名称变化。
40. 作为房主，我希望始终保有创建房间的房主角色，从而避免首版出现房主转让和复杂归属迁移。
41. 作为房主，我希望不能像室友一样退出自己的房间，从而必须通过明确的删房流程结束房间。
42. 作为登录用户，我希望主页只列出自己创建或当前加入的房间，从而不暴露全站房间目录。
43. 作为登录用户，我希望点击房间后进入该房间，切换房间时返回房间列表再选择，从而保持简单明确的导航模型。
44. 作为用户，我希望系统不提供全站房间搜索或按房间名申请加入，从而只有有效邀请可以发起申请。
45. 作为房主，我希望每个房间只有一份当前有效邀请，并同时提供邀请码和复制邀请链接，从而方便线下或线上分享同一资格。
46. 作为房主，我希望邀请可供多人重复使用且不自动过期，从而无需为每位室友逐个创建邀请。
47. 作为房主，我希望完整邀请码和复制邀请链接入口只对自己可见，从而不在普通室友界面扩散邀请管理能力。
48. 作为房主，我希望界面不直接展示完整邀请链接文本，从而通过明确的复制操作分享链接。
49. 作为受邀访客，我希望邀请链接在尚未登录时先引导登录或注册，再继续申请，从而保留邀请上下文而不绕过认证。
50. 作为已登录受邀者，我希望通过有效邀请填写拟用昵称并提交加入申请，从而由房主决定是否授予成员资格。
51. 作为申请人，我希望批准前不能查看歌单或操作房间，从而使邀请泄露只产生申请资格而不是成员权限。
52. 作为申请人，我希望同一账号在同一房间只能保留一份待处理申请，从而不会重复占用申请容量。
53. 作为申请人，我希望可撤回自己的待处理申请，从而在尚未获批时主动结束申请。
54. 作为房主，我希望查看、批准或拒绝加入申请，从而控制当前房间的成员资格。
55. 作为申请人，我希望拟用昵称在待审批时不占用，从而不会仅凭申请锁住昵称。
56. 作为申请人，我希望批准时若昵称已被当前成员使用，系统要求修改后重新提交，从而维持房间内当前昵称唯一。
57. 作为房主，我希望重置邀请后旧链接和旧码同时失效，并取消由旧邀请产生的待处理申请，从而完整撤销泄露的申请入口。
58. 作为当前成员，我希望邀请重置不影响我的成员资格，从而不因房主更新邀请而被移出房间。
59. 作为室友，我希望不在界面看到邀请管理入口，但仍可转发自己已经取得的邀请，从而权限与现实分享行为保持一致。
60. 作为曾经离开的账号，我希望通过当前有效邀请重新申请并再次由房主审批，从而不设置永久黑名单，也不自动恢复旧资格。
61. 作为房间成员，我希望只修改自己的房间昵称，从而房主不能代替室友改变公开身份。
62. 作为房间成员，我希望当前成员的规范化昵称在同一房间内保持唯一，从而成员展示不会混淆。
63. 作为房间成员，我希望改名后旧昵称立即释放，从而其他成员可以使用它但不会继承我的数据。
64. 作为房主，我希望可以移除室友，从而立即结束其房间访问和操作资格。
65. 作为室友，我希望可以主动退出房间，从而结束自己在该房间的成员关系。
66. 作为房主，我希望待审批申请数量在“房间成员”入口显示角标，从而及时发现需要处理的申请。
67. 作为房主，我希望角标在一至九时显示实际数量、超过九时显示“9+”，从而在窄屏仍保持清楚稳定。
68. 作为室友，我希望不显示待审批角标和审批操作，从而界面与我的实际权限一致。
69. 作为成员，我希望进入房间默认打开“公共歌单”，从而把直接点歌作为主要工作流。
70. 作为宽屏用户，我希望看到固定侧栏中的返回房间列表、房间名、当前角色和四个一级入口，从而滚动时仍能直接导航。
71. 作为窄屏用户，我希望使用固定底部四栏导航，从而以图标和完整四字标签快速进入各项功能。
72. 作为成员，我希望四个一级入口固定为“公共歌单”“我的歌单”“房间成员”“房间设置”，从而不把必要功能隐藏到更多菜单。
73. 作为窄屏用户，我希望房间名和当前角色显示在页面顶部但不吸顶，从而保留上下文又不长期挤占内容空间。
74. 作为成员，我希望四个一级入口分别保留自己的二级页面和滚动位置，从而切换后可继续之前的浏览位置。
75. 作为成员，我希望重按当前一级入口回到该入口顶部，从而快速返回页面起点。
76. 作为成员，我希望离开当前房间后清除该房间的二级页面和滚动位置，从而不把状态带入另一个房间。
77. 作为成员，我希望查看室友的个人歌单时从“房间成员”的成员详情进入，从而不增加第五个一级入口。
78. 作为成员，我希望成员详情提供紧凑明确的返回成员上下文，从而容易回到成员列表。
79. 作为键盘用户，我希望导航、弹窗、搜索和表单拥有语义标签、可见焦点及合理焦点顺序，从而无需鼠标也能完成核心流程。
80. 作为窄屏用户，我希望虚拟键盘打开时底部导航暂时隐藏，从而输入控件和候选不会被遮挡。
81. 作为成员，我希望普通滚动时窄屏底部导航保持固定，从而核心入口始终可达。

308. 作为用户，我希望密码、邮箱、昵称、邀请、Cookie、网易云凭据、二维码、搜索及导入文本、快照和完整上游响应不进入日志，从而敏感数据不会因诊断输出泄露。
309. 作为平台运营者，我希望日志在本机限量轮转，从而不引入独立日志平台、查询后台或无限磁盘增长。
310. 作为用户，我希望网易云凭据在数据库中逐条加密且主密钥与数据库分开保管，从而数据库单独泄露不会直接暴露原始凭据。
311. 作为平台运营者，我希望认证签名密钥与凭据解密密钥位于独立受限私有配置中，从而不进入仓库、数据库、日志、环境变量或命令行参数。
312. 作为平台运营者，我希望密钥缺失或凭据无法解密时明确停止相关功能，从而不会自动生成新密钥掩盖数据不可恢复。
313. 作为房主，我希望凭据密钥丢失后重新授权但保留房间、成员和未解决任务，从而不因密钥事故自动删除业务关系。
314. 作为平台运营者，我希望数据库缺失时普通启动失败而不是静默创建空库，从而避免把数据丢失误判为全新部署。
315. 作为平台运营者，我希望数据库只能通过显式初始化创建、迁移只能在停机时显式执行，从而启动过程不会隐式改变持久状态。
316. 作为平台运营者，我希望正常重启保留账号、房间、快照和已提交任务，从而“不做备份”不会被误解为内存应用。
317. 作为平台运营者，我希望首版明确不承诺磁盘损坏或误删后的本地数据恢复，从而无备份边界真实可理解。
318. 作为平台运营者，我希望数据库丢失后不凭歌单名称重建成员关系或删除资格，从而人工处置不会猜测云端所有权。
319. 作为用户，我希望所有页面和业务接口通过同源、浏览器可信 HTTPS 提供，从而密码和会话不经过明文 HTTP 或证书告警连接。
320. 作为用户，我希望登录会话只通过 HttpOnly、Secure Cookie 使用且不放浏览器本地存储，从而前端脚本不能直接读取凭据。
321. 作为用户，我希望业务变更不使用 GET、非 GET 命令校验同源来源且敏感响应不缓存，从而降低跨站请求和缓存泄露风险。
322. 作为用户，我希望自己的文本始终作为文本渲染而不是 HTML 执行，从而房间名、昵称和搜索内容不能注入页面脚本。
323. 作为平台运营者，我希望 Enhanced 只由服务端白名单业务能力调用，从而不暴露公网模块、通用代理或任意歌单 ID 接口。
324. 作为平台运营者，我希望每次 Enhanced 调用使用独立短命子进程、私有临时目录、最小环境和显式凭据，从而不同账号的进程级状态隔离。
325. 作为平台运营者，我希望每个业务写步骤最多产生一次上游写请求，从而依赖内部重试也不能破坏未知写入不重发规则。
326. 作为平台运营者，我希望上游子进程只返回经校验的脱敏结果而不返回原始响应、请求配置或异常对象，从而敏感信息不越过 adapter 边界。
327. 作为平台运营者，我希望服务只监听本机并由 Caddy 对外反代，从而应用不直接暴露公网端口。
328. 作为平台运营者，我希望 systemd 保证单实例且监听成功后才启动调度器，从而不会有两个进程同时执行持久任务。
329. 作为平台运营者，我希望停机先拒绝新命令和派发并有限等待当前子进程，从而被终止的可能写入在恢复后只确认不重发。
330. 作为平台运营者，我希望应用恢复就绪后及时推进可恢复任务，从而正常重启不会永久留下可执行任务。
331. 作为平台运营者，我希望在目标 VPS 上验收可信证书续期、端口、CPU、内存和磁盘，从而规划完成不被误当成可上线事实。
332. 作为平台运营者，我希望性能样本覆盖活跃浏览器、SSE 连接和大型歌单快照，从而验证单机工作点不会触发交换或内存耗尽。
333. 作为用户，我希望本地查询和命令受理在目标规模下快速返回并立即展示异步状态，从而上游排队不会让页面假死。
334. 作为平台运营者，我希望运行时、直接依赖、vendor 源码哈希和生产补丁精确锁定，从而升级必须经过显式评审和重新验收。
335. 作为平台运营者，我希望上线前用本人批准的专用网易云账号和歌单完成真实安全子集验收，从而旧原型证据不替代生产环境验证。

## Implementation Decisions

### 1. 系统形状与固定基线

- 首版为同源、单部署单元的 TypeScript/Node.js 应用。Fastify 提供 HTTP 和静态应用入口，React/Vite 提供纯 SPA；不使用 SSR、RSC、Next.js 或 React Router 全栈服务器。
- 采用一个 pnpm workspace，正式应用是一个 package，受审 Enhanced fork 是独立 vendor package。应用内部按认证、房间、歌单、持久操作、网易云、HTTP、界面和管理命令组织深模块；不拆微服务、独立 worker 服务、内部发布包或通用工作流引擎。
- 精确锁定 Node.js 24.21.0、pnpm 12.9.1、TypeScript 7.0.2、Fastify 5.12.5、React 与 React DOM 19.3.0、React Router 8.4.0、Vite 8.3.2、Better Auth 与其 Drizzle adapter 1.7.7、Drizzle ORM 0.45.3、Drizzle Kit 0.31.11、better-sqlite3 13.0.3、TanStack Query 5.104.1、Zod 4.6.5、UUID 14.0.2、Pino 10.4.0、Lucide React 1.52.0、Vitest 5.0.3 和 Playwright 1.63.0。配套直接依赖同样精确锁定，不使用宽松版本范围。
- 通用能力只增加经过当前固定栈兼容性核查的窄依赖：`@fastify/static` 10.1.5、`@fastify/helmet` 13.1.1、`@fastify/sse` 0.6.0、`@radix-ui/react-dialog` 1.2.0、`@radix-ui/react-alert-dialog` 1.1.24、`@radix-ui/react-tooltip` 1.3.0、`@tanstack/react-virtual` 3.14.13、`@inquirer/prompts` 8.7.3、`tough-cookie` 6.0.2、`fetch-cookie` 3.2.0，以及仅用于浏览器测试的 `@axe-core/playwright` 4.13.0。Radix 只承担弹窗、二次确认和工具提示的可访问交互，TanStack Virtual 只用于大型歌曲列表，Inquirer 与 Cookie jar 只用于服务器管理 CLI；不据此引入完整 UI 框架或新的应用平台。
- 固定 `fastify-type-provider-zod` 7.0.0 要求额外安装本项目不使用的 Swagger/OpenAPI peer，与首版不建设 OpenAPI 的边界不符，因此不采用。应用以一个薄的项目内 Fastify/Zod 适配统一端点校验、响应序列化和类型推导，不维护第二套手写 DTO。
- 核心采用 SongRoom 专用持久操作深模块，接受封闭业务意图并隐藏调度、步骤、目标锁定、崩溃恢复、账号及绑定代次。另设只读查询模块；不向调用方暴露锁键、重试策略、数据库行或任意工作流扩展点。
- 数据库采用 SQLite WAL、better-sqlite3 和 Drizzle。启用外键，配置合理的 SQLite 等待锁超时，使用显式迁移；事务绝不跨越上游调用。普通启动必须校验数据库存在、schema 版本、密钥权限、vendor 哈希和必要配置，不能自动建库或迁移。
- 数据库只可由显式初始化命令创建，迁移仅在应用停止时显式执行。数据库缺失或 schema 不匹配时启动失败并要求管理员处理。
- systemd 保证一个长期 Node.js 应用进程；HTTP、持久调度和上游协调位于同一进程。应用成功监听本机端口后才启动唯一调度器，第二实例因监听冲突失败；不建设数据库租约、心跳或分布式锁。
- 前端由 Vite 构建，服务端编译为 Node ESM，Enhanced worker 保持独立 CommonJS 短命进程。进程重启只根据持久状态恢复，不依赖内存中的在途对象。

### 2. 认证与点歌台账号

- Better Auth 1.7.7 负责邮箱密码注册、登录、退出、改密、密码哈希、签名 Cookie、数据库会话和认证请求限流。账号页面由 SongRoom 自行设计，但必须走组件标准公网端点，不能以不受限的服务端调用替代它们。
- 注册输入为账号称呼、邮箱和密码；注册后采用组件原生自动登录。称呼可重复、可修改，只用于本人账号页；不设置唯一用户名，不验证邮箱归属，不发送验证码或验证邮件，不提供邮件找回或改邮箱。
- 日常认证使用固定版本原生默认策略。已复核的默认密码范围为 8 至 128 个字符；会话有效期为 7 天、续期间隔为 1 天，使用时按原生机制滚动续期。实现后仍须通过接入测试复核这些事实。
- 使用持久化数据库会话和原生签名 Cookie，不启用 Bearer 插件或 Cookie 会话缓存，不改造成自定义令牌摘要表。Cookie 必须为 HttpOnly、Secure，并与精确可信同源入口一致。
- 日常退出只结束当前会话。主动改密要求当前密码，并保持原生默认行为，不自动撤销其他设备会话，也不额外撤销网易云扫码流程或网易云授权。
- 认证请求限流采用生产环境原生默认规则和存储。单实例且无 secondary storage 时允许内存计数随重启清空；不另写连续失败锁定、持久认证计数、验证码或注册频率规则。
- 同一点歌台账号允许多个 Better Auth 设备会话，多端共享用户级网易云绑定及各房间成员身份。业务受理限制按成员和房间跨设备统一执行。
- 每次网易云扫码授权都建立有有效期、单次使用且带代次的授权流程，并同时绑定发起点歌台账号与发起 Better Auth 会话；同账号发起替代流程时旧流程立即失效。二维码读取、状态检查和最终提交都要求原会话仍有效、流程未过期且未被替代，服务端自行核实真实网易云账号后才可绑定；浏览器不得提交账号 ID 覆盖结果，二维码只在发起者授权页临时展示。
- Better Auth 表由固定版本生成，业务表只引用其用户 ID，不复制密码和会话数据。账号称呼属于账号资料，邮箱及称呼均不进入房间成员 read model。
- 人工恢复由具权管理员通过原生设密接口设置新密码，再单独调用原生会话撤销接口；必须分别确认结果。不实现临时密码首次强制改密，不把服务器登录身份当作认证组件管理员。

### 3. 同源接口与浏览器数据流

- 同一代码库使用固定版本 Zod 定义端点级请求、响应和错误 schema，并由 schema 推导 TypeScript 类型。数据库行不得直接返回浏览器，不维护另一套手写 DTO。
- 首版内部同源 API 不承诺 OpenAPI 或版本前缀；前后端在同一次部署中原子升级。HTTP 提供资源查询和命名明确的业务命令，不提供通用命令入口或任意上游调用入口。
- 页面查询按实际页面提供深 read model：房间列表、房间壳、公共歌单、我的歌单、成员列表、成员详情、房间设置和当前操作。view 返回当前允许动作、禁用原因、资源版本和最近同步信息；执行命令时仍须重新鉴权。
- 房间壳只包含房间上下文、四入口、待审批角标、当前操作入口和必要资源版本，不包含账号邮箱、内部步骤或其他房间数据。
- 查询端点保持纯本地读取。进入公共歌单、个人歌单或成员歌单详情后，客户端另发一次显式刷新；页面先显示最近快照，无快照时显示首次同步状态。服务端合并同目标并发刷新，完成后发送 SSE 失效通知。
- 每个登录浏览器使用一个账号级、经鉴权的 SSE 流。事件仅含资源类型、本地资源 ID 和新版本，不含昵称、歌名、候选或操作结果。客户端收到后按当前权限重新查询；SSE 不补放历史，重连后完整读取当前可见状态。
- SSE 引发的 read model 查询不得再次触发上游刷新，且不得成为持续轮询。会话失效时关闭连接，成员资格撤销后旧事件对应资源查询返回不可见。
- 所有 SongRoom 业务变更命令要求幂等键。纯本地变更同步返回成功结果；需要云端执行的命令返回异步操作；本地立即完成并另有云端清理的生命周期命令同时返回本地完成信息和清理操作。Better Auth 原生端点、搜索和无副作用刷新不使用业务幂等键。
- 异步新操作返回 HTTP 202 及操作资源；同幂等键同内容返回 HTTP 200 及原操作；同键不同内容或过期标识返回 HTTP 409 及稳定业务码。校验、权限、资源不可见、容量、队列满、授权暂停和风控暂停同样使用稳定 HTTP 状态及机器可读业务码，不能靠展示文案推断。
- 所有认证和业务 JSON/SSE 响应使用不缓存策略；静态哈希资产可长期缓存，HTML 不缓存。业务状态变更不使用 GET，全部业务非 GET 命令校验精确同源 Origin，关闭跨源资源共享。

### 4. 关系模型与不变量

- 核心业务使用带外键、唯一约束和检查约束的关系表，覆盖房间、成员、邀请、加入申请、网易云授权、规范化云端歌单、歌单绑定、快照歌曲、点歌人标签、持久操作、逐项结果、最小清理任务和管理员审计。
- 应用实体与操作使用服务端生成的 UUIDv7 文本标识；客户端幂等键也为 UUIDv7。服务端按点歌台账号定域并校验标识时间，超过 24 小时或明显来自未来的标识直接拒绝。
- 网易云账号、歌单和歌曲 ID 均作为上游不透明字符串保存，不假设数值范围。歌曲只按网易云歌曲 ID 去重，不按名称、歌手或专辑合并。
- 成员是点歌台账号与房间的持续关系，角色只有房主和室友。每房间恰有一名不可转让的房主；同一账号在不同房间的成员、角色和昵称互相独立。
- 成员当前昵称以去除首尾空白并 NFC 规范化后的大小写敏感文本判断同房间唯一。申请昵称不占用，批准事务再次核验唯一性和容量。
- 成员资格结束时硬删除成员及相关业务数据，不增加软删除、离开时间、恢复标记或离开档案。未解决上游事项另行收缩为不含昵称、快照和导入原文的最小记录。
- 每个房间仅有一份当前邀请，邀请链接与码共享同一代次。邀请码为 60 位随机熵、固定 10 个 base64url 字符的随机值，以普通业务数据保存；重置事务递增邀请代次、使旧码失效并取消旧邀请产生的待处理申请。
- 邀请链接把邀请码放在 URL fragment 中，使其不进入 HTTP 请求和 Caddy 访问日志；SPA 在登录后将经校验的码放入 POST body。邀请码只授予申请资格，不直接授予房间访问。
- 同一账号与房间最多一份待处理申请。批准事务同时校验邀请、申请状态、昵称、申请人归属上限、房间成员上限和全站约束。
- 容量限制固定为：全站最多 100 个点歌台账号、20 个房间；每房间最多 10 名当前成员（含房主）；每账号最多自建 3 个房间、当前归属 10 个房间、待处理申请 3 份；每房间最多 10 份待处理申请。达到上限只拒绝新增，不删除、移除或挤占已有数据；除同账号同房间仅一份待处理申请外，不另设加入申请频率计数。
- 用户级网易云绑定记录点歌台用户、真实网易云账号、凭据代次、授权状态和加密凭据。同一用户同时最多一份当前绑定；同一真实网易云账号在有效绑定或未解决最小任务期间全站只归属一个点歌台账号。
- 网易云授权失效与用户主动退出授权暂停其全部自建房间的上游操作，但不删除业务实体。重新授权必须确认真实账号一致并产生受控凭据代次；旧响应不能覆盖新凭据。
- 更换网易云账号是显式的跨房间破坏性命令。它保留房间、成员、昵称、邀请和仍有效申请，硬删除旧绑定引用、快照引用及公共点歌人标签，不迁移歌曲，不创建新歌单，也不删除旧账号云端歌单。
- 云端歌单以真实网易云账号 ID 与云端歌单 ID 规范化唯一标识。多个房间绑定同一目标时引用同一歌单记录和快照，但成员权限始终按各自房间独立计算。
- 歌单绑定含绑定类型、房间内归属、云端可维护性、点歌台专用创建来源和单调绑定代次。公共绑定、房主已有或收藏个人绑定、室友专用个人绑定必须可区分，删除资格不能由名称推断。
- 每个房间至多一个公共绑定，每个当前成员至多一个个人绑定。公共和室友个人歌单不共用；只有房主已有或收藏个人歌单可在自己的多个房间共用。
- 有效完整读取以事务生成单调快照版本，替换该规范化目标的歌曲集合与顺序并更新成功同步时间。读取携带的旧版本或旧绑定代次不能覆盖新快照。
- 快照必须基于完整歌曲 ID 集合。不得把默认截断的列表、部分 tracks 或已删除对象详情中的旧歌曲当成完整有效快照。
- 点歌人标签关联公共绑定代次、歌曲 ID 和当前成员，成员与歌曲组合去重。标签代表该成员在当前标签生命周期内点过，不代表添加者、次数或票数。
- 有效完整读取确认公共歌曲移除时，在同一本地事务中删除其全部标签；同步失败或不完整读取不得删除快照和标签。未观察到的外部删除后重加不结束标签生命周期。
- 破坏性二次确认操作携带页面读取的本地聚合版本。提交时若房间、成员、邀请或绑定聚合版本已变化，则拒绝旧确认并返回最新影响范围。

### 5. 房间、歌单与生命周期规则

- 建房命令要求当前有效网易云授权；界面保留选择或确认当前已授权音乐账号的产品步骤。浏览器只能提交该用户当前绑定的本地授权标识，服务端须重新核验并从受信绑定解析真实网易云账号，不接受任意真实账号 ID。建房创建房主成员和邀请，但不创建任何云端歌单。
- 公共歌单只允许房主执行专用新建；正常响应返回具体云端 ID 后立即绑定。新建名称为 `songroom-<房间名>-公共`，后续房间改名不自动改云端名称。
- 室友个人歌单只允许归属室友按需专用新建；正常响应返回 ID 后立即绑定。名称为 `songroom-<房间名>-<创建时成员昵称>`，后续改名不自动改云端名称。
- 房主个人歌单只从当前授权账号实际清单中选择。服务端核验目标为当前账号自建或已收藏普通歌单，并据此保存可维护或只读能力；不得仅因任意公开 ID 可读就允许绑定。
- 点歌台内公共歌单对房主和室友提供相同点歌权限，不提供删除歌曲、清空或排序。个人歌单只有归属成员可从中点歌；只有可维护来源提供添加、文本导入、删除和清空。
- 单首删除直接执行；批量删除与清空要求二次确认。清空先完整读取并固定本次所见 ID 集合，只逐首处理这些 ID，不循环追删随后外部新增歌曲，最终读回仍有歌曲时按实际结果展示。
- 个人歌单点歌在操作阶段读取一次当前来源，核验成员归属、绑定代次、目标有效和歌曲仍在。直接搜索点歌不访问个人歌单，二者都使用目标房间房主的授权并校验公共目标。
- 公共目标已有歌曲时不发增加请求、不调整顺序，只进入本人标签提交。只有公共歌曲已确认存在且标签提交成功才形成完整点歌成功。
- 成员主动退出与房主移除使用同一事务：撤销权限，硬删除成员、昵称、该成员标签、个人绑定和快照引用，并创建其专用个人歌单的最小清理任务；不删除公共歌曲、其他成员标签、点歌台账号或其他房间数据。
- 删房事务要求房主和二次确认版本，立即硬删除房间业务数据及访问关系，使邀请和申请失效；为该房间的公共歌单及全部室友专用个人歌单创建最小清理任务。房主已有或收藏个人歌单只解除引用。
- 生命周期本地事务不等待云端删除。清理记录仅保留原真实账号、具体云端 ID、授权归属、专用创建证据、发送状态和必要确认信息，不保存离开成员昵称、快照、标签或导入资料。
- 专用歌单删除收到明确业务成功即终结清理，不要求详情变为 404。结果未知时只读补查同账号完整清单和目标有效状态；详情返回状态为删除墓碑及旧歌曲不能证明仍存活，任意 502 也不能证明已删除。
- 上游明确拒绝删除时，要求房主在原账号官方客户端处理，再由服务端核验。长期未知只有管理员核验原目标仍存活且仍应清理后，才能明确授权一次新删除尝试。
- 确认公共歌单删除时，解除旧公共绑定并清除其标签；确认个人歌单删除时解除相应绑定。重新配置均不从旧快照补歌。
- 一次读取失败、授权暂时不可用或详情异常不得自动解除绑定、认定已删除、重建歌单或清除快照。

### 6. 持久操作与状态机

- 只有确认提交的写入、写后确认、补查、歌单创建、标签补记和专用清理进入持久操作。搜索、普通读取和刷新是可取消的内存工作；其成功产生的完整快照仍持久化。
- 操作采用公共信封和按类型区分的关系明细表，不使用通用 JSON 任务载荷承载权限、调度、发出状态或恢复真相。
- 用户可见聚合状态与内部上游步骤状态分离。内部步骤状态固定为 ready、sending、confirming、succeeded、rejected、unknown 和 stopped；外部业务状态固定表达排队、处理中、待确认、等待授权、需管理员处理、部分完成、成功、明确失败和已停止。
- 每个上游写步骤在调用前先用本地事务持久化发送意图、原账号、凭据代次、目标、绑定代次和步骤内容。进入发送状态后发生任何崩溃，恢复时一律按可能已发处理，只确认、不重发。
- 每个操作拥有唯一执行权。调度器在本地事务中认领下一步骤并提交状态后才可调用上游；上游调用完成后以新的短事务应用结果，不让数据库事务跨越外部调用。
- 结果应用前重新核对操作原账号、凭据代次、房间成员资格、所有涉及的绑定代次和目标。生命周期已变化时停止尚未发步骤，晚到结果仅用于原目标必要确认或清理，不得恢复业务实体或写入新绑定。
- 每次确认提交使用按点歌台账号定域的 UUIDv7 幂等键和规范请求摘要。同键同摘要返回原操作，不同摘要返回稳定冲突错误；终态最小防重记录保留 24 小时。即使记录已清除，过期 UUIDv7 仍直接拒绝。
- 操作终结后立即删除搜索词、导入原文、候选及无用恢复字段。歌曲 ID、最终逐项结果和摘要只保留到成员明确看完或最多 24 小时；不提供历史列表。
- 每个成员在一个房间最多一项未完成写操作，跨设备和标签页统一计算。重复点击同一内容返回原状态；其他成员可进入该账号有界队列。
- 权限撤销后立即禁止原成员查看操作并删除成员业务结果；只有确实需要收敛上游状态的字段可转化为最小清理记录。

### 7. 调度、冲突与恢复

- 调度键为真实网易云账号，而非点歌台用户或房间。同账号每次只执行一个上游请求，启动间隔至少 1 秒；不同账号可并行，全站最多同时执行 2 个上游请求。
- 每个真实账号最多 20 个执行中或排队操作。一轮百行搜索或一次导入各算一个操作，不按歌曲数量占队列；搜索、读取、写入和补查共同计入调度。
- 等待原账号授权、风控恢复或管理员处理的持久任务不占执行槽，但不可因容量、年龄或暂停而丢弃。首版不增加全站操作总数或暂停记录分层配额。
- 持久化真实账号的下次可启动时间，保证重启后仍遵守至少 1 秒间隔。同目标冲突步骤保持先后；不同目标及不同成员操作按最长时间未获得执行机会者轮转，每次上游请求后让出执行机会。
- 个人来源点歌的来源核验、公共写入和确认是一个有序操作阶段，不能让同目标冲突操作在让出账号执行权时插入。官方客户端不受本地调度控制，其外部竞态作为明确边界接受。
- 结果待确认只阻塞对应规范化云端歌单的冲突写入及把它作为来源的点歌，阻塞覆盖所有房间引用；允许只读确认，其他歌单继续执行。直接搜索点歌不受无关个人来源目标阻塞，但仍受公共目标及成员单操作限制。
- 明确风控或频繁请求提示暂停整个真实账号，禁止自动探测恢复；仅服务器管理员可明确恢复。普通目标权限拒绝只暂停该目标，必须结合当前真实账号身份区分授权失效、账号不匹配和目标权限问题。
- 正常上游业务结果必须解析响应体，不能把外层 HTTP 200 当作业务成功。歌曲增删正常执行一次写后完整读回，以实际集合和顺序更新快照并确认相关 ID。
- 一般错误码、超时、子进程被杀、同步失败、成功响应后歌曲缺失或读回矛盾均不能单独证明写入失败。可能已发时进入待确认，不自动重发。
- 初次同步失败后最多安排三轮自动只读补查，目标时间约为失败后 5 秒、30 秒和 2 分钟，仍遵守账号限流且不是精确时间承诺。三轮后停止自动请求；手动刷新或原账号重新授权可开始新的只读确认轮次。
- 普通增删或标签长期未知时，管理员可在核对后终结为“结果未能确认”并解除阻塞。终结不宣称失败、不回滚、不补写；后续必须重读当前状态并以新幂等键提交新操作。
- 授权退出或确认失效时暂停受影响自建房间的任务。原真实账号重新授权后先确认可能已发步骤，再重新核对成员、绑定和目标，安全时自动继续尚未发步骤。风控暂停不因重新授权或重启自动解除。
- 创建正常返回具体歌单 ID 时自动建立绑定。创建请求可能已发但 ID 未知时暂停并交管理员结合创建意图、创建前后完整清单、创建者和具体 ID 核查；不得按名称或日期猜测，不得自动再次创建。
- 创建已获得 ID 但本地关联尚未完成时，可在原成员、房间和绑定仍有效时恢复关联；若成员已离开或房间已删除，只保留对应专用资源清理，不恢复业务关系。更换网易云账号时不得借恢复自动删除旧账号歌单。

### 8. 搜索、导入和点歌执行

- 文本导入每个非空行去除首尾空白后搜索，支持两侧带空格的“歌名 - 歌手”及仅歌名；普通连字符不拆分。输入最多 100 个非空行和总计 20,100 个 Unicode 码点，重复行计入行数，超限整轮拒绝且不启动搜索。
- 每行最多取前 5 个单曲候选，默认第一条。格式错误、未找到和搜索失败分别保存为当前标签页内存预览状态；候选选择不做智能匹配、置信度判断、分页或加载更多。
- 文本导入搜索及直接搜索使用短命内存 searchId。创建后立即返回，候选进度变化通过 SSE 失效提示查询；每个导入页只保留一轮有效搜索。修改输入、放弃、离房或重启会停止旧轮未发请求并丢弃晚到结果。
- 未提交导入的输入、候选选择、二级页面和滚动位置只在当前浏览器标签页的当前房间内存中保存，不进入 Query 缓存、URL、localStorage、sessionStorage 或数据库。
- 导入提交事务重新鉴权并捕获个人绑定代次；先完整读取目标，按歌曲 ID 去重并跳过已存在项。成员资格已经结束时拒绝命令并按生命周期规则清除该房间内存状态；成员仍有效，但个人歌单归属、绑定代次、可写性或房主授权在预览后变化时，命令须明确拒绝且浏览器保留当前预览。通过校验后，缺少项逐首写入、每首写后读回；明确拒绝记录失败后可继续下一项，未知则暂停同目标后续写入。
- 导入允许部分成功，不回滚成功项。结果逐项区分已加入、已存在、明确失败和待确认。读回确认只表示当时云端包含歌曲，不保证可播放或证明由本次首次加入。
- 直接搜索点歌的恢复明细只记录公共目标及标签阶段，不记录不存在的个人来源。个人来源点歌另记录原个人绑定、归属成员和来源歌曲，用于恢复及标签补记时重新核验。
- 两种点歌均先校验成员、房主授权、有效可写公共目标及冲突。个人来源点歌另进行一次完整当前来源读取；直接搜索点歌不读取个人来源，也不因其失效或待确认停止。
- 公共目标已有歌曲时跳过上游增加并提交本人去重标签。需要增加时只有写后读回确认歌曲存在后才可提交标签；读回未知不得提前新增标签。
- 标签提交在与对应快照版本一致的本地事务中完成。标签失败进入只补标签步骤，补记前确认公共歌曲、原成员资格、房主授权和公共绑定仍有效；个人来源点歌还要确认原个人绑定仍有效。条件不成立则停止，不恢复旧数据。
- 搜索、预览和取消不写云端。所有用户可见的允许动作由 read model 计算，但命令受理时必须再次鉴权和核验队列、容量、授权与目标状态。

### 9. Enhanced vendor 与隔离 adapter

- 固定 NeteaseCloudMusicApiEnhanced 4.40.1、源码基线 a8c781fd64faab17fedfd46e0615a2609307f163，以带许可证、来源说明、锁文件和哈希的受审 vendor 包纳入仓库；部署时不得联网下载替代版本。
- 生产补丁删除歌曲增删模块在特定 512 路径下的二次写，删除隐式 NETEASE_COOKIE 凭据来源，禁止请求层输出完整敏感错误响应，并修复二维码检查未定义变量掩盖原错误的问题。不保留未补丁入口或兼容路径。
- 生产 adapter 只暴露 SongRoom 已批准的搜索、读取、身份、二维码、歌单创建、歌单删除和歌曲增删等白名单能力，不暴露 Enhanced 通用模块调用。
- 每次上游调用启动一个独立、单用途、短命子进程并创建一次性 0700 私有临时目录。子进程使用严格 umask，以私有目录作为工作和全部临时目录，只继承最小环境白名单。
- 父进程通过 IPC 传入单一白名单操作、显式凭据、稳定设备信息及已由 schema 校验的参数；不得通过全局变量、共享环境或长期进程复用账号状态。stdout 和 stderr 不接入应用日志。
- 子进程结束或失败后删除私有目录，父进程退出时终止仍存活子进程。上游请求 15 秒、子进程硬截止 25 秒为部署待验收工作点，不视为上游保证。
- worker 只返回每种操作定义的脱敏结构、业务码、HTTP 状态和可能的候选新凭据；不返回原始响应、Axios Error 或请求配置。父进程必须对 IPC 结果再次做 schema 校验。
- 候选凭据只有在真实账号身份和授权代次仍匹配时才可加密提交。读超时视为读取失败；写超时、进程被杀、无消息退出、解析失败和读回矛盾均视为结果可能未知。
- vendor 的白名单写入口及底层请求层须经过静态核查和离线契约验证，确保每个业务步骤最多产生一次真实上游写请求。vendor 哈希、补丁或白名单发生任何变化，都必须重新完成同等核查和验收。

### 10. 凭据、输入与日志安全

- 网易云凭据使用 Node.js 原生 AES-256-GCM 逐条加密，每条授权使用随机 nonce，并以本地授权 ID、真实网易云账号 ID 和凭据代次作为附加认证数据。数据库保存带格式版本的密文包。
- 32 字节凭据主密钥从服务器受限私有文件读取；Better Auth 签名密钥同样稳定保存在与数据库分离的受限文件。密钥不进入环境变量、命令行、仓库、数据库或日志，不接外部密钥管理平台。
- 首版不开发在线密钥轮换。密钥缺失、权限不正确、解密失败或主动替换时停止相关功能；凭据密钥丢失要求原账号重新授权，不删除房间、成员或未解决任务，也不能以新网易云账号完成旧清理。
- 数据库只读泄露且签名密钥未泄露、未启用 Bearer 或接受原始 token 的自定义入口时，Better Auth 数据库 token 不能直接当作完整签名 Cookie 使用；不把此边界扩大为可抵御密码离线猜解、数据库可写、有效 Cookie 被窃取或运行环境失陷。
- VPS 或应用运行环境失陷时，将网易云凭据视为可能泄露，停止服务并处理凭据撤销，修复后重新授权；静态加密不宣称能抵御已控制运行环境的攻击者。
- 应用 JSON 请求体最多 128 KiB。账号称呼 1 至 40、房间名 1 至 16、房间昵称 1 至 12、单条搜索或导入行 1 至 200 个 Unicode 码点；文本导入总计最多 20,100 个码点；管理员原因 1 至 500 个码点。
- 用户文本统一去除首尾空白并规范为 Unicode NFC，拒绝控制字符。前端始终以文本方式渲染用户内容，不提供将用户输入作为 HTML 的路径。
- Pino 向 stdout 输出结构化日志，由 systemd/journald 本机限量轮转。普通日志只包含请求关联 ID、路由模板、状态码、耗时、稳定错误码和必要内部操作 ID，不记录请求或响应体。
- 密码、邮箱、账号称呼、昵称、邀请、Cookie、网易云凭据、二维码、搜索文本、导入原文、歌单快照和完整上游响应不得进入日志。离开成员的最小清理记录及审计不得演变为昵称或业务档案。
- 高风险管理员操作另写最小数据库审计，保存必要时间、管理员内部标识、目标内部标识、动作、原因和结果。首版不建设日志平台、查询后台、用户行为统计或两套独立日志保留策略。
- 邀请作为普通业务数据明文保存，不额外加密；其访问受房主权限保护且不写日志。由于邀请只授予待审批申请资格，不将其泄露等同于成员权限泄露。
- Enhanced 永远不直接暴露公网；浏览器不能提交 Cookie、真实账号调度键、任意云端歌单 ID、绑定代次、内部步骤或上游模块名。服务端从当前账号、房间成员关系和持久绑定推导全部上游目标。

### 11. 服务器管理命令

- 首版仅提供精简服务器管理 CLI，不提供网页管理后台、多级审批、独立身份服务管理台或任意 SQL/上游命令。
- 首个服务器管理员通过 Better Auth 的 adminUserIds 受限配置声明。操作员先正常注册，经鉴权 whoami 取得本人用户 ID，更新配置并重启；不直接修改认证数据库授予权限。
- 管理 CLI 只访问已配置的浏览器可信 HTTPS 入口。每次从 TTY 隐藏读取管理员邮箱和密码，走标准邮箱登录、会话核验和原生管理接口，使用仅存于内存的 Cookie jar，发送精确可信 Origin；完成后主动退出 CLI 会话。
- CLI 不接受粘贴 Cookie、不关闭证书校验、不提供不安全 loopback Cookie 例外。SSH 身份只允许运行命令，不能替代具权 Better Auth 会话。
- 受鉴权命令限定为：管理员身份核验、账号设密并撤销全部会话、查看具体异常操作、终结普通未知、授权一次新的专用删除、核验原账号官方客户端手工清理和恢复风控账号。
- 数据库初始化、迁移、检查与部署自检只依赖服务器权限，但不能修改普通业务状态。账号与异常处置命令必须经应用权限和业务规则校验。
- 高风险命令显示具体任务、原真实账号、目标和当前状态，要求填写原因并明确确认；执行时重新读取并核验状态和处置资格，变化后拒绝使用旧确认。
- 账号恢复必须经已知线下渠道核实，不能仅凭登录邮箱、房间昵称或邀请。设密和撤销会话分别调用原生接口并分别记录结果。
- 创建未知不得猜同名最新歌单；普通未知只能终结为结果未能确认；专用删除未知只有确认原目标仍存活且仍应清理后才允许一次新尝试；证据不足保持暂停。
- 精简运维清单必须覆盖管理员初始化、服务启停、升级检查、账号人工恢复、未知任务处置、原账号手工清理核验、风控恢复、密钥缺失和数据库丢失。

### 12. 前端信息架构与状态

- 使用 React Router 的 SPA 路由能力和 TanStack Query 管理服务端 read model 及缓存失效。房间导航、各入口滚动、弹窗和未提交导入由房间级 React 内存状态管理；不引入 Redux 或通用客户端状态机。
- 第一期房间一级入口固定为“公共歌单”“房间成员”“房间设置”，不渲染空置、禁用或预告性质的“我的歌单”。第二期加入“我的歌单”后，最终一级入口固定为“公共歌单”“我的歌单”“房间成员”“房间设置”。室友个人歌单从成员详情只读查看，不另设一级入口，不将必要入口收进“更多功能”。
- 进入房间默认显示“公共歌单”。第二期加入的个人歌单是独立、可选的来源，不与公共歌单并列为默认工作台；未配置个人歌单不作为阻止直接搜索点歌的待办。
- 导航按可用宽度响应，而非设备类型。宽屏采用固定左侧栏，包含返回房间列表、房间名、当前角色和四入口；窄屏采用固定底部四栏，图标在上、完整四字文字在下。具体切换点由布局能否无溢出容纳内容决定，不把原型验证宽度硬编码成产品语义。
- 窄屏房间名和角色位于内容顶部且不吸顶。虚拟键盘打开时暂时隐藏底栏，普通滚动时底栏固定；弹窗打开时遮罩覆盖房间内容、锁定背景并禁用房间导航。
- 每个一级入口独立保留二级页面和滚动位置；重按当前入口回到该入口顶部。成员详情仅让紧凑返回上下文吸顶。离开房间、切换房间、退出或删房时，在相应草稿丢弃确认通过后清除原房间导航和滚动状态。
- 公共歌单搜索点歌工具栏吸顶；“我的歌单”的搜歌和导入入口不吸顶；导入预览的已选数量与提交区吸顶，导入输入和结果页不吸顶。
- 导入作为“我的歌单”的二级状态。同房间切换一级入口保留当前标签页内存状态且不询问；刷新、关闭、明确放弃、返回房间列表、切换房间、退出账号或删除当前房间前提示未提交内容将丢失并要求确认。刷新和关闭采用浏览器标准离开提示；成员仍有效时，因个人歌单归属、绑定代次、可写性或房主授权变化而被服务端拒绝提交，浏览器保留当前预览；成员资格结束时立即清除该房间状态。
- 每个浏览器标签页只保留当前房间一份导航和导入内存状态。不同标签页草稿独立；已提交操作完全从服务端查询，跨标签页共享成员级受理限制。
- 房主成员页提供邀请码、复制邀请链接、重置邀请、审批、拒绝和移除；室友不渲染这些能力。房主待审批角标一至九显示实际数，更多显示 9+；室友无角标。
- 房主和室友都可查看成员详情及只读个人歌单、修改自己的房间昵称；页面不能借“查看”入口暴露维护能力。
- 搜索和导入候选、操作结果、快照过期、队列繁忙、授权暂停、目标阻塞、接口成功但同步待确认以及标签未完成必须使用彼此可区分的状态，不将待确认包装成明确失败或可重试。
- 界面只展示服务端 read model 给出的 allowedActions 和禁用原因；前端隐藏按钮不构成权限控制。命令失败后按稳定业务码刷新相关 view，不推测服务器内部状态。
- 浏览器支持当前及前一主版本的桌面 Chrome、Edge、Firefox、Android Chrome 和 iOS Safari。响应式验收从 320px 起，核心流程满足键盘使用、可见焦点、语义标签和 WCAG 2.2 AA 对比度。
- 图标按钮使用既定 Lucide React 图标并提供可访问名称或工具提示；固定导航、工具栏、角标和歌曲行使用稳定尺寸与响应式约束，动态状态不得造成重叠或布局跳动。


### 13. 单机部署与性能工作点

- 生产运行在单台公网 VPS，应用和持久化数据同机；接受升级、维护和故障处理期间停机，不做多节点、高可用、自动故障切换或独立 worker 服务。
- 直接使用 systemd 运行专用系统用户下的单应用实例，不引入 Docker。应用仅监听本机回环地址，Caddy 是唯一公网入口并负责浏览器可信 HTTPS。
- 持久数据、私有配置和运行临时数据使用彼此分离、权限受限的系统目录；数据库、密钥和临时目录不得位于静态资源目录。systemd 使用 NoNewPrivileges、只读系统目录和最小必要可写路径。
- 初始目标机器工作点为 2 vCPU、2 GiB RAM 和至少 5 GiB 可用磁盘。该数值、全站并发 2、账号队列 20、1 秒账号间隔和容量限制均为部署待验收工作点，不是已实测性能或网易云安全阈值。
- 正常启动先完成数据库、schema、密钥权限、固定 vendor 哈希、生产补丁和配置自检；监听成功后启动调度器，并在就绪后 5 秒内开始推进可恢复任务。
- 停机先拒绝新业务命令和新上游派发，最多等待当前 25 秒子进程结束；systemd 总停机上限为 35 秒。被终止的发送步骤在下一次启动后按可能已发确认，不重发。
- Caddy 必须提供浏览器默认信任的 HTTPS。实际 Caddy 版本、入口、证书签发及自动续期、端口可达性和机器资源在部署前现场核验；公网 IP 短效证书只是一种候选，不能用明文 HTTP、私有 CA 告警或忽略证书错误替代。
- 生产明确配置唯一 HTTPS base URL 和精确可信 Origin，只信任本机 Caddy 代理提供的转发信息。静态资产与业务 API 采用前述不同缓存策略。
- 本地负载样本包含 100 条 SSE 连接、20 个并发活跃浏览器和单歌单 10,000 首快照。目标 VPS 上，不含上游等待的页面查询和命令受理 p95 不超过 500ms；本地提交后 SSE 失效通知在 1 秒内发出；10,000 首快照的本地替换不超过 3 秒，且不得出现交换或 OOM。
- 上游排队与网易云响应不设延迟 SLA；命令受理后必须立即返回排队或操作状态，页面不得等待整个上游流程才反馈。
- 不开发备份系统、不自动备份、不提供历史回滚。正常重启仍必须持久化数据；磁盘损坏或误删造成的数据库丢失不承诺自动恢复，云端歌单也不能仅凭名称重建本地归属。
- 依赖或 vendor 升级必须显式评审，重新运行全部自动化、离线 adapter 契约和批准范围内的真实验收。不得在部署时隐式更新直接依赖。


## Testing Decisions

### 1. 测试接缝

- 业务自动化的主要且最高接缝是运行中的同源应用：测试启动完整 Fastify、Better Auth 接入、HTTP/SSE、持久操作调度器和真实临时 SQLite，通过公开 JSON 命令、查询、SSE 及浏览器页面观察行为。
- 每个测试数据库从真实显式迁移建立，启用与生产一致的外键、WAL 和约束。完整应用测试不得以内存数据库、逐表 mock 或直接修改数据库代替公开命令准备状态。
- 对解析、规范化、容量判断、允许动作、状态转换和调度选择等无 I/O 规则，通过其公开纯规则接口做快速边界与性质测试；只断言输入输出和不变量，不固定私有函数形状。
- 持久操作深模块另以其封闭业务接口和真实临时 SQLite 做模块集成，覆盖全部事务边界、恢复和调度不变量。测试基础设施提供受控时钟与明确的进程终止或 adapter 中断点，以确定性推进 7 天会话、24 小时幂等窗口、三轮补查及每个崩溃切点；这些控制不进入生产 HTTP 契约。
- Enhanced 是唯一外部 adapter 契约接缝。自动化使用遵守同一 schema 的脚本化 adapter，精确安排读取、业务拒绝、超时、进程终止、晚到响应、删除墓碑和凭据候选等结果；生产 adapter 另做离线子进程契约测试。
- HTTP 集成与浏览器测试使用真实认证、房间权限、SSE 和 read model；模块集成通过深模块公开接口准备必要状态，不 mock 每表 repository。测试只断言外部可见状态、公开模块行为、云端 adapter 调用契约和持久恢复结果，不固定内部函数调用顺序、SQL 文本或私有模块形状，并须在保持公开行为不变的重构后继续成立。

### 2. HTTP、认证与安全集成

- 通过 Better Auth 标准 HTTP 入口覆盖注册、自动登录、重复账号称呼、邮箱登录、错误密码、原生生产限流、当前会话退出、多设备会话、会话过期滚动和主动改密。
- 固定 Better Auth 1.7.7 后验证默认密码范围、7 天有效期、1 天续期间隔、主动改密校验当前密码且默认不撤销其他设备会话。验证退出或会话过期不删除成员和歌单业务数据。
- 覆盖网易云扫码流程只能由发起点歌台账号和发起会话读取、轮询及完成；替代流程、过期流程、会话失效、跨账号尝试和浏览器伪造真实账号 ID 均不能提交绑定，服务端必须以核实后的真实账号为准，二维码及流程材料不得进入日志。
- 通过管理 CLI 到真实 HTTP 入口验证具权管理员登录、会话核验、设密与撤销分别执行、无权账号拒绝、完成后退出，以及 SSH/本机执行环境不能绕过组件鉴权。
- 验证 Cookie 的 HttpOnly、Secure 和同源属性；业务非 GET 对缺少、错误及正确 Origin 的处理；GET 无副作用；JSON/SSE/HTML 不缓存和静态哈希资产缓存策略。
- 验证 Bearer 和 Cookie 会话缓存未启用、邮箱验证与邮件找回入口不可用、改邮箱不可用，认证标准入口没有被不限流服务端转发替代。
- 以恶意房间名、昵称、搜索及导入文本验证 NFC、长度、控制字符拒绝和文本渲染；验证请求体总大小边界、日志不出现请求体及全部敏感字段。
- 从 HTTP 证明浏览器不能指定网易云凭据、真实账号调度键、任意歌单 ID、绑定代次、内部步骤或 Enhanced 模块，且待审批、非成员、已移除成员、普通管理员均不能读取房间资源。

### 3. 账号、房间与邀请

- 覆盖一个账号跨设备、跨房间担任不同角色，房间列表只含当前创建或加入的房间，房间名可重复，昵称按房间独立且当前成员唯一。
- 覆盖建房必须有有效网易云授权，并保留选择或确认当前已授权账号的步骤；浏览器不能借该步骤指定任意真实账号 ID。室友注册及加入不要求自己的授权，成员操作始终选择目标房间房主授权。
- 覆盖邀请链接 fragment 不进入服务端请求和访问日志；未登录后恢复邀请上下文；有效邀请码提交申请；申请前后均不能读取房间。
- 覆盖同账号同房间只有一份待处理申请、撤回、拒绝、批准、批准时昵称冲突、批准时容量变化，以及房主和室友的邀请/审批权限差异。
- 覆盖邀请重置同时撤销旧码、旧链接和旧申请但不影响当前成员；离开后必须用当前邀请重新申请，不自动恢复旧成员。
- 对全部容量做边界测试：上限前成功、达到上限明确拒绝、并发提交只有合法数量成功，且已有用户仍能登录、无数据被自动删除。

### 4. 歌单、导入与点歌

- 覆盖建房和审批不创建歌单；公共、房主个人和室友个人可按任意顺序配置；正常创建按返回 ID 自动绑定；同名目标不参与选择。
- 覆盖房主只能从真实账号清单绑定当前自建或收藏歌单；自建可维护、收藏只读；任意公开可读 ID 不足以绑定；室友专用歌单不能共用或绑定已有目标。
- 覆盖规范化共享快照：同一真实账号及歌单 ID 的多房间绑定看到相同集合与顺序但权限独立，旧读取不能覆盖新快照，部分列表和删除墓碑不能成为有效来源。
- 覆盖进入页面和手动刷新按需同步、并发刷新合并、读取失败保留快照及 syncedAt、页面与 SSE 查询不形成持续上游轮询。
- 覆盖文本导入 100 行接受、101 行整批拒绝、空行不计数、重复行计数、总码点边界、格式解析、普通连字符、五候选、默认第一条及异常分类。
- 覆盖改选确认、取消、跳过和预览均不写云端；重搜取消旧轮未发请求并丢弃晚到候选；搜索失败不自动重试；重启后短命搜索丢失。
- 覆盖仅按歌曲 ID 去重、同名不同 ID 共存、多行同 ID 只写一次、目标已有项跳过且不移动、逐首写后读回、混合成功/失败/未知和部分成功不回滚；覆盖提交前成员资格结束时拒绝并清除房间状态，以及成员仍有效但个人歌单归属、绑定代次、可写性或房主授权变化时明确拒绝并保留当前预览。
- 覆盖导入只写自己的可维护个人歌单，不写收藏或公共目标；入单结果不承诺可播放，也不承诺输入行顺序。
- 覆盖未配置个人歌单时房主和室友都可直接搜索点歌；公共搜索不创建或写个人歌单；个人来源失效、删除或待确认不阻塞直接搜索。
- 覆盖个人来源点歌必须读取当前归属、绑定和完整歌曲集合；歌曲移除、读取失败、绑定撤销和收藏关系失效均停止该路径，不能使用旧快照。
- 覆盖两条点歌路径都受成员、房主授权、公共目标、目标冲突和成员单操作限制；普通浏览器输入不能绕过服务端校验。
- 覆盖公共已存在歌曲不写不移动、不同成员标签分别记录、同成员重复不累计；读回失败不新增标签；歌曲已确认而标签失败时仅补标签。
- 覆盖标签补记前的公共歌曲、成员、授权及绑定核验；个人来源路径额外核验原来源，直接搜索路径不引入个人来源条件。
- 覆盖单首删除、批量删除二次确认、清空二次确认和执行开始集合；官方客户端后来新增歌曲不被循环追删，最终结果不为空时不得显示为空。

### 5. 调度、崩溃与不确定结果

- 使用脚本化 Enhanced adapter 从同源 HTTP 提交并观察：同账号严格串行且启动间隔至少 1 秒、不同账号最多两个并行、每账号 20 个操作边界、队满拒绝和全站执行上限。
- 构造一个长导入和多个短操作，证明每次上游请求后公平让出；证明同目标阶段不被冲突写穿插，其他目标在一个目标待确认时仍可推进。
- 覆盖共享目标跨房间统一阻塞、个人来源阻塞不扩散到直接搜索点歌、一个成员多设备不能绕过同房间单未完成写操作限制。
- 对每个外部调用前后、本地发送意图提交前后、adapter 返回前后及本地结果提交前后执行进程终止并重启。所有可能已发写入只能确认，尚未发步骤按权限决定是否继续，不得重复调用 adapter 写方法。
- 覆盖同幂等键同内容的原操作返回、同键不同内容冲突、24 小时后标识拒绝、来自未来标识拒绝，以及防重记录清除后旧键仍不能重放。
- 覆盖 HTTP 成功但业务失败、明确业务拒绝、普通错误、写超时、子进程无消息退出、写后同步失败和读回矛盾；只有明确拒绝可直接分类失败，其余可能已发结果保持待确认。
- 覆盖约 5 秒、30 秒、2 分钟三轮补查的次数和顺序而不要求精确墙钟时刻；三轮后停止自动请求，手动刷新只确认、不重发。
- 覆盖授权失效、同账号重新授权、扫码得到错误真实账号、更换账号、凭据代次晚到和成员/绑定撤销。旧结果不能覆盖新凭据、恢复旧实体或写入新目标。
- 覆盖风控暂停跨重启保持且只有管理员恢复；单目标权限错误不暂停整个账号；账号身份为空、账号不匹配、网络错误和目标权限返回不同稳定业务状态。
- 覆盖普通未知管理员终结只解除阻塞并显示结果未能确认；创建未知及专用删除未知不能用同一命令丢弃。
- 覆盖创建正常 ID 自动绑定、已获 ID 未关联的恢复、创建响应丢失不重建不猜同名、生命周期已结束时只转为必要专用清理。

### 6. 生命周期、SSE 与界面

- 覆盖室友退出和房主移除立即不可访问，硬删除昵称、本人标签、个人绑定和快照引用，只留下最小专用删除记录；重新申请获批后从零开始。
- 覆盖删房二次确认版本冲突、本地立即完成、邀请和申请失效、公共与室友专用歌单进入清理、房主已有及收藏绑定仅解除且其他房间共用不受影响。
- 覆盖删除明确业务成功直接完成；结果未知仅补查不重发；完整账号清单无目标且详情仍返回状态墓碑及旧歌曲时可按契约确认；任意 502、读取失败或矛盾证据不能假报成功。
- 覆盖未知删除由管理员明确授权一次新尝试、明确拒绝后原账号客户端手工处理及服务端核验、新账号永远不能处理旧清理。
- 覆盖 SSE 事件仅含失效元数据、同账号多端更新、断线重连全量读取、不补历史、会话失效关闭及成员撤销后旧事件不能读取资源。
- 用 Playwright 覆盖 320、390、900 和 1440px：默认公共歌单、宽屏固定侧栏、窄屏固定底栏、四个完整入口、滚动恢复、重按回顶、成员详情返回、各工具栏吸顶规则、虚拟键盘与弹窗遮罩。
- 覆盖房主与室友入口差异、审批角标 1 至 9 和 9+、未提交导入同房间切页保留、返回列表/跨房/退出账号/删房/刷新前提示并在确认后丢弃、不同标签页草稿独立、已提交操作跨页面恢复。
- 覆盖键盘完成注册、邀请、点歌、导入改选、审批和二次确认，检查语义名称、焦点顺序、可见焦点、弹窗焦点管理、WCAG 2.2 AA 对比度、无横向溢出和无控件重叠。
- 自动化浏览器至少运行项目固定 Chromium；上线前再在当前及前一主版本的桌面 Chrome、Edge、Firefox、Android Chrome 和 iOS Safari 完成兼容性抽查，并至少使用一台真实桌面和一台真实手机。

### 7. Adapter、负载与上线验收

- 生产 Enhanced adapter 的离线契约逐项验证 IPC 输入输出 schema、最小环境、私有临时目录权限、退出清理、硬截止、敏感 stdout/stderr 隔离，以及每个白名单业务写步骤最多一次出站写请求。
- 对固定 vendor 哈希和生产补丁做完整性检查，证明内部二次写、隐式环境凭据、敏感错误输出和二维码异常遮蔽均已移除；任何哈希或白名单变化使契约验收失效。
- 在目标 VPS 用真实临时测试数据验证 100 条 SSE、20 个活跃浏览器和 10,000 首快照的性能工作点，记录 p95、本地快照替换耗时、内存、交换和 OOM 情况。
- 自动化通过后，在本人批准的专用网易云账号和歌单范围内验收真实身份、跨账号隔离、完整读取、写后读回、收藏来源、官方客户端共存、重启恢复、队列公平和日志脱敏。不得用旧原型或超出批准范围的真实请求代替。
- 在实际部署环境验收 Caddy 版本、浏览器可信证书、自动续期、端口可达性、精确 Origin、代理信任、systemd 单实例、停机恢复、密钥/数据库缺失失败、初始化迁移和全部管理处置。
- 既有授权复用真实原型提供固定版本、小量双账号、收藏读取、客户端共存和删除墓碑的先验证据；既有交互原型提供四入口、320 至 1440px、草稿与权限交互的先验证据。二者是测试场景来源，不替代正式实现和部署验收。

## Out of Scope

- QQ 音乐、酷狗音乐及其他非网易云平台的授权、歌单接入和预先设计的平台适配框架。
- 网易云官方客户端的播放队列、自动播放、切歌、暂停、当前歌曲、播放进度、内置播放器、试听或音频传输。
- 房主电脑上的本地助手、代理、脚本、内网穿透或由官方客户端代执行的自动化。
- 旧匿名成员、单房间、房间独立网易云授权、浏览器身份恢复和公共点歌主动置顶/重排逻辑的兼容层或数据迁移垫片。
- 一个点歌台账号同时绑定多个网易云账号、房间级授权覆盖、室友提供自己的网易云授权，或同一真实网易云账号并行归属多个点歌台账号。
- 房主转让、房主退出自己的房间、房间恢复、离开成员档案、成员资格自动恢复或房间黑名单。
- 全站房间目录、房间搜索、按房间名加入、注册邀请码、建房邀请码、单人邀请、邀请自动过期或真人身份核验。
- 公共歌单绑定已有歌单、跨房间共用公共歌单、点歌台内公共删歌/清空/排序，以及把公共歌单当作播放队列。
- 室友绑定已有个人歌单、跨房间共用室友个人歌单、编辑别人的个人歌单、从别人的个人歌单点歌，或自动汇总个人歌单到公共歌单。
- 房主在点歌台编辑室友个人歌单、写入收藏来源、取消网易云收藏、删除作者歌单，或承诺共享歌单协作者的特殊写权限。
- 个人歌单手动排序、云端改名、歌单歌曲独立本地副本、旧快照自动补歌及歌曲顺序回放。
- 公共文本批量点歌、导入智能匹配、置信度评分、严格或唯一匹配、候选分页、改选弹窗重新搜索、搜索失败单行自动重试。
- 持久、跨设备或跨房间导入草稿，导入历史、点歌历史、操作历史、提交后取消、成功部分回滚或通过删歌撤销任务。
- 入单前试听、版权/VIP 可播放性筛选、播放成功保证、网易云接口强一致或官方客户端外部修改的原子阻止。
- 头像、加入时间、在线状态、最后活跃、辅助成员信息、歌曲统计、排行、投票或公开音乐社区功能。
- 唯一登录用户名、邮件验证、邮件找回、改邮箱、验证码、自定义账号失败锁定、持久认证计数、双重会话期限、首次强制改密或自制认证内核。
- 网页管理员后台、通用任意上游命令、任意 SQL 管理入口、多级审批、独立审计平台、用户行为分析或独立监控告警系统。
- 自动备份、异机备份、历史恢复、多节点、高可用、自动故障切换、多实例、PostgreSQL、Redis、容器化或独立 worker 服务。
- SSR、RSC、WebSocket、OpenAPI 稳定外部契约、通用工作流引擎、每表 repository 抽象或为未来需求预设的内部公共包。
- 旧浏览器支持、原生移动/桌面应用、商业化、服务等级保证、无限容量、抵御恶意长期积压或规避网易云风控的承诺。
- 在本规格阶段完成正式应用开发、真实生产部署、修改现有 VPS，或把已解决规划和旧原型视为上线验收通过。

## Further Notes

- 本规格汇总多房间网易云 MVP 的已确认产品、交互、并发恢复、安全运维和架构决议；这些决议之间如存在历史阶段性冲突，以最终解决评论和后续明确修订为准。
- 全文使用 CONTEXT.md 的领域术语。点歌台账号、账号称呼、成员、昵称、网易云绑定、网易云授权、歌单绑定、歌单快照、结果待确认和歌单清理任务均不可互换使用。
- “云端为唯一权威”表示歌曲集合与顺序必须来自有效完整网易云读取，不表示上游强一致，也不表示点歌台能阻止官方客户端在核验后继续修改。
- “结果待确认”既不是明确失败，也不是成功或可重试。所有涉及未知写入的产品文案、API 机器码、状态机和管理员命令都必须保留这一差异。
- 专用歌单删除确认不能假设详情接口必然返回 404。已验证删除样本可能继续返回状态墓碑和旧歌曲，也可能出现无快照的 502；完整同账号清单、当前身份和目标有效状态必须按既定契约综合判读。
- Better Auth 默认密码和会话行为已经针对固定 1.7.7 复核，正式接入仍需自动化验证。采用默认策略是明确产品决策，不得重新加入旧 6 至 12 位密码、30 天空闲、90 天绝对期限、改密撤销其他设备或临时密码强制改密。
- 全站容量、并发、队列、请求间隔、超时、补查时间、机器资源和性能指标都是首版待验收工作点，不是网易云安全阈值、永久容量保证或当前服务器已取得的事实。
- 真实网易云验收必须继续采用本人授权、专用测试歌单、低频串行和事前确认范围；自动化只能在 Enhanced adapter 接缝模拟无法安全诱发的异常。
- 当前没有已核实的生产 Caddy、证书、入口、端口和机器资源事实。浏览器可信 HTTPS、证书自动续期和资源工作点未实际通过前，不得上线或退回明文 HTTP、忽略证书告警。
- 不做备份是首版自用范围取舍，不改变正常运行及重启时的持久化要求，也不允许因容量、时间或运维方便丢弃未解决恢复和清理任务。
- 旧授权复用原型和响应式交互原型提供重要先验证据，但没有实现正式房间权限、持久操作、生产隔离或真实部署。后续开发必须依据本规格重新完成自动化和上线验收。
- 本规格已达到 `ready-for-agent`：产品与架构决策无待提问分支。实现阶段如发现固定依赖行为与已核查事实不一致，应停止相关上线工作、记录可复验证据并回到决策层处理，不能用兼容层或静默降级掩盖。
