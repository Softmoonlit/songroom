## Question

房主授权并绑定点歌歌单、室友通过邀请和昵称加入、搜索并点歌、查看点歌人标签，以及房主删除/清空/拖动排序的核心网页体验应如何呈现，才能在手机与桌面浏览器上清楚表达权限、进行中状态、并发刷新和失败结果？

原型应覆盖空状态、初始歌单无标签、多人标签、已有歌曲再次置顶、授权失效、邀请失效、网易云写入失败和房主破坏性操作确认，并通过真人反馈收敛交互，不实现正式后端。

## Comments

### 安全决策入口与首页问题

[确定公网房间与网易云授权安全边界](06-decide-public-room-and-auth-security.md#解决评论最终安全规则已确认) 已解决。用户追问部署后房主首次进入首页显示什么，是否只有登录按钮。本轮只记录问题与待验证建议，不解决本原型票。

建议按身份和初始化状态分流：无有效身份且不带邀请时，显示简洁的点歌台房主密码登录表单，而不是先点按钮再打开表单；有效邀请打开室友昵称加入页面；已登录但尚未绑定的房主进入扫码、确认账号、选择或创建歌单及分享邀请的首次设置流程；已有有效身份且房间已设置时进入实际点歌界面。未授权或已退出但曾有绑定的房间显示标注状态的最后快照和房主重新授权操作，不作为全新房间重新初始化。

以上页面构成与布局仍待本票据的人类原型反馈确认。未认证页面不展示房间数据，不提供公开创建房间、室友注册或无邀请加入入口。原型还需覆盖退出、更换网易云账号、单独踢出、更换邀请及撤销全部室友访问，并准确呈现各动作的数据与权限边界。
