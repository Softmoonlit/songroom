# 确定室友身份与点歌人标签生命周期

Type: grilling
Status: resolved
Assignee: Codex

## Question

点歌台应如何识别通过邀请加入的室友，并如何定义点歌人标签的完整生命周期，包括昵称唯一性、同一成员重复点歌、成员重新进入或改名、初始歌单歌曲、多个成员点同一首歌、歌曲删除后重加，以及标签跨浏览器和跨房间会话的保留规则？

答案必须让点歌人标签可以稳定映射到成员身份，而不是仅依赖可重复、可随时变化的显示昵称。

## Comments

### 第一轮确认：成员身份、昵称唯一性和歌曲生命周期

用户已确认以下决定，后续问题仍待讨论，票据保持开放。

- 成员身份独立于昵称且保持稳定。同一浏览器保留身份后继续使用；换浏览器或清除浏览器数据后默认创建新成员。首版不支持跨设备身份合并，也不允许输入同名接管旧身份；旧标签不转给新成员。
- 同一房间内昵称唯一，忽略首尾空格和英文字母大小写后判重。成员离开或长期不用不会自动释放昵称。
- 绑定时已有歌曲及通过网易云官方客户端等外部入口加入的歌曲没有点歌人标签。房主只有主动通过点歌台点歌时才成为点歌人；房主一般在电脑端官方客户端控制，不自动把这些操作算成房主点歌。
- 歌曲确认删除后清除旧标签，重新加入只记录本次及之后的点歌人；确认清空歌单同样清除全部标签。外部删除采用同一标签语义，删除发现机制由“确定外部歌单变更的协调规则”决定。

### 第二轮确认：改名、重复点歌和跨会话保留

用户对本轮三项建议全部表示同意。决策分支已收敛，待最终汇总确认后关闭票据。

- 成员可以修改自己的昵称，不改变身份，所有现存标签显示当前昵称。新昵称仍须唯一；改名成功后释放旧昵称，旧标签不转给后来使用该昵称的其他成员。
- 每次成功点歌都将歌曲置顶，标签按成员身份去重，并按各成员首次成功点该歌曲的先后排列。同一成员再次点歌不改变标签顺序，不显示次数或时间标记，也不提供单独撤回标签。
- 房间持续存在，不按日期或页面访问划分新会话。关闭页面、隔天返回、服务重启、房主重新扫码均不主动清除成员或标签。有有效身份凭据时延续原身份；凭据丢失或失效后默认新成员，旧标签仍归原成员。
- 如果提供更换绑定歌单的操作，重新绑定同一份歌单不主动清除标签，按实际歌曲增删协调；改绑另一份歌单则保留房间成员和昵称，但清除原歌单全部标签，新歌单已有歌曲均无标签。本决定不新增必须提供换绑入口的需求。
- 身份凭据有效期与撤销机制由“确定公网房间与网易云授权安全边界”决定；点歌成功判据、并发先后和失败后的标签提交由“确定并发点歌与失败一致性规则”决定。

### 解决评论：最终规则已确认

用户已确认完整汇总，本票据已解决。以下为最终决策，前两轮评论保留为讨论记录。

1. **成员身份与昵称分离**：成员具有稳定身份。同一浏览器保留有效身份凭据时延续原成员；换浏览器、清除数据或凭据失效后默认新成员。不支持跨设备合并或同名认领，旧标签不转移。
2. **昵称在房间内唯一**：忽略首尾空格和英文字母大小写后判重。离开或长期不用不会自动释放昵称；主动改名成功后释放旧昵称。
3. **改名保留身份与标签**：成员可以修改自己的昵称，现存标签统一显示当前昵称。新昵称仍须唯一；后来使用旧昵称的成员不会继承旧标签。
4. **标签只来自点歌台点歌**：绑定时已有歌曲及通过官方客户端等外部入口加入的歌曲无标签，不推断点歌人。房主主动通过点歌台点歌时按相同规则记录；房主通常在电脑端官方客户端控制，这些操作不自动生成房主标签。
5. **每次成功点歌置顶，标签按身份去重**：多名成员可共同成为同一首歌的点歌人，按各成员首次成功点该歌曲的先后显示。重复点歌不改变标签顺序，不显示次数或时间标记，也不提供单独撤回标签。
6. **删除结束标签生命周期**：歌曲确认删除后清除对应全部标签；确认清空歌单则清除全部标签。歌曲重新加入只记录本次及之后的点歌人，不恢复旧标签。已确认的外部删除采用同一语义。
7. **房间跨会话持续存在**：关闭页面、隔天返回、服务重启、房主重新扫码均不主动重置成员和标签。凭据丢失或失效后，原成员与旧标签仍保留，新加入者不能接管其昵称或标签。
8. **歌单绑定边界**：如果提供换绑操作，重新绑定同一歌单不主动清除标签，按实际歌曲增删协调；改绑另一份歌单时保留房间成员与昵称，清除原歌单标签，新歌单已有歌曲均无标签。本票据不要求新增换绑入口。
