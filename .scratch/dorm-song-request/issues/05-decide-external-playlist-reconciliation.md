# 确定外部歌单变更的协调规则

Type: grilling
Status: resolved
Assignee: Codex
Blocked by: 03, 04

## Question

当房主在网易云官方客户端或其他入口直接增加、删除或重排点歌歌单时，点歌台应如何发现并协调这些外部变更，以及如何处理没有点歌人标签的外部歌曲、已被外部删除歌曲的标签和点歌台页面中的陈旧顺序？

答案必须指定网易云云端歌单与点歌台数据库各自拥有的数据、同步触发方式、冲突优先级和允许的短暂不一致窗口。

## Comments

### 第一轮确认：检查时机、未观察到的删除与陈旧排序

用户将定期检查间隔调整为一分钟，并同意其余建议；本票据仍开放，等待后续分支讨论与最终汇总确认。

- 有页面在线时每分钟检查一次，无人在线时停止定期检查。首次打开、页面重新回到前台、房主重新授权和手动刷新时触发检查；每次写操作前重新读取完整云端歌单，不根据页面旧数据直接写入。
- 正常情况下，在线页面允许约一个检查周期的陈旧状态；接口失败时不承诺该窗口，页面必须明确显示尚未同步。无人在线期间不承诺及时发现外部变更，重新进入时检查。
- 标签生命周期以点歌台确认删除为边界。外部删除又加回若完全发生在两次检查之间、点歌台未观察到歌曲缺席，则保留旧标签，不根据顺序变化推测删除；已确认删除后重新加入不继承旧标签。
- 房主提交完整排序时，若最新云端歌曲集合或顺序与其操作依据不同，拒绝该次排序，刷新歌单并要求基于新状态重新操作。不覆盖新状态，也不自动合并；仅昵称或标签变化不使排序失效。
- 检查后、实际写入期间发生的外部修改仍待讨论；写入成功判定与标签提交的具体机制由“确定并发点歌与失败一致性规则”决定。

### 第二轮确认：删除证据、检查失败与歌单不可用

用户同意本轮全部建议；本票据保持开放，等待并发外部修改边界及最终汇总确认。

- 一次成功且完整的云端读取足以确认歌曲缺席，并清除对应标签；确认歌单确实为空则清除全部标签。超时、错误响应或不完整结果不能作为删除证据，也不能按空歌单处理。
- 检查失败时保留最后一次确认的歌单及标签，页面显示同步异常和上次成功时间，不宣称数据最新。任何写操作仍须先成功读取最新云端歌单；读取失败不执行写入，并反馈暂时无法操作。普通网络错误不要求重新扫码，后续检查成功后恢复。
- 整份歌单被删除或不可访问时，标记歌单不可用并停止写入，但保留绑定信息、成员和标签，由房主处理权限、授权或歌单问题。不自动创建替代歌单或换绑。原歌单恢复后按完整读取结果协调；改绑另一份歌单则清除原歌单标签。

### 第三轮确认：外部并发修改与陈旧删除、清空

用户同意本轮全部建议，全部决策分支已收敛，待完整汇总确认后关闭本票据。

- 接受当前接口对官方客户端与点歌台并发编辑只能尽力协调的限制，不承诺双方修改不会互相覆盖；写前检查和写后校验不构成原子保护。房主应避免在点歌台写入期间同时通过官方客户端编辑歌单，正常播放不受此限制。
- 日常检查接受云端当前歌曲与顺序，并协调本地标签，不将旧顺序或旧歌曲集合重新写回云端。
- 写后结果与目标不符时，不盲目重复完整排序来争夺顺序；读取并展示云端实际状态，反馈本次操作未能确认成功。成功判据、部分成功后的标签提交和具体重试规则由“确定并发点歌与失败一致性规则”决定，不由本票据提前指定。
- 单首删除按明确歌曲 ID 在最新歌单上执行；目标已不存在时不再调用删除接口，按最新状态协调标签。其他歌曲的增删或重排不单独导致该次单首删除被拒绝。
- 清空与完整排序一样，要求最新歌曲集合和顺序与操作依据一致；若已变化，拒绝操作、刷新页面，请房主重新确认，避免删除其未看见的新歌曲。

### 调查证据：条件写入与读取缓存边界

核查范围为“验证点歌歌单写入语义”采用的 Enhanced `4.40.1`，提交 `a8c781fd64faab17fedfd46e0615a2609307f163`；本次未操作真实账号。

- [`song_order_update.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/a8c781fd64faab17fedfd46e0615a2609307f163/module/song_order_update.js) 只提交歌单 ID、完整歌曲 ID 序列和操作类型；[`playlist_tracks.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/a8c781fd64faab17fedfd46e0615a2609307f163/module/playlist_tracks.js) 未提供已定义的版本号或条件写入参数。当前接口没有可依赖的原子拒绝陈旧写入保证；不据此断言网易云不存在未公开机制。
- 写前读取只能发现读取时已存在的变化，不能保护读取后到写入之间的窗口；点歌台串行化不能约束官方客户端。写后精确匹配也不能证明期间未覆盖外部排序。
- [`server.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/a8c781fd64faab17fedfd46e0615a2609307f163/server.js#L265) 默认使用两分钟 HTTP 路由缓存；[`util/apicache.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/a8c781fd64faab17fedfd46e0615a2609307f163/util/apicache.js#L650-L678) 的缓存键不包含 POST body，并支持绕过缓存。同步和写后验证必须读取不经这层缓存的结果，写操作也不能复用缓存响应；具体调用方式留给架构与一致性票据。绕过缓存不等于保证上游强一致读取。
- [`playlist_detail.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/a8c781fd64faab17fedfd46e0615a2609307f163/module/playlist_detail.js) 读取 `trackIds`；[接口文档](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/a8c781fd64faab17fedfd46e0615a2609307f163/public/docs/home.md#L1232) 声明 `trackIds` 完整，但 `tracks` 不保证完整。`playlist_track_all` 默认只取 1000 首，不能直接作为全量成员关系的依据。完整性校验须针对歌曲 ID 序列，不能以歌曲详情缺失判断歌曲删除。
- 既有原型直接调用模块、不经过 HTTP 缓存，实测 200 首及 19 次写后读取没有陈旧结果；这不构成上游所有规模与并发场景的强一致保证。

### 解决评论：最终规则已确认

用户已确认完整汇总，本票据已解决。以下为最终决策，前述轮次保留为讨论记录；接口依据见本票据“调查证据：条件写入与读取缓存边界”。

1. **数据权属**：网易云云端歌单是歌曲集合与顺序的权威来源；点歌台数据库拥有成员、昵称和点歌人标签。本地歌单快照只用于展示、比较与协调，不用于自动恢复旧云端状态。
2. **检查时机**：有页面在线时每一分钟检查一次，无人在线时停止定期检查。首次打开、返回前台、重新授权、手动刷新时检查；每次写操作前重新读取完整云端歌单。
3. **不一致窗口**：正常在线情况下允许约一个检查周期的展示延迟。无人在线或接口异常期间不承诺及时同步；检查失败时页面显示同步异常及上次成功时间，不宣称数据最新。
4. **外部增删与标签**：外部新增歌曲没有标签，外部重排不改变标签。一次成功、完整的读取确认歌曲缺席后清除其标签；确认空歌单则清除全部标签。未被观察到的删后重加保留旧标签，不推测删除历史。已确认删除后重新加入的歌曲不继承旧标签。
5. **读取失败与歌单不可用**：保留最后确认的歌单、标签和绑定信息，不把错误或不完整结果当作空歌单。无法取得最新完整歌单时不写入。歌单不可用时由房主处理，不自动创建替代歌单或换绑；原歌单恢复后按完整读取结果协调，改绑另一份歌单则沿用已定的标签清除规则。普通网络错误不要求重新扫码，后续检查成功后恢复；授权失效仍须停止写入并重新授权。
6. **陈旧管理操作**：完整排序和清空要求最新云端歌曲集合与顺序和操作依据一致，否则拒绝并刷新，请房主重新操作。单首删除按歌曲 ID 在最新歌单上执行；目标已不存在则不再发送删除请求，按最新状态协调标签。仅昵称或标签变化不使排序、清空失效。
7. **外部并发冲突**：接受当前接口无法原子防止官方客户端与点歌台互相覆盖的限制。写后结果不符时展示云端实际状态，反馈未能确认成功，不盲目重写争夺顺序。正常检查不把旧顺序或歌曲集合写回云端；房主应避免两个入口同时编辑，正常播放不受影响。写前检查与写后匹配都不能证明期间没有覆盖外部修改。
8. **读取与缓存约束**：协调依据完整歌曲 ID 序列，而非可能缺失的歌曲详情。同步读取、写前读取、写后校验必须避开 Enhanced 默认缓存，写操作也不能复用缓存响应。避开缓存不构成网易云上游强一致读取保证。
