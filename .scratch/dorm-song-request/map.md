# 宿舍点歌台决策地图

Label: wayfinder:map
Status: wontfix

## Destination

形成一份可直接进入开发的 MVP 产品与技术规格：房主在公网点歌台授权网易云账号并绑定专用点歌歌单，受邀室友通过昵称协作点歌，系统可靠维护云端歌单顺序与点歌人标签。

规格必须明确用户流程、权限、数据模型、第三方接口边界、并发与失败语义、安全边界、部署方式、交互方案和验收标准。

## Notes

- 本地图记录此前单房间努力，现因用户将目标扩为多房间、账号身份、双类型歌单和用户级授权复用而停止推进；当前规划见[多房间点歌台决策地图](../multi-room-song-request/map.md)。下述旧范围与已解决评论仅作历史记录，不作为新规格的现行规则。

- 领域采用根目录 [`CONTEXT.md`](../../CONTEXT.md) 中的术语；每次处理票据时先读取该文件，并按票据类型使用 `grilling`、`prototype` 或 `domain-modeling`。
- 首版只服务一个宿舍、一个房主、一个房间，同一时间只绑定一个点歌歌单并使用一个网易云账号，通过公网 VPS/云服务器提供服务。
- 房主使用自己的日常网易云主账号，并明确接受非官方接口可能造成的风控、失效或账号处罚风险。
- 房主扫码授权后选择或创建专用点歌歌单；Cookie 只保存在服务端，不进入浏览器、URL 或日志。授权失效时停止写操作并要求房主重新扫码。
- 室友通过不可猜测且可重置的邀请链接加入，以临时昵称参与，不注册账号。
- 室友和房主都可以点歌：新歌加入点歌歌单第一位，已有歌曲移到第一位；同一成员不会形成重复标签，多名成员可以共同成为同一首歌的点歌人。
- 室友不能删除、清空或任意排序；房主可以删除、清空和任意排序。不记录歌曲归属，不提供撤销。
- 点歌人标签保存在点歌台自己的数据库中，网易云歌单只保存歌曲和顺序。
- 点歌台不读取或控制播放队列。房主自行使用网易云官方客户端播放并处理刷新或重新播放。
- 账号与接口风险已由房主接受，但规格仍须使用最小权限、写入限流、串行化和错误校验降低非必要风险。

## Decisions so far

- [确认网易云接口能力与账号风险](issues/01-confirm-netease-api-capabilities-and-account-risk.md)：Enhanced 覆盖登录、搜索及云端歌单增删排序，但属于无稳定合同的非官方接口，房主选择接受主账号风险。
- [确认能否远程控制官方客户端播放队列](issues/02-confirm-remote-official-client-queue-control.md)：没有可从服务端可靠控制指定桌面客户端当前队列的 API，因此播放控制不进入产品边界。
- [验证点歌歌单写入语义](issues/03-verify-playlist-write-semantics.md)：真实账号实测确认完整序列写入与回读校验可可靠维护 200 首点歌歌单，但子集排序、重复添加和动态限流要求串行化及按最终云端状态判定成功。
- [确定室友身份与点歌人标签生命周期](issues/04-decide-member-identity-and-attribution-lifecycle.md#解决评论最终规则已确认)：成员身份独立于可改昵称，标签按身份去重并显示当前昵称，随歌曲删除清除，房间跨会话延续。
- [确定外部歌单变更的协调规则](issues/05-decide-external-playlist-reconciliation.md#解决评论最终规则已确认)：云端为歌曲与顺序的权威来源，在线每分钟检查，以确认缺席清除标签，拒绝陈旧排序与清空，并接受外部并发编辑的接口限制。
- [确定公网房间与网易云授权安全边界](issues/06-decide-public-room-and-auth-security.md#解决评论最终安全规则已确认)：独立房主登录与邀请成员凭据明确权限和撤销，支持退出与换账号，隔离网易云凭据，并要求上线前实测官方客户端并存。

## Not yet specified

- 核心交互完成原型后，再判断是否需要操作历史、最近点歌或成员状态等辅助界面；这些能力目前不足以形成独立、精确的问题。
- 部署与一致性方案确定后，再明确上线检查、监控和恢复手册的具体深度。

## Out of scope

- [确定并发点歌与失败一致性规则](issues/07-decide-concurrency-and-failure-consistency.md)：旧主动置顶与完整排序写入流程已取消，新范围需处理多房间授权复用和快照同步。
- [原型验证核心操作体验](issues/08-prototype-core-web-experience.md)：单房间匿名成员界面不再是目标，由多房间账号和双类型歌单原型接替。
- [确定部署运维与故障恢复方案](issues/09-decide-deployment-operations-and-recovery.md)：单宿舍规模假设已替换，需要多账号、多房间配额和凭据隔离。
- [确定 MVP 系统架构与规格边界](issues/10-decide-mvp-architecture-and-spec-boundary.md)：原单房间规格不是当前交付目标，由多房间完整规格接替。
- [决定 MVP 点歌歌单容量策略](issues/11-decide-mvp-playlist-capacity-policy.md)：原先以完整排序规模为核心的容量策略不直接适用，新导入与同步票重新确定限制及证据门槛。
- [验证扫码授权与官方电脑客户端共存](issues/12-verify-qr-and-desktop-session-coexistence.md)：仍须验证并存，但由新增的授权复用、账号隔离与客户端共存原型统一承接。
