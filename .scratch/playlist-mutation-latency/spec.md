# 歌单修改延迟修复

**Status:** resolved

## 已确认决策

用户要求修复添加、删除、点歌等歌单修改延迟，并精简重复身份核验及固定一秒间隔。本规格替代旧 MVP 规格中的固定启动间隔工作点；保留同真实账号写入严格串行、全站最多两个活动账号、公平轮转、每账号持久操作容量及风控暂停。明确标记的 `playlistDetail` 只读同步任务可在同账号最多四个读槽内并行，且不与同账号写入重叠。

- 普通网易云请求不提前加载未使用的反作弊 token 模块；实际启用 token 的请求仍按需加载并逐次获取 token。每次调用仍采用独立短命进程、私有临时目录、显式凭据和受审 vendor 完整性校验。
- 请求完成后立即允许同账号下一项取得执行权，不添加替代固定等待或推测性自适应限流。明确风控仍暂停账号，管理员明确恢复。
- 只读 `playlistDetail` 同步（公共歌单、个人歌单、明确的只读确认）使用独立读槽：同一真实账号最多四个只读请求并行，仍受全站最多两个活动真实账号限制，并且不能与该账号写入或默认串行任务重叠。其他默认内存任务不自动获得并行资格。
- 日常个人单首删除、公共点歌、随机换歌及后台下一首播放复用扫码绑定或重新授权时确认的账号身份，不逐次请求 identity。保留本地成员、账号、授权 ID/代次、绑定和云端目标归属核验。扫码、重新授权、歌单创建和管理员异常核查的身份读取不在本次删除范围内。
- 删除继续读前核验目标并写后读回；公共逐首点歌继续实时核验本人来源及歌曲；下一首继续实时核验播放锚点。发送前、异步返回后复核相关本地条件，授权失效或代次变化不能使用旧凭据写入。
- 写后云端歌曲集合和排列顺序为权威，未知写入不重发，补查、撤权和晚到响应隔离继续有效。
- SSE 仅使 JSON read model 失效。个人歌单、个人歌曲操作及随机换歌完成事件及时刷新；取消事件前的在途旧读取，避免复用旧结果。一个 read model 的版本不能提前消费其他 read model 的共享事件；保留轮询应对事件丢失。

## 测量依据与范围

诊断时线上部署为 faad60b：最近八次个人添加 1.91–2.18 秒，排队中位约 5 毫秒；一次公共点歌 1.97 秒。VPS 无网络离线测量，每次进程及 vendor 初始化约 0.65–0.80 秒，其中 jsdom 一次剖面占 409 毫秒；按需加载 token 后对照进程初始化约 0.27–0.32 秒。上述是诊断样本，不承诺真实云端端到端时延或网易云安全请求频率。
