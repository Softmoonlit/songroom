# 工单 03：抽选并行同步与点歌状态感知优化

Status: need-review

## 目标

在不使用旧快照放行点歌或随机换歌的前提下，缩短首次随机预览和个人歌单点歌的用户等待。

## 已确认边界

- 随机预览必须先向网易云同步公共歌单和所有选中成员个人歌单，再从本次同步写入的最新本地快照抽选。
- 快照超过 60 秒时仍必须重新同步；60 秒内的重新抽选才复用本次已核验快照。
- 点歌必须实时读取并校验本人来源歌单归属、绑定代数和歌曲仍在来源歌单中；来源读取失败不得凭旧快照放行。
- 写入操作和默认上游任务保持同账号串行；只读 `playlistDetail` 同账号使用独立并发读槽。

## 验收清单

- [x] 随机预览同时发起公共歌单与所有已选成员个人歌单的刷新。
- [x] 只读刷新并发槽最多 4 个，仍禁止与同账号写入或默认串行任务重叠；全站活动账号约束保留。
- [x] 刷新完成后仅使用数据库中本次刷新得到的最新快照，不把旧快照当作刷新成功结果。
- [x] 60 秒内重复抽选零上游请求；超过 60 秒重新同步。
- [x] 个人歌单点歌状态查询轮询从 2500ms 缩短为 600ms；来源实时核验流程保持不变。
- [x] 个人歌单页面切换只读取本地快照，不自动触发网易云同步；显式点击“同步歌单”才发起上游读取。
- [x] 随机预览区分首次“正在同步歌单…”和已有预览后的“正在核验歌单…”，不把上游核验耗时伪装成随机算法等待。
- [ ] 部署后记录真实网易云请求耗时，确认并发读槽对首次抽选的实际收益及网易云风控表现。

## Comments

### 实现记录

1. `upstream-scheduling.ts` 增加明确的 `kind=read` 内存任务；只读任务不占用账号写锁，可在最多 4 个读槽内并行。写入、恢复和其他默认内存任务仍按账号串行。
2. `public-random-preview.ts` 使用 `Promise.all` 同时刷新公共来源和所选成员来源；任一来源失败仍使整次预览失败。
3. `PersonalPlaylistPane.tsx` 将异步点歌操作的轮询间隔改为 600ms。由于当前 SSE 会即时触发操作查询，轮询仍只是丢事件时的恢复路径。
4. 已增加调度器同账号只读并发测试和随机预览三路并发刷新测试。
5. 生产复盘确认 60 秒新鲜窗口内重复抽选通常为毫秒级；超过窗口重新向网易云核验时约为秒级，保留实时核验边界并改进阶段提示。个人歌单切页不再隐式触发刷新，减少页面切换时的长时间加载感知。

### 验证记录

- 随机预览与调度器专项测试：25 项通过。
- TypeScript 三套配置检查通过。
- 替换专项、应用全量测试和相关 E2E 已在本轮其他工单记录中验证；合并前需重跑统一验证。

### 剩余事项

- 需要部署后根据 `public_playlist_replacement` 阶段日志和随机预览请求耗时调整读回/读槽参数；不凭单次请求主观修改。
- 点歌来源核验仍为必要的实时一致性步骤，不通过删除该步骤换取表面速度。
