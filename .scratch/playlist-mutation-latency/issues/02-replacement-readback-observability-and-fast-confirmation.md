# 工单 02：随机换歌阶段观测与读回延迟优化

Status: need-review

## 目标

在保持批量清空、清空读回、批量添加、最终读回四步安全边界的前提下，减少正常云端最终一致性造成的无谓等待，并让页面及时显示当前阶段。

## 验收清单

- [x] 删除、删除后读回、添加、添加后读回仍保持严格顺序，不并发同一公共歌单的读写。
- [x] 写入接口明确成功但读回仍显示旧状态时，使用独立短确认窗口 `500ms / 1.5s / 5s`。
- [x] 写入超时、断连、进程中断等未知结果仍使用 `5s / 30s / 120s` 补查，不重发写入。
- [x] 短读回确认状态持久保存为 `step=confirming`，服务重启后保留下一次检查时间；未知写入仍恢复为 `step=unknown`。
- [x] 删除和添加发送前、读回前立即发送操作 SSE 失效通知，前端分别显示清空确认和加入确认阶段。
- [x] 记录排队等待、删除写入、删除读回、添加写入和添加读回阶段耗时；指标上报失败不影响操作恢复。
- [x] 增加正常读回延迟测试，验证不提前添加、不重发写入且最终成功。
- [x] 换歌确认后保留弹窗，阶段状态和终结结果在弹窗内展示；终结后由用户关闭，后台不再重复显示状态卡片。
- [x] 稳定公共歌单查询键并限制终结操作副作用只执行一次，避免成功后的失效循环造成请求风暴。

## Comments

### 实现与验证记录

1. `public-playlist-replacement.ts` 保留四次云端交互，不采用删除/添加并发或跳过清空验证；写入响应仍只视为接受，不当作最终云端状态。
2. 正常读回不一致与未知写入分离：前者短确认，后者继续使用原有长补查预算。
3. `PublicPlaylistPane` 的操作状态现在能通过 SSE 及时显示“正在确认旧歌已清空”或“正在确认新歌已加入”。
4. 生产模式输出不含凭据的阶段 JSON 指标，字段包含操作 ID、阶段、结果和耗时；测试模式不输出日志。
5. 已通过替换操作专项测试、随机换歌文案测试、应用全量测试、TypeScript 类型检查和随机换歌/个人点歌相关 E2E；部署后的阶段耗时观察仍待完成。
6. 生产复盘发现替换成功后页面查询键每次渲染变化，终结副作用反复失效公共歌单查询；现已稳定查询键并按操作 ID、状态和版本去重处理，避免再次形成请求风暴。
7. 替换确认不再立即关闭弹窗；处理中禁止关闭，成功、失败或终止后在弹窗内显示最终结果，用户关闭后才返回点歌台。

### 剩余事项

- 需要部署后从生产日志观察各阶段真实耗时，再决定是否调整短确认窗口；不根据单次请求主观改动窗口。
- 未引入新的原子替换接口；受审网易云接口仍不提供可用的原子覆写能力。
