# 随机点歌抽选与批量替换调整

## 已确认规则

- 随机抽选不区分新歌与旧歌，不要求结果至少含一首当前公共歌单没有的歌曲；全部候选均在公共歌单中时仍可随机点歌。
- 沿用已有成员尽量均分、余数随机分配、歌曲 ID 全房间去重、交叉候选调整归属、候选不足重新分配规则，仅移除新旧优先级及无新歌拒绝条件。
- 选好歌曲及来源成员后，对整组歌曲洗牌，不保证成员交错，不另外调用排序接口；允许同一成员歌曲相邻。
- 正常执行方向：保存本轮目标清单及必要恢复信息 → 批量清空当前公共歌单歌曲 → 批量添加本轮歌曲 → 读回核验。
- 清空只移除歌曲，保留公共歌单 ID 及绑定，不删除重建歌单；个人歌单不受影响。
- 用户明确接受清空成功、添加失败时公共歌单暂时为空；不自动回滚旧歌曲。
- 预览清单不承诺最终云端顺序；最终页面以网易云读回顺序展示，顺序与提交列表不同可以接受，不触发纠正排序。
- 成功需确认目标歌曲集合完整，不把批量响应成功直接等同于每首歌曲已存在；部分成功必须据实反馈。
- 任一写入结果未知时只读补查，不盲目重复发送。清空结果未知时先确认，再决定能否进入添加阶段。
- 正常路径以减少请求为目标；实际延迟与批量行为需要验证，不承诺固定秒数。
- 其余现有预览确认、来源有效性、权限、冲突协调、标签归属及恢复边界继续适用。清空确认移除后旧标签结束生命周期，重新加入歌曲只按本轮最终来源成员添加标签。

## 代码事实及实现验证事项

- 现有应用适配器的 trackAdd/trackRemove 各接收一个 songId；受审 vendor 的 playlist_tracks 入口可接收逗号分隔歌曲 ID 列表，再传入网易云接口。
- 当前随机替换逐首增删并读回，需要调整为批量步骤及持久状态，不引入另一套后台执行机制。
- vendor 接受列表不等于云端提供批量原子性；必须覆盖批量部分成功、结果未知、进程重启及清空后失败。
- 历史实测观察到批量添加逆序插入，不作为云端接口顺序保证；本方案接受读回顺序差异，因此不依赖逆序技巧。
- 需核实批量清空、添加的请求上限和实际行为；空歌单跳过清空，批量不能假装原子整组替换。

## 确认记录

用户确认不区分新旧随机选歌，优先减少请求；接受整组洗牌后云端实际排列，不要求成员交错或额外排序；明确接受清空成功、添加失败时点歌台暂时为空。
