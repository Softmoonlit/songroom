# 02：随机点歌改为批量清空后批量添加

**What to build:** 房主确认一组随机歌曲后，点歌台保存必要执行依据，批量清空公共歌曲，再批量添加目标歌曲并读回核验；保留公共歌单及个人歌单，不额外排序。页面准确呈现执行进度及失败、部分成功、结果待确认状态。

**Blocked by:** 无，可立即开始；接收已有预览目标清单即可独立验证，可与工单 01 并行。

Status: ready-for-agent

- [ ] 将批量增删贯通受审网易云适配器、现有持久操作和页面反馈；复用既有依赖与调度，不建立平行后台执行机制。
- [ ] 发送前持久保存确认的目标歌曲、来源归属、原歌单依据和必要执行步骤；正常流程为批量清空、批量添加、最终读回核验，空歌单跳过清空。
- [ ] 清空只移除公共歌曲，保留歌单 ID 和绑定，不删除重建歌单，不修改任何个人歌单。
- [ ] 清空的明确成功与未知结果分开处理：未知时先只读确认，不盲目继续添加或重发清空；不能仅凭批量接口接受列表就假定云端原子成功。
- [ ] 添加后按实际读回核验目标歌曲集合完整，顺序不同不视为失败、不发送排序请求；完整成功不能仅依赖批量成功响应。
- [ ] 清空成功、添加明确失败时允许点歌台暂时为空，不自动恢复旧歌曲；批量部分成功据实展示，停止后续写入，不自动重放缺失歌曲。
- [ ] 发送后超时、断连或进程中断按可能已发送处理，沿用现有只读补查预算及重新授权恢复边界，不自动重发未知写入。
- [ ] 沿用预览失效、成员及绑定有效性、账号级串行调度、同目标冲突和暂停控制；外部并发导致集合变化时据实反馈，不通过清理意外歌曲掩盖冲突。
- [ ] 清空确认移除后结束旧标签生命周期；重新加入歌曲仅按本轮最终来源成员记录标签，集合、标签或步骤未完成时不提前报告完整成功。
- [ ] 页面正确区分处理中、清空后待添加、部分成功、明确失败与待确认，并在完成或异常后更新云端实际快照。
- [ ] 直接清理旧随机替换逐首执行路径，不添加逐首回退或兼容层；普通逐首点歌和个人维护不扩大改动范围。
- [ ] 自动化覆盖批量正常路径、部分成功、清空后失败、未知结果、重启、授权变化、标签生命周期和冲突；完成类型检查及必要审查。

## Comments

- 用户明确优先减少请求，接受清空成功后添加失败导致公共歌单暂时为空；接受洗牌后云端实际顺序，不要求成员交错或额外排序。
- 本工单可使用既有抽选清单独立验收，抽选规则变更由工单 01 负责；两者合并后的完整验收由工单 03 负责。
- 本工单尚未实施。批量请求上限、确认响应语义与真实行为须核实；未知语义不得凭 vendor 参数格式推断。真实写入测试的目标与授权在工单 03 执行前落实。
