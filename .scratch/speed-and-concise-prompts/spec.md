# 随机点歌提速与全站状态提示精进化

## 背景与目标

1. **随机点歌第一步（生成预览）提速**：
   - 房主在弹窗中选择成员并点击生成抽选时，若对公共歌单和各成员歌单每次都无条件发起 $1+N$ 次网易云 API 串行调用，整体耗时显著（单次可达数秒）。
   - 尤其在弹窗内点击「换一组」或微调歌曲数量时，此前刚刚拉回且证明完整的来源歌单被重复重新向网易云全量拉取，造成严重的重复等待。
   - 优化目标：引入短期（60 秒）来源快照新鲜度复用机制。在此窗口期内，已验证完整的来源直接复用本地有效快照，瞬间完成重新抽选；首次抽选时公共歌单若新鲜也跳过重复请求；未核验或已过期来源依然严格向上游拉取验证，失败依然严格拒绝，不违反“不凭旧快照放行”的安全红线。
2. **随机点歌第二步（执行替换）感知提速**：
   - 替换涉及“清空旧歌 -> 确认清空 -> 写入新歌 -> 确认添加”两阶段 4 次必要上游调用，以确保网易云云端顺序与点歌人标签一致。
   - 前端轮询间隔原为 2500ms，在 SSE 波动时感知滞后严重。
   - 优化目标：将前端替换操作的轮询间隔缩短至 1000ms，显著缩短操作终结到用户界面的感知时差。
3. **全站状态提示精炼**：
   - 移除全站提示中的拟人化、冗长、说教与口语化修饰（如“遇到了一点小问题”、“小伙伴较多通道正在有序排队”、“请稍作休息”、“重新载入歌单并点击播放全部”等）。
   - 统一转为简洁、专业、明确、直观的现代系统状态提示风格。

## 关键技术规格

1. **抽选来源新鲜度判定（`PublicRandomPreview`）**：
   - 定义 `FRESH_CACHE_TTL_MS = 60_000`（60 秒）。
   - 公共歌单：若本地快照存在、无错误且 `now() - syncedAt <= FRESH_CACHE_TTL_MS`，复用本地快照跳过 `publicPlaylists.refresh`；否则调用 `refresh`。
   - 所选成员个人歌单：若本地快照存在、无错误且 `now() - syncedAt <= FRESH_CACHE_TTL_MS`，复用本地快照跳过 `personalPlaylists.refresh`；否则调用 `personalPlaylists.refresh`。
   - 上游刷新如果抛错或返回快照错误，依然严格阻断并报错，绝不将失败静默视为成功或空歌单。
2. **感知与轮询加速（`PublicPlaylistPane`）**：
   - 轮询间隔由 2500ms 调整为 1000ms。
   - 换歌成功 Toast 文案精简为「换歌成功，点歌台已更新。」
3. **全站文案极简精进化**：
   - `room-http.ts` 错误提示精简。
   - `song-request-messages.ts` 点歌状态与错误提示精简。
   - `random-replacement-messages.ts` 换歌阶段与错误提示精简。
   - 各 Pane 中的 operation 状态和 disabledReason 文案精简。
