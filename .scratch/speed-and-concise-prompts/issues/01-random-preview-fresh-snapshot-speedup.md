# Ticket 01: 随机抽选与预览速度优化（短期新鲜快照复用）

Status: resolved

## 目标

优化随机点歌抽选预览的生成速度。在房主选择成员生成预览、点击「换一组」或调整歌曲数量时，避免对近期已核验完整的歌单进行重复无谓的网易云 API 串行调用，将重复抽选耗时从数秒降低至毫秒级。

## 验收清单

- [x] 在 `PublicRandomPreview` 中实现 60 秒新鲜度检查逻辑。
- [x] 公共歌单在 60 秒内已有完整有效快照时，跳过 `publicPlaylists.refresh` 网络请求，直接复用本地快照。
- [x] 各成员专用歌单在 60 秒内已有完整有效快照时，跳过 `personalPlaylists.refresh` 网络请求，直接复用本地快照。
- [x] 快照不存在、已过期（>60秒）或存在错误时，依然向上游发起真实拉取；任一来源拉取失败依然严格阻断并报错，保持安全底线不变。
- [x] 弹窗内抽选时的加载文案由「正在读取成员个人歌单并公平抽选歌曲…」精简为「正在抽选歌曲…」。
- [x] 单元测试验证新鲜快照复用行为与过期重拉取行为。

## Comments

### 实现说明
1. `PublicRandomPreview` 引入 `#verifiedSources` 映射记录各歌单在本会话经由上游网易云成功拉取核验的时间戳，窗口期为 60 秒（`FRESH_SNAPSHOT_WINDOW_MS`）。
2. 在此窗口期内点击「换一组」或切换候选歌曲总数时，所有来源直接复用已验证快照，耗时由数秒降为毫秒级。
3. 若歌单未核验、超过 60 秒或刷新异常，依然严格发起真实拉取；遇错依然阻断，不凭旧快照放行。
4. 弹窗加载中提示精简为「正在抽选歌曲…」。
5. `public-random-preview.test.ts` 新增短时间复用与过期刷新覆盖测试，15 项单元测试全绿。
