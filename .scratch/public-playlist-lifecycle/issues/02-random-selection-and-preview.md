# 02：实现公平随机选歌与只读预览

**What to build:** 房主按全房间总首数生成一组按成员尽量均分的随机歌曲，预览来源贡献及旧歌曲替换范围，预览阶段不写云端。

**Blocked by:** 既有个人歌单工单 24、25 及来源快照、解绑与资源清理的必要依赖。

**Status:** ready-for-agent

规格：[个人歌单与房主随机换歌](../spec.md)。阻塞项未解除前不启动实现。

## 验收清单

- [ ] 仅当前房主可生成和确认本房间随机预览，来源为房间当前已配置个人歌单的成员，包含只读收藏来源；不扩大普通成员的逐首点歌权限。
- [ ] 支持全房间总数 5/10/15/20，默认 10；按成员尽量均分，余数及平局随机，成员多于目标数时随机参与。
- [ ] 每位成员内随机选新歌优先，不足选旧歌；全房间按歌曲 ID 去重，成员候选不足重分配，整体不足显示实际数量。
- [ ] 公平分配在歌曲 ID 唯一约束下成立，交叉重复允许调整候选及归属；A={X}、B={X,Y}、目标 2 首时得到 A=X、B=Y，不能贪心耗尽 A 的唯一候选后宣称其来源不足。
- [ ] 没有新歌时不换；候选有新歌时最终预览包含新歌，不为追求变化降低已经可以达到的成员均分程度。
- [ ] 未配置或有效空歌单不参与；任何已配置来源读取失败整次不换，保留旧公共歌单，不凭旧快照略过来源。
- [ ] 通过现有调度读取完整来源与当前公共歌单，保存预览依据；不写来源、不排序公共歌单、不发任何歌曲增删请求。
- [ ] 预览展示具体歌曲、成员贡献、实际总数、旧歌曲总数及其中带成员点歌标签的歌曲数；退出预览不改变歌单。
- [ ] 服务端验证预览归属和固定歌曲集合、逐曲来源成员映射，后者决定确认后新增的点歌人标签；客户端不能任意替换歌曲、成员或来源，确认与恢复不更换归属；过期、权限变化、丢失或重启后重新预览。
- [ ] 抽样使用现有依赖或 Node 原生随机能力，不加通用随机框架；测试使用可控随机源验证边界，不用统计碰运气代替正确性断言。
- [ ] 公开接口及模块测试覆盖公平分配、少于成员数、交叉重复、候选耗尽、新旧取舍、读取失败、越权、取消无写和失效预览。
