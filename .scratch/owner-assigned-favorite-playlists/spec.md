# 房主分配收藏歌单与点歌台直连规范

Status: ready-for-agent

## Problem Statement

在现有点歌台流程中，系统要求房主和每个室友在网易云音乐平台主动创建专用的个人歌单，并提供全网搜索直接向个人歌单存歌。这种方式带来了明显的体验与架构痛点：
1. **外部平台资源负担过重**：每个房间的每位成员都需要在房主网易云账号下新建一份专用歌单，并在成员退出或房间删除时执行复杂的异步云端清理和补偿恢复；
2. **操作链路冗长迂回**：成员为了点一首歌，必须先在独立搜索页搜索全网歌曲、存入自己的专用歌单，再进入“我的歌单”二次点击点歌到点歌台；
3. **房主已有收藏资产无法利用**：房主在网易云已精心收藏了大量优质歌单，但因为收藏歌单对第三方只读、无法写入，导致此前不得不放弃直接绑定收藏歌单；
4. **全网搜索增加了系统复杂度与风险**：全网搜索涉及大量瞬态状态、分页与候选展示，且容易遭遇上游风控与接口变动。

## Solution

彻底废除“在网易云主动新建专用个人歌单”与“全网搜索存歌”模型，转为**由房主从其网易云账号的已有收藏歌单中为房间成员分配点歌来源**：
1. **房主集中分配**：房主在「房间成员」列表中为所有成员（包含自身与室友）统一分配、更换或解除绑定的收藏歌单；候选严格限定为房主授权账号下的收藏歌单（排除房主自建歌单）；允许多名成员绑定同一收藏歌单。
2. **只读点歌来源**：成员的「我的歌单」仅展示房主为其分配的收藏歌单快照，支持歌单内搜索与逐首点歌到点歌台，不可向其中添加或删除歌曲。
3. **彻底移除全网搜索**：一级导航收敛为「点歌台」（公共歌单）、「我的歌单」、「房间成员」、「房间设置」四个标签页，进入房间默认展示「点歌台」。不再提供全网搜索歌曲或直接全网点歌能力。
4. **极简安全生命周期**：成员退出房间或房主删除房间时，仅清除本地绑定关系与快照引用，绝不调用网易云接口删除外部歌单或取消收藏，彻底移除所有云端歌单清理任务。

## User Stories

1. 作为房主，我希望在「房间成员」列表中看到每位成员行的操作按钮，以便集中管理每位成员的点歌来源。
2. 作为房主，当某位成员尚未绑定歌单时，我希望在其行看到「分配歌单」按钮，点击能唤起选择弹窗。
3. 作为房主，在分配歌单弹窗中，我希望浏览当前已授权网易云账号下的全部收藏歌单（不含自建歌单），看到歌单名称、封面和歌曲数量，以便精准挑选。
4. 作为房主，当网易云账号暂无任何收藏歌单时，我希望弹窗显示清晰的空状态引导，提示我先去网易云客户端收藏歌单后再来分配。
5. 作为房主，我希望能够为已分配歌单的成员点击「更换歌单」，以便随时为其调整点歌来源。
6. 作为房主，我希望能够为已分配歌单的成员点击「解除分配」，并在二次确认后解除绑定，使该成员恢复为未分配状态。
7. 作为房主，我希望可以将同一份收藏歌单同时分配给多位成员，以便多位室友共享同一种风格或优质大歌单进行点歌。
8. 作为室友，我希望在打开「房间成员」列表时只看到成员基础信息，不展示任何分配或解除操作，以保证管理权归属于房主。
9. 作为室友，当房主尚未为我分配歌单时，我希望在「我的歌单」看到明确提示“房主尚未为你分配歌单，请联系房主分配”，避免无谓的猜测。
10. 作为房主，当我自身尚未分配歌单时，我希望在「我的歌单」看到“你尚未为自己分配歌单”并提供「前往分配」按钮，点击能直接跳转至分配操作。
11. 作为房间成员，当已被分配歌单后，我希望在「我的歌单」中清晰查看该歌单的权威歌曲快照（包含歌名、歌手、专辑与序号）。
12. 作为房间成员，我希望在「我的歌单」中可以通过关键词快速过滤当前歌单中的歌曲，以便在长歌单中迅速找到想听的歌。
13. 作为房间成员，我希望在「我的歌单」中可以点击单曲旁的「点歌」按钮，将歌曲加入公共歌单，并在公共歌单中正确记录我本人的点歌人标签。
14. 作为房间成员，我希望在「我的歌单」中可以点击「手动刷新」，以便在房主外部收藏歌单内容发生更新时同步最新歌曲。
15. 作为房间成员，我希望在「我的歌单」中不再看到“添加歌曲”、“删除歌曲”或“解除绑定”等按钮，以明确感知到该歌单由房主统一维护且为只读。
16. 作为房主，在点歌台发起「随机点歌」时，我希望抽选成员弹窗中仅允许勾选已被分配了歌单的成员，未分配成员置灰并提示原因，避免抽选中空歌单。
17. 作为房间成员，当我的歌单被房主更换或解除分配后，我希望此前我已经点入公共歌单的歌曲以及我的点歌人标签依然保持完整，不被篡改或清除。
18. 作为房间成员，当绑定的收藏歌单在网易云被原作者删除或被房主取消收藏时，我希望在「我的歌单」顶部看到清晰的失效警告标语，同时保留最后一次成功快照，以便获知无法继续点歌的原因。
19. 作为房主，当某成员的歌单发生外部失效时，我希望在房间成员列表中能观察到失效标记，以便及时为其更换有效歌单。
20. 作为所有成员，我希望进入房间时默认直接落地到「点歌台」，以便第一时间看到当前房间正在播放与已点的歌曲队列。
21. 作为所有成员，我希望一级导航只有「点歌台」、「我的歌单」、「房间成员」和「房间设置」四个选项，不再出现独立的“搜索歌曲”页面，让界面回归简洁。
22. 作为房主，在成员退出、被移除或我删除房间时，我希望系统只清理本地数据，绝对不在网易云取消收藏或删除该歌单，切实保障我的网易云账号资产不受破坏。

## Implementation Decisions

### 1. 领域模型与权限划分
- **个人歌单定义调整**：个人歌单不再是由成员创建的可写专用歌单，而是由房主分配给成员的只读网易云收藏歌单。
- **分配权限收拢**：所有分配、更换、解绑命令均要求调用者具备房主身份（`isOwner === true`），室友端无权提交此类命令。
- **只读约束**：个人歌单不具备云端写入能力，服务端移除所有针对个人歌单的添加歌曲与删除歌曲命令及 HTTP 接口。
- **允许共享目标**：解除以往数据库对 `(account_id, playlist_id)` 的全局唯一性约束，支持同一房间内不同成员、甚至不同房间绑定同一个网易云收藏歌单。

### 2. 候选歌单范围与读取
- 房主分配歌单时，服务端调用网易云用户歌单接口分页读取房主账号的所有歌单。
- 候选过滤规则严格限定为：`creatorId !== accountId && subscribed === true && status === 0`（即必须是他人创建且被房主收藏的公开有效歌单，排除房主自建歌单）。
- 候选响应包含歌单 ID、名称、封面 URL、歌曲总数、原作者昵称。
- 候选读取在房主点击分配弹窗时按需显式触发，不设自动轮询；如需最新列表，重新打开分配弹窗即可重新拉取。

### 3. 数据持久化与生命周期调整
- **数据表结构**：
  - 调整 `personal_playlist_binding`：外键关联 `room_id` 与 `member_id`，保留 `room_member_unique` 索引（保证每成员在每房间至多绑定一份歌单）；删除 `personal_playlist_binding_target_unique` 唯一索引；移除专用创建关联字段。
  - 删除废弃表：清理 `personal_playlist_creation`、`personal_song_addition`、`personal_song_mutation` 等表结构及相关持久操作。
- **无害化生命周期**：
  - 成员退出或被移除时：级联删除 `personal_playlist_binding` 本地行及该成员在本地的点歌人标签；**不生成任何云端歌单清理任务**。
  - 房间删除时：清理公共歌单的云端清理任务保留，但**完全移除所有个人歌单的云端清理任务**。
  - 解绑或更换歌单时：更新或删除当前房间成员的本地 binding 行，若该云端歌单在全站已无任何绑定引用，则按既有机制清理本地快照读模型，不调用任何上游写操作。

### 4. 接口契约与 HTTP 路由
- **新增/调整房主分配接口**：
  - `GET /api/rooms/:roomId/personal-playlist/candidates`：房主专属，获取房主网易云账号下的收藏歌单候选列表。
  - `POST /api/rooms/:roomId/members/:memberId/personal-playlist/assign`：房主专属，为指定成员分配或更换收藏歌单，入参 `{ playlistId: string }`，幂等执行并写回本地快照。
  - `POST /api/rooms/:roomId/members/:memberId/personal-playlist/unassign`：房主专属，解除指定成员的歌单分配，幂等执行。
- **调整只读查询接口**：
  - `GET /api/rooms/:roomId/personal-playlist`：查询当前登录成员本人的个人歌单状态与快照。
  - `POST /api/rooms/:roomId/personal-playlist/refresh`：成员本人刷新所分配歌单的快照。
  - `POST /api/rooms/:roomId/personal-playlist/request-song`：保留从本人分配的歌单向公共歌单逐首点歌的接口。
- **彻底退役删除的接口**：
  - 移除全网搜索接口：`GET /api/rooms/:roomId/song-search`。
  - 移除个人歌单自建与修改接口：`createPersonalPlaylist`、`addSong`、`removeSong` 等旧路由。

### 5. 前端界面与交互交互
- **一级导航与页面收敛**：
  - 移除 `SongSearchPane`（搜索歌曲独立页面）及相关状态与路由。
  - 一级导航顺序调整为：「点歌台」、「我的歌单」、「房间成员」、「房间设置」；默认激活「点歌台」。
  - 点歌台（公共歌单页）不设全网搜索入口，顶部仅保留「随机点歌」与「同步歌单」等核心控制项。
- **「房间成员」页面增强**：
  - 房主视角：在每位成员行右侧的操作区，未分配成员提供「分配歌单」按钮，已分配成员提供「更换歌单」与「解除分配」下拉或按钮组。
  - 弹出「分配歌单」模态框：展示收藏歌单卡片列表（封面、标题、曲目数、作者），点击选中并确认提交。
  - 室友视角：纯展示成员昵称与基础状态，无任何歌单分配按钮。
- **「我的歌单」页面简化**：
  - 未分配状态：
    - 室友端：友好空状态卡片，文字提示“房主尚未为你分配歌单，请联系房主分配”。
    - 房主端：友好空状态卡片，文字提示“你尚未为自己分配歌单”，并带有「前往分配」按钮，点击直接切换至「房间成员」页并引导分配。
  - 已分配状态：
    - 顶部展示歌单名称、歌曲总数与同步时间，带有「手动同步」按钮。
    - 列表展示歌曲快照，支持歌单内按歌名/歌手输入过滤。
    - 每首歌曲行仅提供「点歌」按钮，点击点入公共歌单；完全不提供“添加到个人歌单”或“从个人歌单删除”按钮。
    - 若快照刷新感知到外部已被作者删除或房主取消收藏，顶部出现黄色警示 Banner 说明原因。
- **「随机点歌」适配**：
  - 弹窗中遍历房间成员，仅对已绑定有效歌单的成员开放复选框；未分配歌单的成员复选框置灰禁用，旁边标注“未分配歌单”。

## Testing Decisions

- **良好测试的标准**：
  - 严格测试外部行为与业务结果，不测试组件内部私有状态或具体 SQL 拼接。
  - 断言关键业务不变量：房主能分配、室友不可分配、多成员可同绑、退出不发删除请求、只读不可写入、已分配方有点歌资格、点歌人标签准确归属。
- **重点测试模块**：
  - 业务操作与调度层：候选过滤（排除自建只留收藏）、房主分配、更换与解绑幂等性、退出与删房无清理任务、多人同绑同一歌单快照共享与隔离。
  - HTTP 路由与鉴权层：鉴权拦截（室友调用分配返回 403 Forbidden、未分配点歌返回拒绝、旧全网搜索接口返回 404）。
  - 端到端（Playwright E2E）：
    - 房主在成员页分配收藏歌单完整流程；
    - 室友查看我的歌单未分配提示；
    - 房主为室友分配后，室友刷新我的歌单并成功点歌至点歌台；
    - 房主为自己分配歌单并在我的歌单点歌；
    - 房主随机点歌中未分配成员禁用及已分配成员正常均分抽歌；
    - 成员退出后其绑定的收藏歌单在外部网易云平台不被删除；
    - 默认导航为点歌台、各视口响应式布局无溢出。
- **工程既有先例**：
  - 参考已有的 `apps/songroom/tests/e2e/owner-personal-playlist.spec.ts`、`public-playlist.spec.ts` 与 `personal-playlists.test.ts`。

## Out of Scope

- 允许分配房主自己创建的歌单（本期严格限定为房主收藏的歌单）。
- 允许室友绑定室友自己的网易云账号或收藏。
- 在点歌台内对收藏歌单进行任意增删或排序。
- 在点歌台提供任何形式的全网关键词搜索歌曲或直接点歌。
- 自动检测并拉取网易云平台所有变更的后台持续定时轮询。
- QQ 音乐、网易云之外的其他音乐平台接入。

## Further Notes

- 本次变更严格执行全局核心原则：
  1. **不保留向后兼容**：不维护专用歌单创建和全网搜索的兼容分支，旧接口直接清理，数据库迁移脚本一次性调整。
  2. **选择满足当前需求的最简实现**：房主分配直接就地在房间成员列表触发弹窗，不额外搭建繁杂的后台歌单管理子系统。
  3. **立足长远做架构设计**：彻底摆脱在第三方平台自动化建单/删单带来的风控和清理残留隐患，使点歌台回归轻量、纯粹的协作工具定位。
